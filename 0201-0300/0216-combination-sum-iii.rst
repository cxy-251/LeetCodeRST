0216. Combination Sum III
========================

题目信息
--------

:题号: 0216. 组合总和 III
:难度: Medium
:主题: 回溯、组合枚举、剪枝、状态恢复
:原题: `LeetCode 0216 <https://leetcode.com/problems/combination-sum-iii/>`_
:重点: 从 1 到 9 选恰好 K 个不同数字、组合不计顺序、剩余和上下界

题目重述
--------

从数字 ``1`` 到 ``9`` 中恰好选择 ``k`` 个不同的数字，使它们的总和等于 ``n``，返回所有满足条件的组合。
同一组数字的排列视为同一个组合，结果中的每条组合按递增顺序排列；每个数字最多使用一次。``k`` 位于 ``[1,9]``，
``n`` 位于 ``[1,60]``，返回顺序不限，输入不需要修改。

自建示例
--------

``k=3, n=9`` 的组合是 ``[1,2,6]``、``[1,3,5]``、``[2,3,4]``。``[2,1,6]`` 与第一组使用相同数字，
不能作为另一条结果；递增生成顺序可以从源头消除这种排列重复。

``k=2, n=17`` 只有 ``[8,9]``；``k=3, n=7`` 的结果是 ``[[1,2,4]]``。
为了展示失败边界，``k=3, n=5`` 没有结果，因为三个不同正整数的最小和 ``1+2+3`` 已经是 6。

从子集与排列中删除重复
----------------------

把 1..9 的每个数字标记为选或不选，可以枚举 ``2^9`` 个子集，再筛选选中数量和总和；它不会漏解，但没有利用组合不计顺序的
结构。若每次从全部数字中任意选择，还会为同一组数字生成 ``k!`` 种排列，再依赖排序或集合去重。

回溯按递增顺序选择候选。状态中的 ``next`` 表示下一层只能从哪个数字开始；选中 ``x`` 后递归到 ``x+1``，因此路径严格递增，
同一集合只有一条生成路径。这个状态同时代替了全局 ``used`` 数组：小于 ``next`` 的数字已经被决定，不能重新出现。

状态定义与边界剪枝
------------------

``dfs(next, slots, remaining)`` 表示当前 ``path`` 已经是合法递增前缀，还需要从 ``[next,9]`` 选 ``slots`` 个数字，
并使它们的和为 ``remaining``。进入每次调用时保持：

* ``path`` 长度为 ``k-slots``，其中数字严格递增且没有重复；
* ``path`` 的和为 ``n-remaining``；
* 所有尚未尝试的数字都不小于 ``next``。

若可用数字个数小于 ``slots``，或 ``remaining < 0``，分支立即失败。更强的剪枝是比较可达到的和：
从 ``next`` 开始取最小的 ``slots`` 个数得到最小和；从 9 向下取最大的 ``slots`` 个数得到最大和。
若 ``remaining`` 不在这个闭区间内，无论怎样选择都不可能补成答案。

当 ``slots == 0`` 时只接受 ``remaining == 0`` 的路径；这一步把“恰好选 K 个”与“总和相等”同时落地，不能在只满足其中一项时收集。

C++ 实现
--------

.. code-block:: cpp

   class Solution {
   private:
       static int smallestSum(int start, int count) {
           int sum = 0;
           for (int value = start; value < start + count; ++value) sum += value;
           return sum;
       }

       static int largestSum(int count) {
           int sum = 0;
           for (int value = 9; value > 9 - count; --value) sum += value;
           return sum;
       }

       static void dfs(int next, int slots, int remaining,
                       std::vector<int>& path,
                       std::vector<std::vector<int>>& answer) {
           if (slots == 0) {
               if (remaining == 0) answer.push_back(path);
               return;
           }
           if (remaining < 0 || 9 - next + 1 < slots) return;

           if (remaining < smallestSum(next, slots) ||
               remaining > largestSum(slots)) {
               return;
           }

           for (int value = next; value <= 9; ++value) {
               if (value > remaining) break;
               path.push_back(value);
               dfs(value + 1, slots - 1, remaining - value, path, answer);
               path.pop_back();
           }
       }

   public:
       std::vector<std::vector<int>> combinationSum3(int k, int n) {
           std::vector<std::vector<int>> answer;
           std::vector<int> path;
           dfs(1, k, n, path, answer);
           return answer;
       }
   };

题解
----

回溯如何覆盖每个组合
~~~~~~~~~~~~~~~~~~~~

在任意状态，下一位组合中的数字必然是 ``[next,9]`` 中的某个值。循环依次尝试每个候选，递归负责所有更大的后缀，
因此任何递增组合都会沿着它的数字顺序被走到；反过来，``next`` 的限制保证生成的每条路径都没有重复数字。

例如 ``k=3,n=9``：选择 1 后，下一层从 2 开始，能够生成 ``[1,2,6]``、``[1,3,5]`` 等；返回并弹出 1 后，
选择 2 的分支从 3 开始生成 ``[2,3,4]``，不会再次生成以 1 开头的组合。``path.pop_back()`` 是回溯的边界，
它让同一容器在兄弟分支之间复用，同时保持每次递归入口的不变量。

剪枝删除了哪部分搜索
~~~~~~~~~~~~~~~~~~~~~~

只检查 ``remaining < 0`` 只能排除和已经过大的分支。若还需 3 个数字但剩余可选数字的最小和已经大于目标，继续向后只会选更大
的数，必然失败；若连 9、8、7 的最大和都小于目标，换成更小数字也不可能成功。上下界剪枝一次删除整棵不可能子树，
而不是等到槽位耗尽才逐个确认。

状态走读
~~~~~~~~

对 ``k=3,n=9``，一条成功路径和一条失败剪枝如下：

.. list-table::
   :header-rows: 1

   * - 调用状态
     - 选择
     - 下一状态或结论
   * - ``dfs(1,3,9)``
     - 选 1
     - ``dfs(2,2,8)``，路径 ``[1]``
   * - ``dfs(2,2,8)``
     - 选 2
     - ``dfs(3,1,6)``，路径 ``[1,2]``
   * - ``dfs(3,1,6)``
     - 选 6
     - ``dfs(7,0,0)``，收集 ``[1,2,6]``
   * - 回溯至 ``dfs(2,2,8)``
     - 选 3
     - 后续需要 5，得到 ``[1,3,5]``
   * - ``dfs(1,3,5)``
     - 尚需 3 个数
     - 最小和 6，大于 5，立即返回

表中的 ``dfs(1,3,5)`` 说明剪枝使用的是“未来最小可能和”，不是对某个当前候选做猜测，因此不会丢掉合法组合。

代码分析
~~~~~~~~

``smallestSum``、``largestSum`` 只在固定的 1..9 范围内循环，成本最多 9 次，换来的却是对整个后续搜索树的可行性判断。
``value > remaining`` 时可以停止当前循环，因为所有候选数字为正且后续数字更大；这条剪枝不会影响负数场景，因为题目没有负数候选。

公共入口只初始化空路径并从 1 开始。递归返回后立刻弹出刚加入的值，保证下一次循环看到的是进入当前调用前的路径；答案复制路径，
因此随后回溯不会改变已经收集的组合。主解选择有序回溯而非全子集枚举，是因为它同时编码了“不重复”和“组合不计顺序”两个约束。

复杂度与边界
~~~~~~~~~~~~

候选集合固定为 9 个数字，未剪枝时最多访问 ``O(2^9)`` 个子集状态；每个状态最多做常数级上下界计算，实际访问数会被目标和与槽位
显著削减。递归深度为 ``O(k)``，路径工作空间为 ``O(k)``，返回结果另占输出空间。``k=9``、最小和 6、最大和 45、
目标超出可达区间等情况由同一上下界判断覆盖；当 ``slots==0`` 时只有剩余和恰为 0 才收集。

0201. Bitwise AND of Numbers Range
==================================

题目信息
--------

:题号: 0201. 数字范围按位与
:难度: Medium
:主题: 位运算、连续整数、公共前缀、最低有效位
:原题: `LeetCode 0201 <https://leetcode.com/problems/bitwise-and-of-numbers-range/>`_
:重点: 连续区间一旦跨过某个二进制边界，该位置及更低位都会出现 0，答案只保留端点公共高位前缀

题目重述
--------

给定两个非负整数 ``left`` 和 ``right``，满足 ``left <= right``。返回闭区间
``[left, right]`` 中所有整数的按位与：

``left & (left + 1) & ... & right``。

某一位只有在区间内每个整数的对应位都为 1 时，最终结果的这一位才会保留为 1。输入满足
``0 <= left <= right <= 2^31 - 1``；当两个端点相等时，区间只有一个整数，答案就是它本身。

自建示例
--------

``left = 10, right = 11`` 时，``1010 & 1011 = 1010``，因此返回 10。

``left = 12, right = 15`` 时，区间二进制为 ``1100、1101、1110、1111``。只有高两位
``11`` 始终不变，两个低位都曾出现 0，因此返回 ``1100``，即 12。

``left = 5, right = 7`` 时，端点是 ``101`` 和 ``111``。虽然两端最低位都是 1，中间的
``6 = 110`` 会把最低位清零，所以不能只计算 ``left & right``；最终结果是 ``100``，即 4。

C++ 实现
--------

.. code-block:: cpp

   #include <cstdint>

   class Solution {
   private:
       int commonPrefix(int left, int right) {
           std::uint32_t low = static_cast<std::uint32_t>(left);
           std::uint32_t high = static_cast<std::uint32_t>(right);
           unsigned int shifts = 0;

           while (low != high) {
               low >>= 1;
               high >>= 1;
               ++shifts;
           }
           return static_cast<int>(low << shifts);
       }

       int clearChangingSuffix(int left, int right) {
           std::uint32_t low = static_cast<std::uint32_t>(left);
           std::uint32_t high = static_cast<std::uint32_t>(right);

           while (low < high) {
               high &= high - 1;
           }
           return static_cast<int>(high);
       }

   public:
       int rangeBitwiseAnd(int left, int right) {
           return commonPrefix(left, right);
       }
   };

题解
----

逐个枚举没有利用连续区间
~~~~~~~~~~~~~~~~~~~~~~~~

最直接的方法从 ``left`` 枚举到 ``right``，把每个整数依次与到答案中。它当然不会漏掉任何
参与者，也可以在结果已经变成 0 时提前结束，但区间可能从 1 一直延伸到 ``2^31 - 1``，
逐个处理的最坏代价仍与区间宽度成正比。

只计算 ``left & right`` 也不够。按位与要求该位在区间内所有整数中都为 1；两个端点为 1
不能证明中间值也为 1。``[5,7]`` 的最低位就是反例：5 和 7 都为 1，6 却为 0。

真正需要判断的是：哪些二进制位在整个连续区间内从未变化。

连续整数只保留公共高位前缀
~~~~~~~~~~~~~~~~~~~~~~~~~~

从一个整数连续递增时，低位会频繁翻转，并在进位时跨过形如 ``...0111`` 到 ``...1000`` 的
边界。若 ``left`` 和 ``right`` 在某一位首次不同，说明区间已经跨过这个位置对应的二进制块
边界。从这个差异位开始到最低位，都能在区间中找到至少一个对应位为 0 的整数，因此这些位
不可能出现在最终按位与结果中。

首次差异位左侧的高位则完全相同。两个端点仍处于同一个公共高位前缀之下，而整个闭区间都
夹在它们之间，所以中间整数也不会离开这个前缀。

因此答案正好是 ``left`` 与 ``right`` 的最长公共二进制前缀，后面补 0。

同步右移暴露公共前缀
~~~~~~~~~~~~~~~~~~~~

``commonPrefix`` 每轮同时把 ``low`` 和 ``high`` 右移一位，相当于从两个端点删除同一个最低
位。只要二者仍不同，就说明剩余部分还包含差异位，删除掉的低位属于最终必须清零的后缀。

循环结束时二者第一次相等，这个共同值就是原端点的公共高位前缀。``shifts`` 记录删除了多少
位，最后执行 ``low << shifts``，只把公共前缀移回原位置；腾出的低位天然全部为 0。

例如 ``[26,30]``：

.. code-block:: text

   轮次   low     high    shifts
   0      11010   11110   0
   1      1101    1111    1
   2      110     111     2
   3      11      11      3

公共前缀是 ``11``，补回三个 0 得到 ``11000``，即 24。

若 ``left == right``，循环一次也不进入，``shifts`` 为 0，直接返回原值。若区间跨过很大的
二进制边界，例如 ``[1, 2^31-1]``，两个端点最终都会右移到 0，答案自然为 0。

清除 right 的最低有效 1
~~~~~~~~~~~~~~~~~~~~~~~

还可以从相同的“变化后缀必须归零”出发，只修改右端点。表达式
``high &= high - 1`` 会清除 ``high`` 当前最低的一个 1。

只要 ``low < high``，区间仍跨越某个会变化的低位；这些低位本来就不可能保留在答案中，
因此可以直接从右端点删除一个最低有效 1，而不需要枚举该位经历过的所有中间整数。重复处理
直到 ``high <= low``，剩下的 ``high`` 就是区间按位与结果。

例如 ``[26,30]``：``11110 -> 11100 -> 11000``。第二次清除后得到 24，已经不大于 26，
循环结束并返回 24。这个方案代码更短，但“为什么可以直接删除最低 1”比同步右移的公共前缀
解释更跳跃，因此保留为替代实现，公开入口采用 ``commonPrefix``。

不变量与复杂度
~~~~~~~~~~~~~~

同步右移执行 ``s`` 轮后，``low`` 和 ``high`` 分别等于原始端点删除最低 ``s`` 位后的值，
而这些已删除位都处在会变化的后缀中。循环停止时剩余前缀相同，所以保留下来的每个高位在
整个区间中都固定；被删除后缀中的每一位至少在某个区间成员中为 0。恢复公共前缀的位置后，
得到的正是全部整数的按位与。

两个实现都最多处理整数位宽数量级的位。设位宽为 ``W``，时间复杂度为 ``O(W)``，本题
``W <= 31``，因此也可视为常数时间；额外空间均为 ``O(1)``。主解使用 ``uint32_t`` 保存位
模式，避免依赖有符号右移语义，最终结果仍位于题目保证的非负 ``int`` 范围内。

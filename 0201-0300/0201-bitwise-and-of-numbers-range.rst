0201. Bitwise AND of Numbers Range
==================================

题目信息
--------

:题号: 0201. 数字范围按位与
:难度: Medium
:主题: 位运算、连续整数、公共前缀、Brian Kernighan
:原题: `LeetCode 0201 <https://leetcode.com/problems/bitwise-and-of-numbers-range/>`_
:重点: 从逐个相与重新观察“哪些位可能始终为 1”，用最高差异位一次判定整个变化后缀必为 0

题目重述
--------

给定两个非负整数 ``left`` 和 ``right``，满足 ``left <= right``。闭区间 ``[left, right]``
中的每个整数都必须参与按位与，返回：

``left & (left + 1) & ... & right``。

输入满足 ``0 <= left <= right <= 2^31 - 1``。区间包含两个端点；当 ``left == right`` 时，
只有一个参与者，答案就是该整数本身。

自建示例
--------

``left = 26, right = 30`` 时，区间为 ``11010、11011、11100、11101、11110``，返回
``11000``，即 24。

``left = 5, right = 7`` 时，``left & right = 101``，但中间的 ``6 = 110`` 会把最低位清零，
所以真正结果是 ``100``，即 4。这个例子说明只检查两个端点不够。

``left = 8, right = 8`` 时没有中间整数，直接返回 8。

C++ 实现
--------

.. code-block:: cpp

   #include <cstdint>

   class Solution {
   private:
       int enumerateInterval(int left, int right) {
           std::uint32_t result = static_cast<std::uint32_t>(left);
           std::uint32_t high = static_cast<std::uint32_t>(right);

           for (std::uint32_t value = result + 1U;
                value <= high && result != 0U;
                ++value) {
               result &= value;
           }
           return static_cast<int>(result);
       }

       int commonPrefix(int left, int right) {
           std::uint32_t low = static_cast<std::uint32_t>(left);
           std::uint32_t high = static_cast<std::uint32_t>(right);
           unsigned int removed = 0;

           while (low != high) {
               low >>= 1U;
               high >>= 1U;
               ++removed;
           }
           return static_cast<int>(low << removed);
       }

       int clearChangingSuffix(int left, int right) {
           std::uint32_t low = static_cast<std::uint32_t>(left);
           std::uint32_t high = static_cast<std::uint32_t>(right);

           while (low < high) {
               high &= high - 1U;
           }
           return static_cast<int>(high);
       }

   public:
       int rangeBitwiseAnd(int left, int right) {
           return commonPrefix(left, right);
       }
   };

题解
----

逐个相与是正确基线
~~~~~~~~~~~~~~~~~~

最直接的做法就是按题意从 ``left`` 走到 ``right``，把每个整数依次并入结果。
``enumerateInterval`` 正是这条基线：它没有任何推测，因此不会漏掉影响答案的中间值；当结果
已经变成 0 时还可以提前结束，因为之后再与任何整数都不可能重新产生 1。

问题在于它仍然按“区间里有多少个整数”工作。若区间很宽，同一个二进制位置会随着连续递增
反复经历 0、1，却被算法逐个确认。最坏时间为 ``O(right-left+1)``，而题目端点可以相隔
十亿数量级。

真正需要保留的信息不是每个整数本身，而是 **哪些二进制位从 left 到 right 的整个过程中
始终没有出现过 0**。

端点相与仍然遗漏中间状态
~~~~~~~~~~~~~~~~~~~~~~~~

一种自然缩减是只算 ``left & right``。它检查了两个最远端点，却不能代表中间所有整数。
``[5,7]`` 中：

.. code-block:: text

   5 = 101
   6 = 110
   7 = 111

最低位在两个端点都是 1，但在 6 中为 0，所以最终必须清零。按位与要求的是“所有参与者都
为 1”，端点一致只是必要条件，不是充分条件。

这个失败反而给出了新的观察方向：连续整数的二进制并不是任意变化，而是按固定进位规则
变化。只要找到区间跨过的最高二进制边界，就可以一次判断一整段低位，而不再检查每个值。

最高差异位判死整个后缀
~~~~~~~~~~~~~~~~~~~~~~

从高位向低位比较 ``left`` 与 ``right``。设它们第一次不同的位置为 ``p``，更高部分的公共
前缀为 ``P``。因为 ``left < right``，这一位必然是：

.. code-block:: text

   left  = P 0 ...
   right = P 1 ...

这意味着闭区间一定跨过从 ``P 0 111...111`` 到 ``P 1 000...000`` 的进位边界。
边界右侧第一个整数的第 ``p`` 位以下全部为 0，因此所有低于 ``p`` 的位置都已经找到一个
“零见证”；而边界左侧的整数在第 ``p`` 位为 0，所以第 ``p`` 位同样不能保留。

因此，从最高差异位 ``p`` 一直到最低位，最终按位与必然全部为 0。

反过来看，``p`` 左侧就是 ``left`` 与 ``right`` 的公共前缀 ``P``。两个端点都没有离开这个
高位前缀对应的整数块，夹在中间的所有整数也不会离开，所以这些高位在整个区间中保持不变。

于是答案被完全确定：

.. code-block:: text

   最长公共高位前缀 + 同长度的全 0 后缀

这里才真正删除了枚举工作：一个差异位不仅决定自己为 0，还同时判定它右边的整个后缀都
无需继续调查。

同步右移暴露仍可能存活的部分
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``commonPrefix`` 直接实现这个结论。只要 ``low != high``，说明最高差异位还没有被删掉；
两个端点同时右移一位，相当于从答案候选中丢弃一个已经属于变化后缀的位置，并用
``removed`` 记录丢弃了多少位。

循环第一次达到 ``low == high`` 时，所有差异位及其右侧已经删除，剩下的共同值就是最长
公共高位前缀。最后把它左移 ``removed`` 位，恢复原来的位位置；新补出的低位天然全是 0。

这个过程不是在“计算区间中的按位与”，而是在不断缩小仍有资格保留 1 的位范围。

具体状态走读
~~~~~~~~~~~~

对 ``left = 26``、``right = 30``：

.. code-block:: text

   初始      low=11010   high=11110   removed=0
   右移 1    low=1101    high=1111    removed=1
   右移 2    low=110     high=111     removed=2
   右移 3    low=11      high=11      removed=3

第三次右移后端点第一次相等，公共前缀是 ``11``。把它左移三位得到 ``11000``，即 24。
算法从头到尾没有访问 27、28、29；这三个中间值的作用已经被“区间跨过最高差异位”这一
结构事实整体吸收。

若 ``left == right``，公共前缀就是完整数字，循环不执行，``removed = 0``。若两个端点连
最高有效位都不同，右移会一直把它们压到共同前缀 0，结果自然也是 0。

另一条路径：只清除确定无法保留的 1
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

还可以把同一个结论落实成 ``clearChangingSuffix``。对任意非零 ``x``，
``x & (x-1)`` 会恰好清除 ``x`` 的最低有效 1。

这里关键不是这个位技巧本身，而是为什么当前最低 1 可以删。只要 ``low < high``，整数
``high-1`` 仍然位于原闭区间中；而 ``high-1`` 会把 ``high`` 的最低有效 1 变成 0。因此这个
位置已经存在一个区间成员为 0，它不可能出现在最终按位与中，可以直接执行：

.. code-block:: text

   high &= high - 1

之后若新的 ``high`` 仍大于 ``low``，同样论证继续成立。每轮都不是“尝试修改答案”，而是
用一个真实存在于区间中的零见证，删除一个已经证明不可能存活的置位。

例如 ``[5,7]``：

.. code-block:: text

   high = 111 -> 110 -> 100

第一次由区间成员 6 证明最低位必须清零；第二次继续清除变化后缀中的下一置位。最后
``100 < 101`` 并不异常，按位与结果本来就可以小于 ``left``。得到的 4 与公共前缀方法一致。

这种写法在置位较少时可能执行更少轮，但它把“公共前缀”隐藏在连续清位过程中。主解选择
``commonPrefix``，因为代码结构与最高差异位的推导完全一致；清位方案作为同一结构结论的
另一种实现保留。

方案选择与复杂度
~~~~~~~~~~~~~~~~

``enumerateInterval`` 的时间取决于区间宽度，最坏为 ``O(right-left+1)``，只使用常数额外
空间。它的价值是给出不会漏解的直接基线，并暴露真正需要消除的是逐个访问中间整数。

``commonPrefix`` 每轮删除一个低位，若整数位宽记为 ``W``，时间为 ``O(W)``、额外空间
``O(1)``；本题有效位宽不超过 31，因此循环次数有固定上界。``clearChangingSuffix`` 每轮
删除右端状态的一个最低置位，最多同样执行 ``O(W)`` 次，额外空间 ``O(1)``。

三个实现都不会修改调用者传入的整数；公开入口采用公共前缀方案，因为它最直接体现从
“枚举所有整数”到“只保留整个区间都稳定的位”这一核心认识变化。

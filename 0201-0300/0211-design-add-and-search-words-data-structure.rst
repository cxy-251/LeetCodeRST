0211. Design Add and Search Words Data Structure
================================================

题目信息
--------

:题号: 0211. 添加与搜索单词——数据结构设计
:难度: Medium
:主题: Trie、通配符搜索、深度优先搜索、对象状态
:原题: `LeetCode 0211 <https://leetcode.com/problems/design-add-and-search-words-data-structure/>`_
:重点: 点号恰好匹配一个字符、完整单词与前缀的区别、跨调用保存字典

题目重述
--------

设计一个 ``WordDictionary`` 类，支持两个会被交替调用的方法。``addWord(word)`` 把一个只含小写英文字母的
单词加入字典；``search(pattern)`` 判断字典中是否存在某个此前加入的完整单词，能和查询模式逐位匹配。模式中的
普通字母只能匹配相同字母，点号 ``.`` 可以匹配任意一个小写字母，但必须恰好消耗一个字符，不能代表空串或多个字符。

单词和模式长度都在 ``[1, 25]``，所有方法调用总数不超过 ``10^4``；模式最多含两个点号。对象要在连续调用之间保留
已经加入的单词。搜索成功的条件是到达一个完整单词的末尾，某个更长单词的前缀即使逐位匹配，也不能返回 ``true``。

自建示例
--------

普通字母确定路径，点号才产生选择：

.. code-block:: text

   addWord("bad"), addWord("dad"), addWord("mad")
   search(".ad") -> true
   search("b..") -> true
   search(".ae") -> false

查询 ``.ad`` 可以在根节点的 ``b``、``d``、``m`` 三条边中任选一条；``b..`` 仍必须沿 ``b`` 子树向下两层，
两个点号各匹配一个字符；``.ae`` 的最后一个字母在三个候选词中都不相同，因此所有分支失败。

前缀不能冒充完整单词：

.. code-block:: text

   addWord("rain")
   search("rai") -> false
   search("ra.n") -> true

``rai`` 只走到 ``rain`` 的中间节点；``ra.n`` 的点号匹配 ``i`` 后到达 ``rain`` 的终止节点，长度和终止状态都满足。

C++ 实现
--------

.. code-block:: cpp

   class WordDictionary {
   private:
       struct Node {
           std::array<std::unique_ptr<Node>, 26> children{};
           bool terminal = false;
       };

       Node root_;

       bool matches(const Node* node, const std::string& pattern,
                    std::size_t position) const {
           if (position == pattern.size()) return node->terminal;

           const char character = pattern[position];
           if (character != '.') {
               const int index = character - 'a';
               const Node* child = node->children[index].get();
               return child != nullptr && matches(child, pattern, position + 1);
           }

           for (const std::unique_ptr<Node>& child : node->children) {
               if (child != nullptr && matches(child.get(), pattern, position + 1)) {
                   return true;
               }
           }
           return false;
       }

   public:
       WordDictionary() = default;

       void addWord(std::string word) {
           Node* node = &root_;
           for (char character : word) {
               const int index = character - 'a';
               if (node->children[index] == nullptr) {
                   node->children[index] = std::make_unique<Node>();
               }
               node = node->children[index].get();
           }
           node->terminal = true;
       }

       bool search(std::string word) const {
           return matches(&root_, word, 0);
       }
   };

题解
----

直接保存字符串的正确性
~~~~~~~~~~~~~~~~~~~~~~

最直观的做法是把每个加入的单词原样放进列表。搜索模式时逐个取出单词：长度不同时立即跳过；长度相同时从左到右比较，
普通字母要求相等，点号跳过值比较。只要有一个单词整段匹配就返回 ``true``，列表扫描结束仍未命中就返回 ``false``。

这个基线没有遗漏：字典中的每个候选单词都被检查，而匹配规则正好对应题目两种字符。它还自然地用长度区分了
``"rai"`` 和 ``"rain"``。但它把每个单词的公共前缀重复比较。若字典中有 ``bad``、``dad``、``mad``，查询 ``.ad``
仍要分别读取三个后缀；字典中有大量同前缀单词时，重复工作随单词数量增长。

几种搜索空间的取舍可以先摆在一起：

.. list-table::
   :header-rows: 1

   * - 表示方式
     - ``addWord``
     - ``search``
     - 被删除或保留的工作
   * - 字符串列表
     - 保存一个新字符串
     - 最坏 ``O(WL)``
     - 每个单词都重新检查公共前缀，最直观但重复最多
   * - Trie 加分支 DFS
     - 沿路径创建或复用节点
     - 按实际访问状态 ``Q``
     - 共享前缀，只在点号处展开真实分支，主解
   * - 预生成点号模式索引
     - 一个单词扩展最多 ``26^2`` 个模式
     - 查询可能很快
     - 把指数级存储和未来插入成本提前支付，不能作为通用设计

``W`` 是字典中的单词数，``L`` 是单词或模式长度上界。Trie 的优势不是把所有搜索都变成常数，而是把“相同前缀已经判断过”
这一事实保存下来；点号仍可能带来真实分支，不能在复杂度中把它隐去。

把候选单词压缩成 Trie
~~~~~~~~~~~~~~~~~~~~~~

Trie 将一组字符串的公共前缀合并成一条路径。节点表示“已经匹配的前缀”，从节点出发的第 0 到 25 号子链接分别表示
下一个小写字母；``terminal`` 表示这个节点对应的完整字符串曾被加入。于是：

* 加入单词时，只在路径第一次出现的位置创建节点，后续单词复用已有前缀；
* 查询普通字母时，下一条边是唯一的，缺边就证明没有候选能继续；
* 查询点号时，只需在当前节点的非空子链接中分支，空槽位根本不是字典中的候选；
* 查询模式耗尽时必须检查 ``terminal``，因为节点可能只是更长单词的中间前缀。

Trie 没有预先为所有点号模式建立索引。模式最多两个点号，预生成所有替换也许看似可行，但它把每个单词扩展成最多
``26^2`` 个模式，并且无法覆盖未来才加入的单词；把分支延迟到真正搜索时，只为当前查询访问存在的前缀。

这里的 ``terminal`` 不能由“节点有无孩子”推断。加入 ``"app"`` 后再加入 ``"apple"``，``app`` 节点同时是完整单词终点
和更长单词的前缀；反过来只加入 ``"apple"`` 时，``app`` 节点有 ``p`` 子链接却不是可返回的完整单词。终止标记把这两个
概念分开，也是跨调用保存字典语义的核心。

搜索状态与转移
~~~~~~~~~~~~~~

递归状态 ``matches(node, position)`` 的含义是：从根到 ``node`` 的路径已经消费了模式的
``pattern[0..position)``，现在判断剩余后缀能否到达一个完整单词。该定义同时绑定了树位置和字符串位置，避免把不同
长度或不同前缀的状态混在一起。

状态转移按模式当前位置分三类：

* ``position == pattern.size()``：不再消耗字符，只返回 ``node->terminal``；
* 当前字符是字母 ``c``：取唯一的 ``children[c-'a']``，不存在就失败，存在就把位置加一递归；
* 当前字符是 ``.``：枚举 26 个槽位中的非空子节点，每个分支把点号恰好匹配成一个字符，任一成功就短路返回。

每次递归都令 ``position`` 增加 1，因此不会出现点号匹配空串或递归不前进的情况。搜索只读取 Trie，不会因为一次失败
而删除路径或终止标记，下一次 ``search`` 仍能看到同一份字典。

状态走读
~~~~~~~~

以加入 ``bad``、``dad``、``mad`` 后查询 ``.ad`` 为例，递归状态的变化如下：

.. list-table::
   :header-rows: 1

   * - 状态
     - 当前模式字符
     - 分支或结果
   * - ``(root, 0)``
     - ``.``
     - 枚举 ``b``、``d``、``m`` 三个非空子节点
   * - ``(b, 1)``
     - ``a``
     - 只进入 ``b->a``，其他 25 条边不可能匹配
   * - ``(ba, 2)``
     - ``d``
     - 进入 ``bad`` 的终点
   * - ``(bad, 3)``
     - 已耗尽
     - ``terminal=true``，该分支返回 ``true``

由于 ``b`` 分支已经成功，``d``、``m`` 分支不会继续展开；这就是点号的“存在一个选择”而不是“所有选择都要成功”。
若查询 ``rai``，状态会到达 ``rai`` 节点但 ``position == 3`` 时 ``terminal=false``，即使该节点有 ``n`` 子链接也返回假。

再看一次没有成功分支的情况：查询 ``".ae"`` 时，根节点的每个非空子链接都可以消费第一个点号；进入 ``ba``、``da``、``ma``
后，当前位置 ``e`` 的对应子链接都为空，于是三个分支分别在同一层失败。算法不需要把失败路径拼成完整字符串，也不会把点号
误当成“任意长度的通配符”。

对象状态的跨调用走读
~~~~~~~~~~~~~~~~~~~~~~

``addWord`` 和 ``search`` 不是一次性函数；Trie 必须在每次公开方法返回后保持不变量。以连续调用为例：

.. list-table::
   :header-rows: 1

   * - 调用
     - Trie 变化
     - 查询结果
   * - ``addWord("apple")``
     - 建立 ``a-p-p-l-e``，只在 ``e`` 标记终止
     - —
   * - ``search("app")``
     - 只读 ``a-p-p`` 路径，``terminal=false``
     - ``false``
   * - ``addWord("app")``
     - 复用已有节点，把第二个 ``p`` 标为终止
     - —
   * - ``search("app")``
     - 同一路径，``terminal=true``
     - ``true``
   * - ``search("a..le")``
     - 点号分别选择已有的 ``p``、``p``
     - ``true``

搜索过程没有修改终止标记或子链接，因此第二次查询看到的结构与第一次查询结束时完全相同；唯一改变 Trie 的公开操作是插入。

代码分析
~~~~~~~~

``Node`` 的固定数组把字符到子节点的查找变成一次下标访问；``unique_ptr`` 让节点所有权随着父节点自动释放，析构时不需要
再维护与 Trie 结构平行的释放代码。``addWord`` 的循环只负责建立路径，终点标记放在循环之后，所以 ``"app"`` 和
``"apple"`` 可以共享 ``app`` 节点而互不覆盖。

``matches`` 的字母分支先取指针再递归，缺失边是最早的剪枝点；点号分支遍历子指针而不生成临时字符串，递归参数中的
``position`` 就是当前路径长度。公共入口 ``search`` 只从根和位置 0 开始，所有跨调用状态都保存在 ``root_``。

``addWord`` 只在缺失边上调用 ``make_unique``，因此两个单词的公共前缀不会被复制；循环结束后才设置 ``terminal``，
保证一个单词的中间节点不会被误认为终点。``search`` 声明为只读接口，递归参数使用 ``const Node*``，从类型层面表达查询
不会改变字典。点号循环按固定 26 个槽位检查空指针，找到一个成功子调用后立即返回，未访问的兄弟分支不产生额外工作。

Trie 是树而不是带合并边的有向图：一个节点只有一条从根到它的前缀路径，因此同一个 ``(node, position)`` 不会由两条不同
路径汇合。无需额外的记忆化表；若把节点结构换成可共享的 DAG，才需要重新考虑状态去重。

复杂度与边界
~~~~~~~~~~~~

设单词长度为 ``L``，Trie 总节点数为 ``N``。``addWord`` 沿一条路径工作，时间为 ``O(L)``；所有节点的固定 26 个槽位
占 ``O(26N)`` 空间，常数字母表下记为 ``O(N)``。无点号的 ``search`` 每层只有一条路径，时间为 ``O(L)``。

含点号时，时间应按实际访问的 ``(Trie 节点, 模式位置)`` 状态数 ``Q`` 计算；点号只在非空子树上分支，最坏才会接近
所有与模式长度相容的 Trie 节点。题目最多两个点号，若只按分支数粗估为 ``O(26^2 L)``，但真实代价还受已加入词的
前缀数量限制。递归栈最多 ``O(L)``，不复制整棵 Trie。

长度为 1 的模式在消费一个字符后立即检查终止标记；只有更长单词时不会误报。空字典的根仍存在，任意非空模式会在第一
个缺失边返回假；重复加入同一单词只会再次设置同一个 ``terminal``，不改变搜索结果。

LeetCode 多语言 RST 学习仓库
============================

本仓库按 LeetCode 题号顺序建设多语言算法学习资料。每道公开算法题对应且只对应一个自包含 RST，
在同一文件中学习题目契约、算法抽象、状态不变量、正确性证明、复杂度、语言边界和十语言实现。

项目目标
--------

* 使用原创题目重述和自建示例；
* 按题号递增推进；
* 普通算法题覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R；
* 讲清解法选择、状态变化、正确性、复杂度和语言真实差异；
* 题解代码不运行、不编译、不对拍，只记录可追溯的静态审查和剩余风险；
* 使用冻结质量基线和批次合同阻止最近产物污染后续格式；
* Premium、Database、Shell 或无法可靠确认的题目按对应状态登记；
* 禁止把单题拆成 ``.inc`` 或通过 ``.. include::`` 拼装正文。

质量控制
--------

仓库把“状态连续性”和“格式示范权”分开：

* ``docs/TUTORIAL_QUALITY_BASELINE.rst`` 冻结黄金题，只提供结构、解释深度和证明质量；
* ``state/BATCH_CONTRACT.toml`` 规定当前范围、样本角色、风险、禁止事项和最小静态审查；
* ``state/DRIFT_LOG.toml`` 记录已发生的结构拆分、摘要退化、最近样本污染和预算失真；
* 最近完成题目只提供术语、平台接口、关联题目和进度事实，不自动成为格式样本；
* 两个以上风险维度为 high 时允许缩批，禁止为了凑 4–6 分压缩复杂题；
* Database 与 Shell 题不符合固定十语言算法产物合同，只登记对应 skipped 状态，不创建空壳教程；
* 题号跨过百题边界后必须进入新的范围目录，并同步创建该目录的 ``README.rst``。

单文件只是结构门。每道合格算法题解还必须包含精确契约、自建示例、问题抽象、解法选择、
状态与不变量、完整证明、真实复杂度、十语言语义、静态审查证据、关键边界、学习链和带答案自检。

执行方式
--------

所有生成、返工、抽查、规则维护和归档由当前对话中的明确指令触发：

#. 读取最新 ``main``、进度、批次合同、冻结基线和 active corrections；
#. 只使用合同选定黄金题学习结构和解释深度；
#. 最近题目只按合同作为事实来源；
#. 按风险决定实际连续范围，高风险叠加时缩批；
#. 按题号登记非算法与受限题，逐题完成算法内容、十语言代码与必要静态审查；
#. 把新题写入正确百题目录，并同步所属范围 README；
#. 执行内容质量门和漂移回归；
#. 同步根索引、进度、知识账本和下一批合同；
#. 显式暂存本轮文件，使用标准 ``git commit`` 形成一个原子提交并非强制推送到 ``origin/main``；
#. 复查本地与远端 ``main``、提交差异、状态和下一步。

仓库任务禁止创建分支、PR、上传分片分支或临时组装工作流。

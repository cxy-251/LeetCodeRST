LeetCode 多语言 RST 学习仓库
============================

本仓库按 LeetCode 题号顺序建设多语言算法学习资料。每道公开可访问题目对应且只对应一个自包含 RST 文件，
在同一文件中学习题目契约、算法抽象、状态不变量、正确性证明、复杂度、语言边界和十语言实现。

项目目标
--------

* 使用原创题目重述和自建示例；
* 按题号递增推进；
* 普通算法题覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R；
* 讲清解法选择、状态变化、正确性、复杂度和语言真实差异；
* 验证记录准确区分运行、编译、静态检查和独立基准对拍；
* 疑难算法周期性复现，语法知识采用解释衰减；
* Premium 或无法可靠确认的题目按规则登记；
* 禁止把单题拆成 ``.inc`` 或通过 ``.. include::`` 拼装正文。

质量基线
--------

单文件只是结构门，不代表题解达标。每道合格题解必须根据题目实际包含：

* 精确契约与平台接口；
* 自建正常示例和必要反例；
* 问题抽象与解法选择；
* 状态定义、核心不变量和完整正确性证明；
* 真实复杂度、语言物化成本和所有权边界；
* 固定十语言实现及语言特化说明；
* 可核实的验证证据；
* 关键边界、易错点、新增与强化知识、关联题目；
* 最小自检与答案要点。

只有“算法、正确性、复杂度、代码、三个问题”的摘要骨架不得计入质量完成。详细验收见
``docs/AUTOMATION_QUALITY_GATE.rst``。

* ``state/REVIEW_INDEX.toml``：active corrections、审查策略与归档索引；
* ``docs/FORWARD_RULES_0101_0150.rst``：``0101–0150`` 阶段规则与历史来源；

* ``docs/AUTOMATION_QUALITY_GATE.rst``：内容、结构、验证和提交质量门；
* ``docs/PROBLEM_TEMPLATE.rst``：单题结构骨架；
* ``docs/SOLUTION_AND_TYPES_POLICY.rst``：解法、平台类型和语言适配器；
* ``docs/REVIEW_AND_PREVENTION_POLICY.rst``：风险触发抽查和历史题边界；
* ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``：只允许直接更新 ``main`` 的执行流程；

* ``problems/0101-0200/README.rst``：当前范围题目索引、Premium 与返工状态。

规则优先级
----------

出现重复或冲突时：

#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections 与 review policy；
#. 当前生效的前向规则；
#. 专项策略、模板和质量门；
#. ``archive/`` 中的历史证据；
#. ``main`` 提交和对话摘要。

执行方式
--------

所有生成、返工、抽查、规则维护和归档由当前对话中的明确指令触发：

#. 读取最新 ``main``、状态、当前规则和成熟基准题；
#. 若 ``needs_revision`` 非空，暂停新题并按连续题号返工；
#. 逐题完成内容、代码与必要验证；
#. 每道公开题只创建一个 RST，正文与十语言代码全部内联；
#. 通用问题维护到长期规则和质量门；
#. 删除无用中间文件；
#. 基于最新树构造一个原子提交直接写入 ``main``；
#. 复查提交差异、状态和下一步；
#. 在对话中报告实际结果。

仓库任务禁止创建分支、PR、上传分片分支或临时组装工作流。

文档形式
--------

题目正文和项目说明以 RST 为主，仓库内容以直接阅读源文件为目标。每个公开题的 RST 必须脱离外部代码分片
即可完整阅读，并且达到教学质量基线，而不是只满足文件存在和代码数量要求。

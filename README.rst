LeetCode 多语言 RST 学习仓库
============================

本仓库按 LeetCode 题号顺序建设多语言算法学习资料。每道公开可访问题目对应且只对应一个自包含 RST，
在同一文件中学习题目契约、算法抽象、状态不变量、正确性证明、复杂度、语言边界和十语言实现。

项目目标
--------

* 使用原创题目重述和自建示例；
* 按题号递增推进；
* 普通算法题覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R；
* 讲清解法选择、状态变化、正确性、复杂度和语言真实差异；
* 题解代码不运行、不编译、不对拍，只记录可追溯的静态审查和剩余风险；
* 使用冻结质量基线和批次合同阻止最近产物污染后续格式；
* Premium 或无法可靠确认的题目按规则登记；
* 禁止把单题拆成 ``.inc`` 或通过 ``.. include::`` 拼装正文。

质量控制
--------

仓库把“状态连续性”和“格式示范权”分开：

* ``docs/TUTORIAL_QUALITY_BASELINE.rst`` 冻结黄金题，只提供结构、解释深度和证明质量；
* ``state/BATCH_CONTRACT.toml`` 规定当前范围、样本角色、风险、禁止事项和最小静态审查；
* ``state/DRIFT_LOG.toml`` 记录已发生的结构拆分、摘要退化、最近样本污染和预算失真；
* 最近完成题目只提供术语、平台接口、关联题目和进度事实，不自动成为格式样本；
* 两个以上风险维度为 high 时允许缩批，禁止为了凑 4–6 分压缩复杂题。

单文件只是结构门。每道合格题解还必须包含精确契约、自建示例、问题抽象、解法选择、
状态与不变量、完整证明、真实复杂度、十语言语义、静态审查证据、关键边界、学习链和带答案自检。

* ``state/BATCH_CONTRACT.toml``：当前批次的范围、风险、黄金样本和完成条件；
* ``state/REVIEW_INDEX.toml``：active corrections 与审查策略；
* ``docs/TUTORIAL_QUALITY_BASELINE.rst``：冻结黄金题与结构漂移判定；
* ``state/DRIFT_LOG.toml``：历史质量事故和回归检查；
* ``docs/FORWARD_RULES_0101_0150.rst``：``0101–0150`` 阶段规则与历史来源；
* ``docs/FORWARD_RULES_0151_ONWARD.rst``：``0151`` 起长期算法和语言规则；
* ``docs/AUTOMATION_QUALITY_GATE.rst``：内容、样本隔离、静态审查、漂移和提交质量门；
* ``docs/SOLUTION_AND_TYPES_POLICY.rst``：解法、平台类型和语言适配器；
* ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``：直接更新 ``main`` 的原子提交流程；
* ``docs/CODEX_GIT_WORKFLOW.rst``：Codex 使用标准 ``git add``、``commit``、``push`` 的安全流程；
* ``state/CONCEPT_LEDGER.toml``：知识账本分段索引；
* ``problems/0101-0200/README.rst``：当前范围题目索引、Premium 与返工状态。

执行方式
--------

所有生成、返工、抽查、规则维护和归档由当前对话中的明确指令触发：

#. 读取最新 ``main``、进度、批次合同、冻结基线和 active corrections；
#. 只使用合同选定黄金题学习结构和解释深度；
#. 最近题目只按合同作为事实来源；
#. 按风险决定实际连续范围，高风险叠加时缩批；
#. 逐题完成内容、十语言代码与必要静态审查；
#. 执行内容质量门和漂移回归；
#. 同步索引、进度、知识账本和下一批合同；
#. 显式暂存本轮文件，使用标准 ``git commit`` 形成一个原子提交并非强制推送到 ``origin/main``；
#. 复查本地与远端 ``main``、提交差异、状态和下一步。

仓库任务禁止创建分支、PR、上传分片分支或临时组装工作流。

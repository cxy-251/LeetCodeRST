LeetCode 多语言 RST 学习仓库
============================

本仓库按 LeetCode 题号顺序建设多语言算法学习资料。每道公开算法题对应一个自包含 RST 文件，目标是在同一文件中讲清题目契约、算法抽象、状态不变量、正确性证明、复杂度、语言边界和十语言实现。

项目目标
--------

* 使用原创题目重述和自建示例，不复制题面原文；
* 按题号递增推进，遇到 Premium、Database、Shell 或题面信息不足的题目只登记进度，不创建空壳教程；
* 普通算法题覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R；
* 题解代码不运行、不编译、不对拍，只记录人工推演、静态审查和剩余风险；
* 每题保持一个自包含 RST，禁止拆成 ``.inc``、代码分片或通过 ``.. include::`` 拼装正文。

控制文件
--------

本仓库只保留三个控制文件：

* ``README.rst``：说明仓库目标、目录结构和总体约定；
* ``AGENTS.md``：规定 ChatGPT/Codex 书写、审查和修改题解时必须遵守的规则；
* ``PROGRESS.rst``：记录当前进度、跳过题目、当前任务和下一入口。

目录中的 ``README.rst`` 只作为题目索引，不承担控制规则职责。

目录结构
--------

题解按百题范围放置：

* ``0001-0100/``；
* ``0101-0200/``；
* ``0201-0300/``。

每个范围目录包含该范围的题解 RST 和一个范围索引 ``README.rst``。新题跨过百题边界时，进入新的百题目录。

当前进度
--------

当前进度、跳过题目和下一任务只看 ``PROGRESS.rst``。根 README 不重复维护完整进度，避免状态分裂。

题解质量底线
------------

合格的公开算法题解至少要让读者看懂：

#. 输入输出、平台接口、值域、字符域、结构前提和副作用；
#. 为什么选择当前算法，而不是只给代码；
#. 状态变量、不变量、更新时机和代码之间的对应关系；
#. 正确性证明如何覆盖合法性、完整性、最优性或终止性；
#. 时间复杂度、核心空间、输入物化、输出载荷和语言适配成本；
#. 十语言实现是否保持同一语义；
#. 哪些边界、失败路径和语言细节仍未运行、未编译、未测试。

执行入口
--------

新的 ChatGPT/Codex 对话应先读取：

#. ``README.rst``；
#. ``AGENTS.md``；
#. ``PROGRESS.rst``；
#. 当前题号所属范围的 ``README.rst``；
#. 当前要生成或审查的题解文件。

不要寻找或恢复旧的 ``state/``、``docs/``、``archive/``、``concepts/`` 控制体系。

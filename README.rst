LeetCode 多语言分析题解仓库
============================

本仓库按 LeetCode 题号顺序整理题目文件。每个题号对应一个自包含 RST：公开算法题形成完整分析题解，Premium、Database、Shell 以及题面暂时无法可靠确认的题目形成简短状态页。

项目产物
--------

* 按题号递增推进，每个题号保留固定文件位置；
* 公开题解从原始搜索空间出发，推导算法转换、状态设计、数据结构选择和复杂度变化；
* C++ 作为主语言，在一个代码块中展示具有独立思想价值的代表性解法；
* 题解正文围绕 C++ 函数讲清基准方法、重复工作、优化来源、关键状态、排除依据、正确性和复杂度；
* 状态变化较强的题目使用跟踪表、状态图、指针示意、DP 小表或操作序列展示执行过程；
* 每个文件从开头到“九语言实现”之前形成独立的 C++ 题解；该标题及其后的多语言实现继续保留，但不作为后续审核和完成判断的必需内容；
* 代码在关键位置使用简洁的中文注释，并包含算法依赖的辅助函数和轮子；
* 状态页记录题号、题名、类型、原题链接和处理状态。
* 题号每 100 道作为一个交付批次，批次完成后统一提交并推送一次，尾批次按实际题目数量处理。

控制文件
--------

根目录使用三个控制文件：

* ``README.rst``：说明仓库目标、产物形态和目录结构；
* ``AGENTS.md``：规定长期稳定的题解结构、教学深度、审查标准和任务闭环；
* ``PROGRESS.rst``：保存下一轮的目标题号、目标文件、工作重点和完成后入口。

接续方式
--------

每轮任务按以下顺序接续：

#. 读取 ``PROGRESS.rst``，确认当前题号和目标文件；
#. 读取 ``AGENTS.md``，确定当前题目对应的文件类型和写作规则；
#. 检查最新 ``main`` 上的目标 RST，只读取和完善已有文件；缺失题号记录状态，不创建新文件；
#. 完成目标题号 RST；
#. 完整重写 ``PROGRESS.rst``，把任务入口推进到下一题；
#. 将目标题号 RST 与新的 ``PROGRESS.rst`` 组成一个原子提交。

目录结构
--------

题目文件按百题范围放置：

* ``0001-0100/``；
* ``0101-0200/``；
* ``0201-0300/``。

题号跨过百题边界时，在新的百题目录中继续。接续状态统一由根目录控制文件维护。

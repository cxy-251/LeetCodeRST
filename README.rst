LeetCode 多语言代码仓库
========================

本仓库按 LeetCode 题号顺序整理多语言代码。每道公开算法题对应一个自包含 RST 文件，主要目标是在同一文件中提供固定语言顺序的可读代码，方便读者复制、运行、调试和自行验证。

项目目标
--------

* 按题号递增推进；
* 普通算法题覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R；
* 每道公开算法题保持一个自包含 RST 文件；
* 题解文件以代码为主，可以保留必要的题目接口、简短思路和复杂度说明；
* 仓库不负责运行、编译、对拍或证明代码正确性，读者拿到代码后自行验证；
* Premium、Database、Shell 或题面信息不足的题目只登记进度，不创建空壳教程；
* 禁止把单题拆成 ``.inc``、代码分片或通过 ``.. include::`` 拼装正文。

控制文件
--------

本仓库只保留三个控制文件：

* ``README.rst``：说明仓库目标、目录结构和总体约定；
* ``AGENTS.md``：规定 ChatGPT/Codex 生成、审查和修改题解代码时必须遵守的规则；
* ``PROGRESS.rst``：记录当前进度、跳过题目、当前任务和下一入口。

目录中的 ``README.rst`` 只作为题目索引，不承担控制规则职责。

目录结构
--------

题解按百题范围放置：

* ``0001-0100/``；
* ``0101-0200/``；
* ``0201-0300/``。

每个范围目录包含该范围的题解 RST 和一个范围索引 ``README.rst``。新题跨过百题边界时，进入新的百题目录。

当前进度
--------

当前进度、跳过题目和下一任务只看 ``PROGRESS.rst``。根 README 不重复维护完整进度，避免状态分裂。

题解最低形态
------------

公开算法题的 RST 至少包含：

#. 题号、英文题名和文件标题；
#. 必要的平台接口或输入输出说明；
#. 固定十语言代码；
#. 必要时保留很短的思路、复杂度或语言差异说明。

不强制要求完整证明、人工推演、静态审查记录、剩余风险说明或自检问题。

执行入口
--------

新的 ChatGPT/Codex 对话应先读取：

#. ``README.rst``；
#. ``AGENTS.md``；
#. ``PROGRESS.rst``；
#. 当前题号所属范围的 ``README.rst``；
#. 当前要生成或修改的题解文件。

不要寻找或恢复旧的 ``state/``、``docs/``、``archive/``、``concepts/`` 控制体系。

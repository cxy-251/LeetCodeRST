0190. Reverse Bits
==================

--------

精确契约
--------

输入一个 32 位无符号整数的位模式，把 32 个二进制位按位置完全反转，
并返回反转后的 32 位无符号结果。

若输入位从高到低为：

``b31 b30 ... b1 b0``

输出必须是：

``b0 b1 ... b30 b31``

关键点是 **宽度固定为 32**。输入的高位前导零也参与反转：
它们会变成输出的低位零。
算法不能只处理到数值变为 0 后就结束，除非还能补齐剩余位的位置移动。

示例与反例
----------

标准示例
~~~~~~~~

输入位模式：

``00000010100101000001111010011100``

反转后：

``00111001011110000010100101000000``

最低位为 1
~~~~~~~~~~

输入 ``00000000000000000000000000000001``，输出
``10000000000000000000000000000000``，即无符号值 ``2^31``。

最高位为 1
~~~~~~~~~~

输入 ``10000000000000000000000000000000``，输出 1。
Java 的输入 ``int`` 在数值显示上为负数，
但 32 位位模式仍完全合法；算法必须使用无符号右移。

全零与全一
~~~~~~~~~~

* 全零反转后仍为 0；
* ``0xFFFFFFFF`` 反转后仍是 ``0xFFFFFFFF``。

错误的“循环到 n 为 0”
~~~~~~~~~~~~~~~~~~~~~~

若输入只有最低位为 1，只循环一次会得到答案 1；
正确答案需要把该位继续左移到第 31 位，结果为 ``2^31``。
因此主循环必须恰好执行 32 轮。

问题抽象与解法选择
------------------

每轮从输入最低位取出一个位：

.. math::

   bit = input \mathbin{\&} 1

然后先把答案左移一位，再把该位放到答案最低位：

.. math::

   answer = (answer << 1) \mathbin{|} bit

最后对输入做逻辑右移，丢弃已经处理的最低位。
重复 32 次后，原最低位经过 31 次后续左移到达输出最高位，
原最高位在最后一轮进入输出最低位。

状态、不变量与实现映射
----------------------

设原输入位为 ``b0,b1,...,b31``，其中 ``b0`` 是最低位。完成 ``t`` 轮后保持：

* ``answer`` 的低 ``t`` 位从高到低依次是 ``b0,b1,...,b(t-1)``；
* ``answer`` 在这 ``t`` 位之外为 0；
* ``input`` 等于原输入逻辑右移 ``t`` 位，最低位是尚未处理的 ``bt``；
* ``0 <= t <= 32``。

也可写成：

.. math::

   answer_t = \sum_{i=0}^{t-1} b_i 2^{t-1-i}

每轮 ``answer<<1`` 给已处理位腾出新最低位置，随后加入 ``bt``；
逻辑右移使下一原位成为输入最低位。

语言映射：

* C、C++、Rust、Go、C# 直接使用无符号 32 位类型；
* Java 返回 ``int``，位模式仍是 32 位，读取输入必须用 ``>>>``；
* Python 整数无固定宽度，但循环固定 32 次且输入限制在无符号 32 位域；
* TypeScript 位运算按有符号 32 位执行，
  每轮用 ``>>> 0`` 重新解释为无符号数值；
* Julia 使用 ``UInt32``；
* R 的整数类型无法表示全部无符号 32 位正值，
  使用精确双精度数做除 2、取余和乘 2，避免 ``bitw`` 的有符号解释。

正确性证明
----------

引理一：循环不变量初始化成立
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``t=0`` 时 ``answer=0``，尚未放入任何位；
``input`` 是原输入逻辑右移 0 位。不变量成立。

引理二：一次迭代保持不变量
~~~~~~~~~~~~~~~~~~~~~~~~~~

假设完成 ``t`` 轮后不变量成立。当前 ``input`` 最低位是原位 ``bt``。
执行 ``answer<<1`` 后，已有序列 ``b0...b(t-1)`` 整体左移一位，
最低位空出；按位或 ``bt`` 后，
答案的低 ``t+1`` 位从高到低成为 ``b0...b(t-1),bt``。

输入逻辑右移一位后，等于原输入逻辑右移 ``t+1`` 位，
下一最低位是 ``b(t+1)``。
因此不变量推进到 ``t+1``。

引理三：32 轮后答案位序完全反转
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

由不变量，``t=32`` 时答案的 32 位从高到低依次是
``b0,b1,...,b31``，恰为原位序反转。
输入已经逻辑右移 32 位，不再包含未处理位。

引理四：算法终止
~~~~~~~~~~~~~~~~

循环计数从 0 单调增加到 32，轮数固定，因此必定终止。

定理：算法返回输入 32 位位模式的完全反转
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

引理二保证每轮按正确次序加入一个原位，引理三给出终止状态，
引理四保证有限结束，所以返回值正确。

复杂度与语言成本
----------------

* 固定执行 32 轮，按题目固定宽度可记为 ``O(1)``；
  若把位宽记作 ``W``，时间为 ``O(W)``；
* 只维护输入副本、答案、当前位和计数，额外空间 ``O(1)``；
* 无输出容器或字符串物化；
* Java 返回的 ``int`` 可能显示为负数，但其 32 位位模式与平台要求一致；
* TypeScript 最终 ``>>>0`` 产生 ``0..2^32-1`` 的精确 ``number``；
* R 的双精度数可精确表示所有 32 位无符号整数及循环中的乘 2 中间值，
  最大不超过 ``2^32-1``。

.. code-block:: c

   #include <stdint.h>

   uint32_t reverseBits(uint32_t n) {
       uint32_t answer = 0U;

       for (int step = 0; step < 32; ++step) {
           answer = (answer << 1U) | (n & 1U);
           n >>= 1U;
       }

       return answer;
   }

边界、失败路径与易错点
----------------------

* 固定位宽是算法合同的一部分，不能遗漏前导零的反转位置；
* Java 必须使用无符号右移 ``>>>``；
* TypeScript 位运算结果需用 ``>>>0`` 规范为无符号数值；
* 返回 32 位位模式时，Java ``int`` 的负数显示不代表位模式错误；
* Python 输入必须按合同限制在 ``0..2^32-1``，否则高于 32 位部分会被忽略；
* R 输入应是可精确表示的非负整数数值，当前合同满足。

自检问题
--------

#. 为什么循环必须执行 32 次？
#. 循环完成 ``t`` 轮后，``answer`` 中保存了哪些位？
#. Java 为什么不能使用 ``>>``？
#. TypeScript 和 R 分别怎样表达无符号 32 位结果？

答案要点
~~~~~~~~

#. 固定宽度中的前导零也必须占据反转后的位置；提前停止会少做左移。
#. 原输入最低的 ``t`` 位按反序排列在答案的低 ``t`` 位中。
#. ``>>`` 会复制符号位，最高位为 1 时输入无法按逻辑位流补零。
#. TypeScript 用 ``>>>0`` 重新解释位模式；
   R 用精确双精度整数做除 2、取余和乘 2。

0191. Number of 1 Bits
======================

题目信息
--------

:题号: 0191
:难度: Easy
:主题: 位运算、Brian Kernighan 算法、汉明重量、无符号语义
:原题: `LeetCode 0191 <https://leetcode.com/problems/number-of-1-bits/>`_

:教学重点: 最低有效 1 消除、循环次数证明、32 位位模式适配

精确契约
--------

输入一个 32 位无符号整数的位模式，返回其中值为 1 的二进制位数量，
也就是汉明重量。

结果范围固定为 ``0..32``。算法处理的是位模式，
不依赖该模式在有符号类型中的数值显示；即使最高位为 1，仍应按 32 个位置统计。

示例与反例
----------

普通示例
~~~~~~~~

``n=11``，二进制低位是 ``1011``，共有 3 个 1，返回 3。

单个高位
~~~~~~~~

``n=128`` 的二进制是 ``10000000``，返回 1。

边界位模式
~~~~~~~~~~

* ``n=0``：没有置位，返回 0；
* ``n=2^31``：只有最高位为 1，返回 1；
* ``n=2^32-1``：32 位全为 1，返回 32。

错误的算术右移循环
~~~~~~~~~~~~~~~~~~

若对有符号输入反复执行算术右移，最高位为 1 时左侧会持续补 1，循环可能无法归零。
主解法不依赖右移，而是反复清除一个置位，因此固定宽无符号位模式一定在有限次操作后变为 0。

问题抽象与解法选择
------------------

设非零位模式 ``n`` 的最低有效 1 位位于位置 ``p``。那么：

* ``n`` 在位置 ``p`` 为 1；
* ``p`` 以下所有位置都为 0；
* ``n-1`` 会把位置 ``p`` 从 1 变为 0，并把更低位置全部变为 1；
* 更高位置保持不变。

因此：

.. math::

   n \mathbin{\&} (n-1)

会清除 ``n`` 的最低有效 1，同时不改变任何更高的 1。
每轮执行一次并把计数加一，直到位模式为 0。
循环次数恰好等于原输入的置位数量。

状态、不变量与实现映射
----------------------

Kernighan 循环维护：

* ``value``：原输入尚未被清除的置位集合；
* ``count``：已经清除的置位数量。

循环开始时始终满足：

.. math::

   count + popcount(value) = popcount(original)

每轮 ``value &= value-1`` 恰好清除一个最低有效 1，
因此 ``popcount(value)`` 减一，``count`` 加一，
总和保持不变。

C++ 主解法使用 ``std::uint32_t``，``value &= value - 1`` 在固定宽位模式上恰好清除最低有效 1，
不需要依赖右移或符号扩展。

正确性证明
----------

引理一：``n-1`` 的位变化只影响最低有效 1 及其低位
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

设最低有效 1 位于 ``p``。由于 ``p`` 以下全是 0，
减一时借位穿过这些低位，把它们变为 1，并把位置 ``p``
从 1 变为 0；位置 ``p`` 以上不需要借位，因此保持不变。

引理二：``n & (n-1)`` 恰好清除最低有效 1
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

位置 ``p`` 在 ``n`` 中是 1、在 ``n-1`` 中是 0，因此按位与后变为 0。
位置 ``p`` 以下在 ``n`` 中全为 0，即使 ``n-1`` 中变为 1，按位与后仍为 0。
位置 ``p`` 以上两数相同，原有的所有位保持。
所以只清除最低有效 1，不改变更高置位。

引理三：循环不变量始终成立
~~~~~~~~~~~~~~~~~~~~~~~~~~

初始化时 ``count=0``、``value=original``，不变量成立。
每轮由引理二，``value`` 的置位数恰好减一，
同时 ``count`` 加一，因此两者之和保持为原置位数。

引理四：循环终止且轮数等于汉明重量
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

每轮清除一个置位。32 位模式最多有 32 个置位，因此有限轮后 ``value=0``。
若原输入有 ``w`` 个 1，前 ``w-1`` 轮后仍剩一个 1，
第 ``w`` 轮清除最后一个；循环恰好执行 ``w`` 次。

定理：算法返回输入的 1 位数量
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

终止时 ``popcount(value)=0``。由循环不变量，
``count=popcount(original)``，所以返回值正确。

复杂度与语言成本
----------------

* 主算法执行次数等于置位数 ``w``，时间 ``O(w)``，且 ``0<=w<=32``；
  固定题目宽度下也可记为 ``O(1)``；
* 只使用 ``value`` 和 ``count``，额外空间 ``O(1)``；
* 返回计数最大 32，C++ ``int`` 足以保存结果；
* 输入只复制到局部位变量中，不修改调用方持有的数值对象。

十语言实现
----------

C
~

.. code-block:: c

   #include <stdint.h>

   int hammingWeight(uint32_t n) {
       int count = 0;

       while (n != 0U) {
           n &= n - 1U;
           ++count;
       }

       return count;
   }

边界、失败路径与易错点
----------------------

* ``n & (n-1)`` 只对非零 ``n`` 执行，循环条件已经保证；
* Java 的有符号显示不影响按位与，但使用算术右移的替代写法可能不终止；
* TypeScript 需要在每轮后重新解释为无符号 32 位；
* Python 若传入负数，任意精度补码模型会导致本循环不适用；
  官方合同是无符号 32 位非负值；
* R 的实现是固定宽逐位计数，不应错误声称执行次数等于置位数；
* 调用语言内建 ``popcount`` 可以正确，
  但会绕开本题要学习的最低位消除性质。

自检问题
--------

#. 为什么 ``n-1`` 会把最低有效 1 变成 0？
#. ``n&(n-1)`` 为什么不会删除更高的 1？
#. 循环次数为什么恰好等于原置位数？
#. Java 和 R 的实现为何不同？

答案要点
~~~~~~~~

#. 减一需要从最低有效 1 借位，该位变 0，低位零变 1。
#. 最低有效 1 以上没有借位，高位在 ``n`` 和 ``n-1`` 中相同。
#. 每轮恰好清除一个 1，直到所有 1 都清除。
#. Java 的 32 位补码按位操作可直接使用 Kernighan；
   R 无完整无符号 32 位整数域，改用精确数值逐位计数。

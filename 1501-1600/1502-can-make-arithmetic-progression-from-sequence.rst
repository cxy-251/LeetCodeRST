1502. Can Make Arithmetic Progression From Sequence
===================================================

题目信息
--------

:题号: 1502
:难度: Easy
:主题: 数组、排序、等差数列
:访问状态: Public
:原题: `LeetCode 1502 <https://leetcode.com/problems/can-make-arithmetic-progression-from-sequence/>`_
:重点: 任意重排看似需要搜索排列，排序可以把所有可能排列压缩成唯一的有序序列

题目重述
--------

给定整数数组 ``arr``，可以任意重新排列其中的全部元素。

若存在一种排列，使任意两个相邻元素之差都相同，则返回 ``true``；否则返回 ``false``。

等差数列允许公差为 ``0``，因此数组中的元素全部相同时也应返回 ``true``。

约束条件：

* ``2 <= arr.length <= 1000``；
* ``-10^6 <= arr[i] <= 10^6``。

朴素枚举
--------

最直接的想法是枚举数组的所有排列，再逐个检查相邻差是否相同。

对某个排列，只需记录前两个元素的差，然后检查后面的每一组相邻元素，因此一次检查需要 ``O(n)`` 时间。只要找到一个合法排列，就可以返回 ``true``。

这种方法在逻辑上没有问题，因为它确实检查了所有可能的排列。但长度为 ``n`` 的数组最多有 ``n!`` 个排列，总时间达到 ``O(n! · n)``。当 ``n`` 最大为 ``1000`` 时，排列搜索完全不可行。

真正的瓶颈不是检查等差数列，而是寻找正确的排列。

排序消除搜索
------------

等差数列的元素顺序具有很强的结构。

若某个合法排列的公差为负数，把整个排列反转后，公差就变成非负数。因此只需考虑从小到大排列的等差数列。

对于公差非负的等差数列，元素一定按非递减顺序出现。也就是说，只要数组能够重排成等差数列，那么排序后的数组本身就必须是这个等差数列。

于是，不需要继续搜索其他排列，只需：

#. 将数组升序排序；
#. 取前两个元素的差作为目标公差；
#. 检查后续所有相邻差是否都等于目标公差。

这个判断同时具备两个方向：

* 若排序后的相邻差全部相同，它本身就是一个合法排列；
* 若排序后的相邻差不相同，就不存在其他合法排列，因为任何递增或不下降的等差排列都只能具有这个排序顺序。

这样便把阶乘级的排列搜索压缩成一次排序和一次线性扫描。

示例推演
--------

可以形成等差数列：

.. code-block:: text

   arr = [9, 3, 7, 5]

排序后：

.. code-block:: text

   [3, 5, 7, 9]

前两个元素确定目标公差：

.. code-block:: text

   difference = 5 - 3 = 2

继续检查：

.. code-block:: text

   7 - 5 = 2
   9 - 7 = 2

所有相邻差都相同，因此返回 ``true``。

无法形成等差数列：

.. code-block:: text

   arr = [1, 4, 6]

排序后仍为 ``[1, 4, 6]``，但相邻差分别为 ``3`` 和 ``2``。排序顺序已经是可能的非递减等差排列所必须采用的顺序，因此不存在其他有效排列，返回 ``false``。

重复元素：

.. code-block:: text

   arr = [4, 4, 4]

排序后所有相邻差都为 ``0``，可以组成公差为 ``0`` 的等差数列。

C++ 实现
--------

.. code-block:: cpp

   class Solution {
   public:
       bool canMakeArithmeticProgression(vector<int>& arr) {
           sort(arr.begin(), arr.end());

           const int difference = arr[1] - arr[0];

           for (int i = 2; i < static_cast<int>(arr.size()); ++i) {
               if (arr[i] - arr[i - 1] != difference) {
                   return false;
               }
           }

           return true;
       }
   };

代码分析
--------

``sort(arr.begin(), arr.end())`` 将所有可能的排列归一化为唯一的升序序列。由于题目只询问是否存在合法排列，不要求保留原数组顺序，因此可以直接在 ``arr`` 上排序。

``difference`` 保存排序后前两个元素的差。题目保证数组长度至少为 ``2``，所以可以直接访问 ``arr[0]`` 和 ``arr[1]``。

循环从下标 ``2`` 开始，逐一比较当前相邻差与目标公差。只要出现一次不同，就说明排序后的数组不是等差数列，可以立即返回 ``false``。

扫描结束仍未发现不同的相邻差，说明排序后的数组就是所需排列，返回 ``true``。

边界情况
--------

* 数组只有两个元素时，任意两个数都能构成等差数列，循环不会执行并直接返回 ``true``；
* 所有元素相同时，目标公差为 ``0``，每个相邻差也都是 ``0``；
* 只有部分元素重复时，排序后会出现公差为 ``0`` 和非零公差混合的情况，检查会返回 ``false``；
* 数组包含负数不影响判断，排序后仍然只需比较相邻差。

复杂度分析
----------

设数组长度为 ``n``。

* 排序需要 ``O(n log n)`` 时间；
* 相邻差扫描需要 ``O(n)`` 时间；
* 总时间复杂度为 ``O(n log n)``；
* 额外空间复杂度取决于排序实现，通常记为 ``O(log n)``。

线性方案
--------

还可以利用最小值、最大值和元素位置设计 ``O(n)`` 方法。

若长度为 ``n`` 的数组能够构成等差数列，那么公差必须满足：

.. code-block:: text

   difference = (maximum - minimum) / (n - 1)

因此首先要求 ``maximum - minimum`` 能被 ``n - 1`` 整除。随后检查每个元素是否恰好落在：

.. code-block:: text

   minimum + k * difference

的某个位置，并保证不同元素没有占用同一个位置。

这种方法可以把时间降到 ``O(n)``，但需要额外记录位置，还要单独处理公差为 ``0``、重复元素和整除关系。题目的数据规模只有 ``1000``，排序方案更短、更稳定，也更直接地体现了“合法排列的排序结果仍是等差数列”这一核心结构。

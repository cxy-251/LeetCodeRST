Julia UnitRange 语义更正
-----------------------

Julia 官方文档把 ``UnitRange`` 定义为使用隐式步长 ``+1``，从起点持续到超过终点。起点已经大于
终点时，该范围为空；递减遍历需要显式写出负步长，例如 ``n:-1:1``。

因此，前几批审查中“``a:b`` 在 ``a>b`` 时自动形成递减序列”的结论错误。本批更正覆盖此前同类
审查备注。历史 RST 不在本阶段回改，后续新题统一采用正确语义。

参考：

* `Julia UnitRange
  <https://docs.julialang.org/en/v1/base/collections/#Base.UnitRange>`_。

0046. Permutations
------------------

正向样本
~~~~~~~~

固定前缀与候选后缀完整表达了“已经使用”和“尚未使用”的元素集合。交换前递归、交换后撤销是同一
可逆操作，完整性、唯一性和状态恢复证明闭合。复杂度也计入了 ``n!`` 个长度为 ``n`` 的答案快照。

前向风险
~~~~~~~~

C 版本以 ``int`` 连乘 ``n!`` 计算外层容量，随后分配外层答案数组、列长度数组和每个结果行。正文
只写“题目约束较小”，没有列出精确 ``n`` 上界，也没有在首次写入前检查分配结果。叶子快照分配
失败会直接进入 ``memcpy``。

多个语言会在搜索期间临时重排输入，递归完成后恢复原顺序。Rust 消费自己拥有的 ``Vec``；R 修改
外层局部绑定并可能产生写时复制。执行期间发生修改、返回前恢复、调用后最终状态是三个不同语义，
需要分别说明。

保存答案必须创建独立快照。Go 切片、Python 列表、Rust ``Vec`` 和托管语言集合若只保存引用，
后续撤销会改写已经保存的答案。

提升规则
~~~~~~~~

* 阶乘容量由精确约束验证，中间乘积使用足够宽的容量类型；
* 外层结果、元数据和每个叶子快照形成完整资源契约；
* 区分临时修改、恢复后的最终输入状态和所有权消费；
* 每个输出快照与可变搜索状态解除别名。

0047. Permutations II
---------------------

正向样本
~~~~~~~~

正文准确区分数值相同与输入下标不同。``used[index-1] == false`` 表示前一个等值副本仍是当前层
候选，选择后一个副本只会生成等价子树；当前值只保留最靠前未使用下标作为规范代表。无重复与
完整性证明分别覆盖了这一规则。

前向风险
~~~~~~~~

C 版本继续使用 ``n!`` 作为外层容量上界，答案数组、列长度、``used``、``path`` 和每个结果行都
没有完整失败处理。排序还会改变输入顺序。

R 使用 ``<<-`` 更新 ``used``，每次选择通过 ``c`` 重建路径，撤销又通过负索引创建新向量。每个
搜索节点可能复制 ``O(n)`` 状态，不能直接使用可变数组语言的 ``O(n × U)`` 时间说明。

不同语言对输入的最终影响不同：C、C++、Python、Java、Go、TypeScript、C# 和 Julia 通常原地排序；
Rust 排序自己拥有的值；R 排序局部绑定。调用后语义应按语言记录。

提升规则
~~~~~~~~

* 去重证明同时跟踪值等价与下标身份；
* 规范代表只删除同层等价分支，不阻止深层使用其他副本；
* 排序和搜索期间的输入修改语义按语言说明；
* R 的路径与标记写时复制计入搜索节点成本。

0048. Rotate Image
------------------

正向样本
~~~~~~~~

把顺时针旋转分解为主对角线转置与行反转，两个阶段都是双射。坐标复合直接得到
``(row, column) -> (column, n-1-row)``。只遍历上三角保证每对对称元素恰好交换一次。

前向风险
~~~~~~~~

十语言实现都依赖严格方阵。C 省略 ``matrixColSize`` 检查，只在每行长度确实为 ``n`` 的平台
契约下成立。

R 返回新的矩阵对象，运行时可能因写时复制分配 ``O(n²)`` 存储。算法没有显式创建第二个结果矩阵，
仍不等于该语言实现拥有字面上的 ``O(1)`` 额外空间。

本题正文关于 Julia ``a:b`` 的说明错误。``a:b`` 不会自动递减；当起点大于终点时它是空
``UnitRange``。现有 ``row < dimension`` 守卫可以保留，但不能用错误的递减范围解释它。

提升规则
~~~~~~~~

* 原地矩阵变换优先分解为可逆双射，并证明复合坐标；
* 方阵、行长度和可变性构成完整接口前提；
* 复制型矩阵适配器单独计算调用后语义与空间；
* Julia 递减遍历使用显式负步长，空 ``UnitRange`` 按真实语义处理。

0049. Group Anagrams
--------------------

正向样本
~~~~~~~~

频次向量是字母异位词等价类的规范签名。正文分别证明“同组一定等价”和“等价一定同组”，并用
分隔符消除十进制字段边界歧义。

前向风险
~~~~~~~~

时间先写为 ``O(L+N)``，随后简写为 ``O(L)``。题目允许空字符串，因此总字符数 ``L`` 可能小于
字符串数量 ``N``；每个输入项至少需要一次分组处理，不能在没有 ``N=O(L)`` 的前提下省略 ``N``。

C 使用固定 ``char signature[160]``，容量没有由最大单词长度、单个计数的十进制位数、26 个分隔符
和终止符推导。``snprintf`` 返回值未验证是否超出剩余空间，``offset`` 可能越过缓冲区，后续
``160-offset`` 会失去意义。

C 的哈希表、分组数组、尺寸数组、容量数组、键副本、字符串副本和 ``realloc`` 缺少整体失败契约。
Rust 使用 ``u16`` 保存频次，也需要由单词最大长度证明不会溢出。

R 通过 ``c`` 扩展 ``key_order`` 和组内成员，组较大时可能产生累计二次复制成本。

提升规则
~~~~~~~~

* 简化复杂度前证明被省略项受主项支配；
* 允许空载荷时保留输入项数量 ``N``；
* 复合签名同时证明编码单射和最大序列化长度；
* ``snprintf`` 检查返回值、剩余容量和终止符；
* 哈希结构与输出分组采用整体成功或整体清理；
* 频次类型由最大单词长度推导。

0050. Pow(x, n)
---------------

正向样本
~~~~~~~~

循环不变量

.. code-block:: text

   answer × factor^exponent = base^E

统一覆盖奇数位乘入、底数平方与指数减半。固定宽整数语言都先扩宽指数再处理最小负数；
TypeScript 使用取模和 ``Math.floor``，避开 JavaScript 位运算的 32 位转换。正文也区分了数学
结构正确性与 IEEE 754 舍入、上溢和下溢。

前向风险
~~~~~~~~

复杂度写为 ``O(log |n|)``，但 ``n=0`` 时 ``log 0`` 没有定义。应使用指数位数或
``O(log(|n|+1))``。

题目重述没有明确 ``x=0, n<0`` 与 ``0^0`` 是否属于输入域。负指数分支会执行 ``1/x``，其语义
依赖精确数学契约与目标语言浮点规则。

TypeScript 和 R 使用浮点数保存指数，在 32 位范围内能够精确表示整数；仍需明确输入是整数，并在
每轮使用取整除法保持整数状态。

提升规则
~~~~~~~~

* 对数复杂度覆盖零指数；
* 浮点数学题列出未定义或特殊输入域；
* 数学不变量与实际浮点误差分别说明；
* 浮点容器承载整数状态时，证明表示范围和整数迭代保持。

最终提升的统一规则
------------------

容量、快照与输入状态
~~~~~~~~~~~~~~~~~~~~

* 阶乘、组合数和输出数量用于预分配前验证中间乘积；
* 每个答案保存独立快照；
* 区分执行期临时修改、返回前恢复和调用后持久修改；
* 所有权消费、借用对象与复制型适配器分别描述。

值身份与等价类
~~~~~~~~~~~~~~

* 重复值算法同时跟踪值相等和输入下标身份；
* 去重选择规范代表，并证明被删除分支由保留分支覆盖；
* 规范签名证明等价双向成立和编码单射。

变换与坐标
~~~~~~~~~~

* 矩阵、排列和索引变换拆成可逆映射；
* 每个位置或元素恰好处理一次；
* 复合映射与目标坐标一致；
* 容器形状、索引基准和语言范围语义按实际实现验证。

复杂度表达
~~~~~~~~~~

* ``O(f+g)`` 简化为 ``O(f)`` 前证明 ``g=O(f)``；
* 空字符串、空载荷和零指数保留独立规模变量；
* R 的写时复制和动态 ``c`` 追加重新计算；
* 数字序列化、哈希键、输出快照和返回副本计入真实载荷。

数值与浮点契约
~~~~~~~~~~~~~~

* 类型宽度由完整聚合上界和容量表达式推导；
* 最小负整数先扩宽再取反；
* 浮点题明确特殊输入域、舍入、上溢和下溢；
* 对数表达使用 ``log(x+1)``、位数或表长覆盖零值。

0031. Next Permutation
----------------------

正向样本
~~~~~~~~

最长非递增后缀说明当前后缀已经达到最大排列；最右枢轴保留最长前缀；最右侧严格更大元素给出
枢轴的最小增加；反转剩余后缀得到固定新前缀下的最小排列。这四步共同证明结果是字典序直接后继，
而不是任意更大排列。

Rust 没有让 ``usize`` 递减到 ``-1``，而是在 ``pivot == 0`` 时直接处理整体最大排列，也是合理的
语言特化控制流。

前向风险
~~~~~~~~

后继扫描直接执行 ``while nums[successor] <= nums[pivot]``，没有显式边界条件。它之所以安全，是因为
枢轴定义已经提供见证：``nums[pivot + 1] > nums[pivot]``，后缀中一定存在严格更大元素。此类无边界
递减必须把见证存在性写在代码附近，不能只依靠读者自行推导。

C++ 使用 ``vector``、``swap`` 和 ``reverse``，但代码块没有直接展示对应头文件。C++、Rust 等实现
还把容器长度或位置转换为 ``int`` / ``i32``，题目重述没有列出证明窄化安全的精确最大长度。

R 返回修改后的向量副本。算法只维护常数个索引并不等于 R 适配器只使用 ``O(1)`` 总额外成本；
写时复制和返回语义需要单独报告。

提升规则
~~~~~~~~

* 无边界递减或弹栈前，证明后继、哨兵或非空元素必然存在；
* 原地排列证明元素多重集不变、结果严格增大、没有中间排列以及最大排列回绕；
* 容器长度窄化由精确上界证明；
* 标准库符号直接导入，适配器复制单独计费。

0032. Longest Valid Parentheses
-------------------------------

正向样本
~~~~~~~~

``-1`` 哨兵把从下标零开始的合法区间长度统一成普通减法；多余右括号成为新的失效边界，未匹配
左括号阻止合法后缀继续向左扩展。每个下标最多压栈、弹栈一次也直接支撑线性复杂度。

前向风险
~~~~~~~~

C 在 ``malloc`` 后立即写入 ``stack[0]``，没有检查分配结果。资源失败发生在首次写入之前，因此
必须在解引用前处理，不能让分配失败表现为未定义行为。

Julia 主代码对空字符串执行 ``0:(length(chars)-1)``，也就是 ``0:-1``，随后访问不存在的字符。
正文已经明确指出应在 ``collect`` 前添加 ``isempty(s) && return 0``，但必要修复仍停留在代码块之后。
主代码已知有缺陷时，补充说明不能代替修复本身。

栈方案中的 ``pop`` 安全依赖完整哨兵不变量：初始化时非空；每次右括号处理前非空；弹空后立即把
当前位置作为新边界压回；``-1`` 只表示边界，不是合法字符串下标。该不变量应与 ``pop`` 紧邻。

提升规则
~~~~~~~~

* 正文确认的必要守卫、导入和修复必须直接进入主代码；
* C 分配结果在首次写入前检查；
* 哨兵栈完整证明初始化、弹出前非空、弹空后的恢复和哨兵语义；
* ``n + 1`` 容量和下标类型由精确长度约束支撑。

0033. Search in Rotated Sorted Array
------------------------------------

正向样本
~~~~~~~~

本题对闭区间二分的说明完整：目标若存在始终位于当前区间；每轮至少一个半区有序；目标值域决定
哪一侧可安全排除；中点提前检查；区间每轮严格缩小。元素互不相同也是判断有序半区所需的关键
前提，正文没有把该结论错误外推到重复元素版本。

前向风险
~~~~~~~~

C++ 将 ``size_t`` 转成 ``int``，Rust 将 ``usize`` 转成 ``i32``。正文没有给出数组最大长度，因此
无法由当前文件证明这些窄化包含所有合法下标。

该函数返回“命中下标或 ``-1``”。它与 0034、0035 返回插入边界的二分函数表面相似，调用语义却
完全不同。二分模板若只记录区间形式而不记录返回语义，很容易把边界坐标直接当作元素下标访问。

提升规则
~~~~~~~~

* 二分函数首先声明返回命中位置、插入边界、末尾外位置还是失败哨兵；
* 所有长度和下标窄化覆盖最大合法下标与边界 ``n``。

0034. Find First and Last Position of Element in Sorted Array
-------------------------------------------------------------

正向样本
~~~~~~~~

``lower_bound`` 与 ``upper_bound`` 都以半开区间寻找第一个满足单调谓词的位置。存在性验证把“合法
插入位置”与“真实命中”分开，直接表达严格大于也避免了 ``target + 1`` 的整数溢出。

前向风险
~~~~~~~~

C 为两元素答案数组分配内存后没有检查 ``NULL``，随后立即写入两个槽位。返回元数据、分配失败和
调用者释放责任需要组成一个完整契约。

多个语言通过 ``upper`` 或 ``strict`` 布尔参数复用边界函数。当前正文已经解释参数意义，后续仍应
要求函数先定义单调谓词，并让参数名、调用点和返回值清楚区分 lower/upper，避免布尔模式反转。

Rust、C++ 的边界最终转换为 ``i32`` / ``int``，同样缺少精确最大长度支撑。

提升规则
~~~~~~~~

* C 在答案数组首次写入前验证分配结果；
* 边界辅助函数命名单调谓词和 lower/upper 模式；
* 返回的插入边界必须先做存在性验证，再作为数组元素下标使用。

0035. Search Insert Position
----------------------------

正向样本
~~~~~~~~

查找命中与插入位置统一成 ``lower_bound``，半开区间自然允许答案等于 ``n``。正文通过不变量推导
比较符号和更新方向，没有要求读者机械记忆模板。

前向风险
~~~~~~~~

正文提供空数组示例，却没有列出精确官方长度约束并说明空数组是否属于主动扩展。官方契约与通用
扩展需要分开，尤其当扩展影响循环初始化和返回边界时。

返回值可能等于 ``n``，它是合法边界坐标，却不是可直接访问的元素下标。Rust、C++ 又将该边界
窄化为 ``i32`` / ``int``，因此精确长度上界必须覆盖 ``n`` 本身，而不仅是 ``n - 1``。

提升规则
~~~~~~~~

* 边界坐标与元素下标明确区分；
* 答案为 ``n`` 时禁止未经检查直接索引数组；
* 官方长度约束与空数组扩展分别说明；
* 窄化证明覆盖末尾外边界。

本批提升的统一规则
------------------

见证存在后才能省略边界检查
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* 无边界递减扫描先证明满足条件的元素必然存在；
* ``pop``、``unwrap``、非空断言由紧邻不变量支撑；
* 哨兵不是普通数据，要说明初始化、恢复和退出条件。

主代码必须自洽
~~~~~~~~~~~~~~

* 已知必要修复直接并入主代码块；
* 不能展示会越界、无法编译或失败路径未闭合的代码，再在正文后要求读者自行添加补丁；
* 教学解释、边界清单与实际代码使用同一版本。

索引窄化覆盖边界坐标
~~~~~~~~~~~~~~~~~~~~

* ``size_t`` / ``usize`` / 容器长度转换为 ``int`` / ``i32`` 前列出精确上界；
* 插入位置可等于 ``n``，窄化证明必须覆盖 ``n``；
* ``-1`` 哨兵需要有符号类型或语言特化控制流。

排列与二分证明各自覆盖真实语义
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* 排列题证明多重集保持、结果方向、邻接最优和回绕；
* 二分题定义区间不变量、单调谓词、缩小方向、终止性和返回语义；
* 命中下标、插入边界、末尾外位置与失败哨兵不得混用。

C 分配在首次写入前闭合
~~~~~~~~~~~~~~~~~~~~~~

* ``malloc`` / ``calloc`` 返回值在第一次解引用前检查；
* 返回数组的尺寸元数据、失败返回和调用者释放责任保持一致；
* 不把资源失败伪装成正常空答案。

资料分层
--------

题目正文
~~~~~~~~

``problems/0001-0100/0001`` 至 ``0050`` 是被审查对象。审查阶段保持原样，只有用户明确指定某一道题
需要修复时，才进入该题的独立修复流程。

结构化审查记录
~~~~~~~~~~~~~~

``state/REVIEW_0001_0050.toml`` 与 ``state/reviews/*.toml`` 保存：

* 单题正向样本；
* 单题观察；
* 规则候选和规则编号；
* 批次范围与下一步。

这些文件用于追溯“某项规则来自哪一道题”，不直接作为新题生成清单。

详细审查证据
~~~~~~~~~~~~

``docs/REVIEW_FINDINGS_0001_0050.rst`` 与 ``docs/review-findings/*.rst`` 保存完整的文字分析。
它们属于审查快照，保留当时的观察过程。后来发现的事实更正由 ``state/REVIEW_INDEX.toml`` 的
``corrections`` 条目覆盖。

最终前向规则
~~~~~~~~~~~~

``docs/FORWARD_RULES_0051_0100.rst`` 是 ``0051–0100`` 唯一的完整执行规则。批次记录中的重复表达、
早期候选或被更正结论，不再直接约束新题。

专项文件
~~~~~~~~

* ``docs/AUTOMATION_QUALITY_GATE.rst``：当前对话批次的验收步骤和完成条件；
* ``docs/SOLUTION_AND_TYPES_POLICY.rst``：解法选择、平台类型、标准库和语言适配器边界；
* ``docs/PROBLEM_TEMPLATE.rst``：单题 RST 的结构骨架；
* ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``：对话驱动、原子提交到 ``main`` 的执行流程；
* ``docs/REVIEW_AND_PREVENTION_POLICY.rst``：审查证据与历史题处理边界。

规则优先级
----------

出现重复或冲突时，按以下顺序解释：

#. ``state/PROGRESS.toml``：当前阶段、下一题和本轮状态；
#. ``state/REVIEW_INDEX.toml`` 中的事实更正；
#. ``docs/FORWARD_RULES_0051_0100.rst``：新题完整质量规则；
#. 当前专项文件，例如解法类型、模板、RST 风格或执行流程；
#. 批次审查记录和详细发现；
#. 历史提交说明、PR 描述和对话报告。

高优先级文件覆盖低优先级文件。批次证据用于追溯，不用于覆盖已经整理后的最终规则。

已解决的冲突
------------

Julia ``UnitRange``
~~~~~~~~~~~~~~~~~~~

Julia ``a:b`` 是隐式步长 ``+1`` 的 ``UnitRange``。当 ``a>b`` 时范围为空；递减遍历需要显式负步长，
例如 ``n:-1:1``。该结论覆盖早期批次记录中“``a:b`` 会自动递减”的错误描述。

执行方式
~~~~~~~~

当前工作由用户在对话中明确触发，完整结果以一个原子提交写入 ``main``。旧质量门中的定时任务、
固定自动分支和默认 PR 流程已经移除。分支和 PR 只在用户明确选择评审或隔离流程时使用。

历史题修复边界
~~~~~~~~~~~~~~

逐题审查的发现默认用于 ``0051–0100``。历史题不因审查记录中的确定性观察自动修改；用户明确指定
具体题目后，才读取该题完整上下文并执行独立修复。

维护方式
--------

新增前向规则时：

#. 在当前题 RST 中落实正确实现；
#. 必要时更新 ``docs/FORWARD_RULES_0051_0100.rst``；
#. 专项文件只保存其职责范围内的说明，不复制整套规则；
#. 事实更正登记到 ``state/REVIEW_INDEX.toml``；
#. 不回写或重排旧批次证据，除非记录本身无法定位或严重误导且用户明确要求整理历史记录。

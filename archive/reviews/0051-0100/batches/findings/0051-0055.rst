范围与阶段结果

这是 ``0051`` 至 ``0100`` 第二轮审查的第一批。历史题目正文保持原样；本文件记录证据，结构化结论
同步写入 ``state/reviews/0051-0055.toml``。本批确认两个确定性的 R 语言问题，并登记到
``state/REVIEW_INDEX.toml`` 的高优先级更正。

R 语义依据
----------

本批两项确定性结论来自 R 官方语言定义，而不是从其他语言实现类推：

* 复杂下标赋值 ``x[i] <- value`` 概念上会把修改后的对象重新绑定到目标变量；函数每次调用都有独立
  求值环境，闭包的 enclosing environment 并不是递归调用者的帧。普通 ``<-`` 因而不会把调用帧中的
  局部向量修改传递给下一次递归调用；
* ``seq.int(from, to, by)`` 要求 ``to-from`` 与 ``by`` 的方向一致，符号相反时直接报错，不会像
  C 风格 ``for`` 条件那样自然执行零次。

参考：

* `The R Language Definition：subset assignment 与 lexical environment
  <https://cran.r-project.org/doc/manuals/r-release/R-lang.html>`_；
* `R seq / seq.int documentation
  <https://stat.ethz.ch/R-manual/R-devel/library/base/html/seq.html>`_。

0051. N-Queens
--------------

正向样本
~~~~~~~~

正文把搜索深度固定为行号，使用列、``row-col`` 对角线与 ``row+col`` 对角线三组占用状态。进入
``dfs(row)`` 时的合法前缀、占用数组一致性和撤销关系都直接对应代码。合法性、完备性、无重复与
终止性分别证明，输出成本也单独计入 ``S*n^2`` 个字符。

C 版本是本批资源管理的正向样本：结果扩容先建立两份新元数据数组，成功后再提交；每个棋盘的行指针
先初始化为空，任一行失败可以释放已经完成的部分；最终失败清理外层数组和所有完整棋盘。

前向风险：R 递归状态没有共享
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

R 版本在 ``dfs`` 内写出：

.. code-block:: r

   placement[[row]] <- col
   columns[[col]] <- TRUE
   diag_down[[down]] <- TRUE
   diag_up[[up]] <- TRUE
   dfs(row + 1L)

这些是普通复杂赋值。它们会在当前 ``dfs`` 调用帧创建局部绑定。递归调用的函数 enclosure 是定义
``dfs`` 时的外层环境，不是当前调用帧，所以子调用读取不到父层刚写入的 ``placement`` 和占用向量。
``save_board`` 也从定义环境读取最初的 ``placement``。因此该实现不能维护正文要求的递归路径和约束
状态，属于确定性正确性问题。

正文随后声称“列、对角线和路径通过闭包共享并撤销”，与 R 实际作用域相反。该语言没有运行验证，静态
检查也没有识别问题。

提升规则
~~~~~~~~

* R 递归共享状态使用显式参数返回、``environment`` 引用状态，或经过审计的 ``<<-``；
* 逐层验证子调用确实观察到父层选择，而不是只比较十语言代码形状；
* 修复状态传递后重新计算向量复制、别名与峰值空间；
* 高风险语言语义缺少运行时，只能保留“静态未验证”状态。

0052. N-Queens II
-----------------

正向样本
~~~~~~~~

本题把 0051 的绝对对角线数组改为“当前行攻击列”掩码。``columns``、``diag_down`` 和 ``diag_up``
的每一位都在当前递归层解释；候选补集、最低置位提取、下一行的左右位移和 ``full`` 裁剪形成完整
状态变换。

``n <= 9`` 同时支撑 C/Java/C#/TypeScript 的有符号位运算、Rust/Julia 的无符号掩码以及 R 的
32 位 ``bitw*`` 接口。本题只返回计数，正确删除了 0051 的棋盘快照成本。

前向风险
~~~~~~~~

位掩码代码很短，真正的正确性依赖三个容易被隐藏的前提：

* 掩码属于当前行坐标系，而不是全局绝对对角线编号；
* ``\`` 与 ``/`` 的位移方向由列编号方向确定；
* 取反和移位后必须重新裁剪到有效低 ``n`` 位。

Rust、C#、Julia 和 R 未执行。``wrapping_neg``、无符号取负以及 R 的 32 位位运算属于语言特定语义，
不能由其他语言运行通过替代。

提升规则
~~~~~~~~

* 位掩码递归先定义“位属于哪个坐标系、哪一层”；
* 补集、移位方向和边界裁剪分别证明；
* signed、unsigned、TypeScript 和 R 的有效位宽由精确约束推导；
* 语言特定最低位操作至少执行最小语义测试。

0053. Maximum Subarray
----------------------

正向样本
~~~~~~~~

``ending_here`` 被定义为“必须以当前位置结尾”的最优非空子数组和，``best`` 是已经扫描前缀中的全局
最优。正文通过唯一右端点把局部状态与全局答案连接起来，并把转移完整分成“从当前位置开始”和“连接
前一个最优后缀”两类。

初始化使用首个真实元素，正确处理全负数组。Python 使用迭代器避免 ``nums[1:]`` 复制；Go 明确
切片表达式只建立描述符；Rust 说明按值传入的向量被消费。这些语言差异与复杂度一致。

前向风险
~~~~~~~~

本题没有发现确定性代码错误。仍有两项值得提升为通用检查动作：

* 非空优化问题不能使用不属于候选域的 ``0`` 或空集合初始化；
* 数值证明需要覆盖 ``ending_here + value`` 这一临时候选。该值代表真实连续区间，因此同样受
  ``n * max_abs_value`` 约束，不能只引用最终 ``best`` 的范围。

提升规则
~~~~~~~~

* 非空区间、路径和集合优化从首个合法候选初始化，或使用显式不存在状态；
* 数值安全同时覆盖临时候选、滚动状态和最终答案；
* 切片、迭代器和所有权消费按目标语言真实成本说明。

0054. Spiral Matrix
-------------------

正向样本
~~~~~~~~

剩余元素始终构成 ``[top..bottom] x [left..right]`` 的闭合矩形。正文围绕“外圈按上、右、下、左顺序
输出”和“边界单调收缩”证明顺序、完整性、无重复和终止。Julia 已使用显式负步长完成反向遍历，避免
第一次审查发现的 UnitRange 误解。

确定性问题：R 反向范围在退化矩形中报错
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

R 代码在输出上边后增加 ``top``，输出右边后减少 ``right``。第三条边只检查 ``top <= bottom``：

.. code-block:: r

   if (top <= bottom) {
     for (col in seq.int(right, left, by = -1L)) {
       ...
     }
   }

单列矩阵中，``right`` 会减到 ``0``，而 ``left`` 仍为 ``1``。此时 ``top <= bottom`` 可能成立，
``seq.int(0, 1, by=-1)`` 的步长方向与端点相反，会在循环开始前报错。第三条边还需要
``left <= right``。

第四条边只检查 ``left <= right``。宽度大于 1 的单行矩阵输出上边后会出现 ``bottom < top``，却
仍可能构造 ``seq.int(bottom, top, by=-1)``，同样报错。第四条边还需要 ``top <= bottom``。

C、C++、Java、Go 和 TypeScript 的递减 ``for`` 循环会先检查循环条件，起点越界时自然零次执行；
R 的 ``seq.int`` 必须先构造完整序列，不能逐字移植控制流。正文列出的单行和单列验证没有在 R 运行，
因此没有覆盖这一路径。

提升规则
~~~~~~~~

* 构造显式步长范围前同时验证端点顺序和步长方向；
* 退化单行、单列和中心单点必须在每种目标语言实际运行；
* 不把 C 风格循环的零次迭代语义自动外推到范围对象；
* 历史 RST 保持原样，事实更正由 ``REVIEW_INDEX`` 提供更高优先级说明。

0055. Jump Game
---------------

正向样本
~~~~~~~~

正文没有把 ``farthest`` 解释为具体落点，而是解释为已经扫描的可达位置能够覆盖的最右端。失败条件
``index > farthest`` 和成功条件 ``farthest >= n-1`` 都来自同一可达前缀不变量。

最关键的证明是：从可达位置 ``i`` 可以选择 ``1..nums[i]`` 中任意步数，因此新增可达位置是一个连续
区间，所有出边并集仍是前缀。这个契约使离散图状态能够压缩成单个边界。

前向风险
~~~~~~~~

本题没有发现确定性实现错误。该贪心模式不能机械迁移到“必须恰好跳固定步数”的问题；固定步长可能
产生带空洞的可达集合，单个 ``farthest`` 会丢失状态。

``farthest`` 允许超过数组末尾，它是抽象覆盖端点。只有循环中的 ``index`` 经过 ``index<n`` 检查后
才用于读取 ``nums[index]``。

提升规则
~~~~~~~~

* 把图状态压缩为区间前，证明每个转移覆盖所有中间端点；
* 区分抽象边界、插入位置与真实可访问下标；
* 可达性和最少步数分别维护所需状态，不能混用 0045 的层边界。

本批提升的统一规则
------------------

R 状态与范围语义
~~~~~~~~~~~~~~~~

* 普通复杂赋值不会自动修改递归闭包外层向量；
* 共享状态选用显式参数、引用环境或经验证的 superassignment；
* ``seq.int`` 的端点差与步长方向必须一致；
* 语言特定作用域和范围构造需要可执行边界测试。

状态压缩的前提
~~~~~~~~~~~~~~

* 位掩码先定义位的坐标系和递归层含义；
* 取反与移位后裁剪有效位宽；
* 离散可达集合压缩为区间前，证明转移结果没有空洞；
* 抽象边界只有通过范围检查后才能用于内存访问。

非空状态与数值候选
~~~~~~~~~~~~~~~~~~

* 非空优化从首个合法候选初始化；
* 临时候选、滚动状态和最终答案都需要数值上界；
* 语言的切片、复制、闭包赋值和所有权语义进入真实复杂度。

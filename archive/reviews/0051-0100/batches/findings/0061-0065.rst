0061. Rotate List
-----------------

正向样本
~~~~~~~~

题解先计算 ``shift = k % n``，把大范围旋转化为一次切分。常规引用语言先把原尾连回原头，再定位
``n-shift-1`` 下标的新尾并断开唯一出边。证明同时覆盖：

* 有效旋转步数；
* 新尾和新头位置；
* 节点身份与节点数量守恒；
* 原前缀和后缀内部相对顺序；
* 最终结构重新无环。

随机验证使用节点身份数组作为参考，不会因重复节点值产生假阳性。

Rust 所有权适配
~~~~~~~~~~~~~~

``Option<Box<ListNode>>`` 无法在安全 Rust 中构造共享引用环。实现没有机械翻译成环，而是在前缀末尾
``take`` 出后缀，再把旧前缀所有权接到新后缀尾部。审查重点是证明两种控制流拥有相同切分点、节点集合
和最终遍历顺序，而不是要求十语言逐语句同构。

前向风险
~~~~~~~~

临时成环期间，中间结构违反题目要求的“最终无环”约束。当前代码只有一个成环后的退出路径，因此安全；
未来维护若在定位阶段加入提前返回，必须先断环。临时拓扑算法应明确记录：

#. 临时修改发生的位置；
#. 修改后允许执行的操作；
#. 唯一恢复位置；
#. 所有异常和提前退出是否经过恢复。

提升规则
~~~~~~~~

* 临时拓扑必须审计完整恢复路径；
* 所有权模型不支持字面算法时，允许采用可证明等价的线性变换；
* 原地结构验证使用节点身份、节点数和无环性，不只比较值。

0062. Unique Paths
------------------

正向样本
~~~~~~~~

最后一步来自上方或左方的分类互斥且完备。一维 ``dp`` 从左向右更新时，旧 ``dp[col]`` 是上一行同列，
新 ``dp[col-1]`` 是当前行左侧，覆盖顺序与二维转移完全一致。``dp[0]=1`` 自然覆盖单格、单行和单列。

最终上界为什么能约束中间状态
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

正文称所有前缀子网格状态不超过完整终点答案。该结论在本题成立，还需要补出支配见证：任意到达前缀
单元格的路径，都可以继续只向右和向下走到完整网格终点。给每条前缀路径追加固定的“先向右、再向下”
后缀，就得到不同的终点路径，因此前缀路径集合可单射到终点路径集合。

这类证明不能只写“状态位于前缀，所以更小”。只有存在单调扩展或集合嵌入时，最终上界才能用于中间
整数宽度。

其他观察
~~~~~~~~

``O(n)`` 空间中的 ``n`` 是列数。若实现交换行列以使用较短维度，应把复杂度写成 ``O(min(m,n))``，
并同步调整循环方向和状态含义。组合数对照解法即使最终答案适合 32 位，逐项乘法仍需要更宽中间类型。

0063. Unique Paths II
---------------------

正向样本
~~~~~~~~

障碍单元格执行 ``dp[col]=0``，会同时阻断旧上方状态向下传播和当前状态向右传播。统一的
``dp[0]=1`` 初始化也能在第一次扫描时自然处理开放起点或障碍起点。

为什么最终答案上界不够
~~~~~~~~~~~~~~~~~~~~~~

障碍可能让某个前缀拥有大量路径，却在后续被完全封死，所以中间计数可以大于最终答案。该题不能照搬
0062 的“最终值支配全部前缀”论证。

当前实现把状态截断到 ``L=2_000_000_001``，并使用 64 位暂存。正确性依赖两个条件：

#. 对非负加法转移，
   ``min(min(a,L)+min(b,L),L) = min(a+b,L)``；
#. 题目保证最终真实答案不超过 ``2_000_000_000``，严格小于 ``L``。

因此截断状态在终点仍恢复为真实答案。只写“防止溢出所以 clamp”而没有转移同态与最终阈值证明，并不足以
保证精确性。

失败哨兵
~~~~~~~~

本题合法答案包含 ``0``。C 版本把分配失败表示为 ``-1``，正确避开输出域；0062 可以使用 ``0`` 的理由
不能迁移到本题。

提升规则
~~~~~~~~

* 最终上界约束中间状态前证明状态到最终结果的嵌入；
* 饱和 DP 证明截断与全部转移兼容，并保证真实终点低于阈值；
* 每道题重新根据输出域选择资源失败哨兵。

0064. Minimum Path Sum
----------------------

正向样本
~~~~~~~~

第一行和第一列各自只有一个合法前驱，因此先做前缀累加；内部位置才使用
``min(上方, 左方)+当前值``。一维覆盖顺序和最优子结构证明完整，输入网格保持只读。

数值上界
~~~~~~~~

路径和上界来自单条合法路径访问的位置数：

.. code-block:: text

   最大路径长度 = m + n - 1
   最大路径和   = (m + n - 1) × max_cell

本题最大为 ``399 × 200 = 79800``。不能使用网格状态数 ``mn`` 代替路径长度，也不能只证明最终答案
而忽略转移候选加上当前单元格后的中间和。

零值与输入契约
~~~~~~~~~~~~~~

零是合法单元格代价，不能充当未初始化、不可达或无穷大哨兵。原地改写网格确实可把额外工作空间降为
``O(1)``，但它改变调用后输入；若调用者必须保留原网格，就需要重新计入 ``O(mn)`` 复制。

0065. Valid Number
------------------

算法结论
~~~~~~~~

四个布尔状态正确表达：

* 是否见过底数数字；
* 是否见过小数点；
* 是否进入指数；
* 指数标记之后是否已经补齐数字。

符号只允许位于开头或紧跟指数；小数点只位于底数；指数只能出现一次且前后都需要数字见证。结束时同时
检查底数数字与指数完成状态，可以排除 ``"."``、``"e1"``、``"1e"`` 和 ``"1e-"``。

确定性复杂度表述问题
~~~~~~~~~~~~~~~~~~~~

复杂度段写道 Julia 和 R 的实现都需要 ``O(n)`` 辅助存储。R 的 ``utf8ToInt(s)`` 的确物化整数码点
向量；Julia 的 ``codeunits(s)`` 不同。Julia 官方文档说明它默认返回 ``CodeUnits`` wrapper，即一个
vector-like 包装对象。该题后面的 Julia 说明也把它称为底层 UTF-8 代码单元视图。

因此应区分：

* Julia：``CodeUnits`` 轻量包装和扫描状态为 ``O(1)`` 辅助空间；
* R：``utf8ToInt(s)`` 物化长度 ``n`` 的向量，辅助空间为 ``O(n)``。

历史正文按本轮策略不修改，``state/REVIEW_INDEX.toml`` 新增事实更正覆盖该复杂度句。

R 常量分类
~~~~~~~~~~

R 实现每轮多次调用 ``utf8ToInt("0")``、``utf8ToInt("e")`` 等单字符转换。输入上限很小，渐进时间仍是
``O(n)``，峰值仍由输入码点向量决定；前向实现应在循环前缓存字符码，减少隐藏分配并让分类条件更清楚。

提升规则
~~~~~~~~

* 区分轻量 wrapper、零拷贝视图、延迟迭代器和物化副本；
* 语法标记触发后续必需成分时，维护独立待满足见证；
* 循环内不重复执行与下标无关的字符常量转换。

本批提升的统一规则
------------------

结构与所有权
~~~~~~~~~~~~

* 临时成环、线索或其他中间拓扑必须证明所有退出路径恢复最终结构；
* 语言所有权不支持字面算法时，证明替代变换的节点集合和最终顺序等价；
* 原地结构测试必须覆盖节点身份和无环性。

状态上界与数值
~~~~~~~~~~~~~~

* 最终答案上界只有在中间状态可嵌入最终对象时才能约束全部中间值；
* 障碍、删除、抵消或死路会破坏这种支配关系；
* 饱和 DP 需要转移兼容性和最终阈值两部分证明；
* 路径和按单条路径长度推导，不按整个状态空间大小推导。

语言适配成本
~~~~~~~~~~~~

* wrapper、视图和物化副本分别计费；
* 输出域决定失败哨兵；
* 合法零值不能兼任未初始化标记；
* 循环不变的分类常量应预先计算。

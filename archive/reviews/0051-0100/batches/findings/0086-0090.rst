0086. Partition List
--------------------

正向样本
~~~~~~~~

实现逐个取出原链表节点，先保存原后继并断开 ``next``，再根据 ``node.val < x`` 把节点追加到
``before`` 或 ``after`` 尾部。两条链只做尾插，因此各分区内部的节点相对顺序与原链表一致。扫描结束
后只增加 ``before_tail -> after_head`` 一条受控边。

C、C++、Python、Java、Go、TypeScript、C#、Julia 和 R 使用两个哨兵与两个链尾。Rust 直接维护两个
``Option<Box<ListNode>>`` 所有权槽位，``take`` 分离后继，随后把独占节点移动到对应尾槽。十语言都复用
原数据节点，没有通过交换值伪造稳定分区。

拓扑隔离与稳定性证书
~~~~~~~~~~~~~~~~~~~~

稳定链表分区不能只比较返回值序列。相同值节点仍具有不同身份，完整验证应覆盖：

* 每个原节点恰好出现一次；
* 小于 ``x`` 的节点全部位于前段；
* 两个分区内部按原身份顺序排列；
* 返回链没有哨兵节点、遗漏节点或环。

本题通过逐节点断开旧 ``next`` 保证旧拓扑不会逃逸。其他实现也可以保留旧边到扫描末尾再统一终止，
但必须提供等价的尾部终止和无环证明。

前向规则
~~~~~~~~

* 稳定分区同时证明值分类、原相对顺序和节点身份守恒；
* 重建多条链时断开旧边，或明确证明最终尾部终止足以隔离旧拓扑；
* 链表测试同时检查节点集合、数量、顺序和无环性。

0087. Scramble String
---------------------

正向样本
~~~~~~~~

状态 ``solve(i, j, length)`` 精确表示两个等长区间是否互为 scramble。每个非叶状态枚举
``1 <= split < length``，并完整检查：

* 不交换：左对左、右对右；
* 交换：第一串左段对第二串右段，第一串右段对第二串左段。

两个子状态长度都严格小于父状态。字符频次不同只用于安全否定，频次相同仍继续枚举切分。直接相等检查
提前提交已经确定的真状态。十语言缓存都区分未知、真和假。

状态充分性与失败缓存
~~~~~~~~~~~~~~~~~~~~

缓存键必须包含两个起点和区间长度。只记录起点会把不同长度的区间混为同一子问题。合法 ``false`` 也
必须写入缓存；若只缓存成功状态，大量无法匹配但字符频次相同的区间仍会被不同上层切分反复展开。

前缀频次把每个区间的多重集检查降为固定 26 项扫描。直接相等比较最坏扫描当前区间，切分枚举也最多
扫描 ``O(n)`` 个位置，因此 ``O(n^3)`` 状态乘每状态 ``O(n)`` 工作仍为 ``O(n^4)``。

前向规则
~~~~~~~~

* 记忆化键覆盖决定状态语义的全部坐标和模式；
* 未计算、可行和不可行使用不同缓存值；
* 必要条件剪枝只能提前否定，不能被误写为充分判定；
* 交换转移的区间起点按当前长度和切分位置重新推导。

0088. Merge Sorted Array
------------------------

正向样本
~~~~~~~~

``first``、``second`` 和 ``write`` 分别指向两个未合并有序前缀的末端以及当前最右空位。循环中始终有：

.. code-block:: text

   write = first + second + 1

只要 ``second >= 0``，就有 ``write > first``。因此向 ``nums1[write]`` 写入不会覆盖 ``nums1`` 尚未
读取的有效前缀。两个前缀的最大值只能位于各自末端，每轮把较大值写入最右空位即可永久确定该位置。

``nums2`` 耗尽后，``nums1`` 的剩余前缀已经处于正确位置；``nums1`` 先耗尽时，循环继续复制
``nums2`` 的剩余前缀。十语言在 ``m = 0``、``n = 0`` 和相等值边界上的控制流正确。

事实更正：Julia 与 R 的修改可见性
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

历史正文把 Julia 与 R 一并解释为“调用边界可能具有复制语义，因此返回修改后的向量”。两者不能合并：

* Julia 函数参数采用 pass-by-sharing。``Vector`` 是可变对象，``nums1[write] = value`` 对调用者传入的
  同一数组可见；函数名 ``merge_sorted!`` 也符合 Julia 对修改型函数的命名惯例。返回 ``nums1`` 是接口
  便利，不是为了弥补复制语义。
* R 的形式参数在函数调用帧中表现为局部绑定。修改函数内 ``nums1`` 不能作为修改调用者变量的通用接口
  保证，因此适配器需要返回结果向量。

该更正写入 ``state/REVIEW_INDEX.toml``，历史题目正文按当前审查策略保持原样。

前向规则
~~~~~~~~

* 逆向原地写入必须给出读前缀、写位置和已完成后缀的关系式；
* “原地”分别说明底层对象是否对调用者可见地修改，以及是否返回同一对象；
* 可变对象共享、局部重绑定、独占消费和复制返回按语言分别记录。

0089. Gray Code
---------------

正向样本
~~~~~~~~

公式 ``gray(i) = i XOR (i >> 1)`` 对 ``i = 0..2^n-1`` 直接产生结果。正文分别证明：

* 结果不会产生第 ``n`` 位之外的比特；
* 连续输入的 Gray 编码异或为一个二的幂，因此只差一位；
* Gray 映射可逆，因此没有重复，并在等大有限域上完整覆盖；
* ``gray(2^n-1) = 2^(n-1)``，与起点 ``0`` 只差最高位。

输出本身包含 ``2^n`` 个整数，时间与返回空间下界都由输出规模决定。``n <= 16`` 支撑 C、Java、C#、
TypeScript 和其他固定宽位运算路径。

事实更正：``n = 0`` 的退化约定
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

官方题目域是 ``1 <= n <= 16``。历史正文主动扩展 ``n = 0`` 并返回 ``[0]``。公式实现确实会生成该
单元素结果，但若按字面继续检查“最后一个元素与第一个元素只差一位”，二者是同一个 ``0``，异或值为
``0``，并不是二的幂。

因此支持 ``n = 0`` 时必须明确采用零维 Gray 序列的退化约定，例如只要求唯一覆盖空比特向量，并对
单元素序列免除首尾不同元素检查。不能在未声明约定时声称完整满足原循环条件。

前向规则
~~~~~~~~

* 闭式构造分别证明范围、相邻关系、可逆性、完整覆盖和首尾闭合；
* 主动扩展官方输入域时，逐项说明原契约在退化边界上的解释；
* 一位差验证同时检查异或值非零以及 ``x & (x-1) == 0``。

0090. Subsets II
----------------

正向样本
~~~~~~~~

排序后相同值连续。递归层 ``dfs(start)`` 枚举下一下标，并只在
``index > start && nums[index] == nums[index-1]`` 时跳过候选。这条条件只删除同层第二个及后续同值
兄弟；选择第一个副本进入下一层后，后续相同副本仍然可选，因此 ``[v,v]`` 等结果不会丢失。

每个目标多重集都可以选择当前层最靠左的可用副本，形成唯一规范下标序列。该表示证明完整性和唯一性。
十语言都在提交结果时保存独立快照，后续路径撤销不会改写历史答案。

输出载荷与语言资源
~~~~~~~~~~~~~~~~~~

设唯一结果行数为 ``S``，全部返回元素总量为 ``P``。排序成本为 ``O(n log n)``，结果行元数据和元素
复制分别需要 ``Theta(S)`` 与 ``Theta(P)``。路径和递归栈为 ``O(n)`` 工作空间。

C 预留至多 ``2^n`` 个行槽位，并在任一行分配失败时释放全部已完成行、列长度数组和路径。R 使用环境
保存行列表，避免每次向结果列表尾部追加时重建整张列表；递归参数 ``c(path, value)`` 仍属于路径复制
成本。各语言的输入排序副作用已经在正文中分别声明。

前向规则
~~~~~~~~

* 重复值去重条件绑定当前递归层，并证明规范代表覆盖被跳过兄弟；
* 保存结果时创建独立快照或证明对象后续只重绑定、不再修改；
* 枚举复杂度区分结果行数、元素载荷、路径工作空间和预处理；
* 排序修改输入、消费输入和局部排序副本按语言接口分别说明。

跨题归纳
--------

本批提升以下稳定模式：

* 稳定链表变换需要值序列与节点身份双重证书；
* 旧拓扑必须通过断边或尾部终止证明与结果拓扑隔离；
* 记忆化键覆盖完整状态，失败结果同样缓存；
* 必要条件剪枝不能替代完整转移；
* 逆向原地写入使用读写前沿关系证明覆盖安全；
* 参数修改可见性按目标语言分别核对；
* 闭式构造同时证明局部相邻性、全局唯一覆盖和循环闭合；
* 官方输入域外扩展需要显式退化契约；
* 重复值枚举使用同层规范代表，并计入输出行元数据与元素载荷。

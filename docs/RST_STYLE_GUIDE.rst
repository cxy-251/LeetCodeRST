RST 写作规范
=============

适用范围
--------

本规范适用于仓库中的题目正文和项目说明。目标是让 RST 源文件本身清晰可读，不依赖 Sphinx 或其他构建工具。

文件与标题
----------

* 一道题对应一个 RST 文件；
* 文件名格式为 ``0001-two-sum.rst``；
* 题目文件按每 100 题一个目录存放；
* 顶级标题使用等号，下一级使用短横线，再下一级使用波浪线；
* 标题装饰线长度应覆盖标题文本，不使用混乱的层级符号。

推荐标题层级：

.. code-block:: rst

   0001. Two Sum
   =============

   问题抽象
   --------

   主解法：哈希表
   --------------

   Python
   ~~~~~~

段落与列表
----------

* 普通段落之间保留一个空行；
* 无序列表使用 ``*``；
* 有序步骤使用 ``#.``，避免手工维护序号；
* 只在确实存在并列关系时使用列表；
* 不用大量短句列表代替完整解释。

代码块
------

代码使用 ``.. code-block::``，并指定语言：

.. code-block:: rst

   .. code-block:: python

      for value in values:
          print(value)

指令后的正文必须缩进三个空格。代码本身再保持语言需要的缩进。

语法解释放在代码块中
~~~~~~~~~~~~~~~~~~~~

语言语法、标准库 API、类型语义和惯用写法的解释必须靠近对应代码，优先写在代码块内。正文外主要解释算法、状态、复杂度和正确性，不重复堆砌语法说明。

.. code-block:: python

   seen: dict[int, int] = {}  # 键保存数值，值保存下标

   for index, value in enumerate(nums):
       complement = target - value
       if complement in seen:  # ``in`` 查询字典中的键
           return [seen[complement], index]

短解释使用行尾注释。解释超过一个短语、涉及多项语义或会造成超长行时，放到目标代码上一行：

.. code-block:: rust

   // entry API 只进行一次哈希查找，并返回该键对应的占用状态。
   let count = frequencies.entry(value).or_insert(0);
   *count += 1;

注释预算
~~~~~~~~

* 首次出现的重要语法可以完整解释；
* 已强化过的知识只保留一句提醒；
* 熟悉内容不再重复解释；
* 算法关键状态、不变量和容易误写的位置可以持续注释；
* 禁止逐行翻译代码；
* 注释应回答“为什么这样写”“状态发生了什么变化”“哪里容易错”。

代码行宽
~~~~~~~~

* 代码和注释优先控制在 88 个显示列以内；
* 100 个显示列是硬上限；
* 行尾注释造成超长时，改成上一行注释；
* 函数参数、长条件、泛型类型和构造表达式按语言惯用方式换行；
* 不使用大量空格强行对齐注释；
* 中文注释按视觉宽度判断，不能只按字符数判断。

示例：

.. code-block:: cpp

   std::vector<int> twoSum(
       const std::vector<int>& nums,
       int target
   ) {
       std::unordered_map<int, int> seen;

       for (int index = 0; index < nums.size(); ++index) {
           const int need = target - nums[index];
           const auto found = seen.find(need);  // 返回迭代器

           if (found != seen.end()) {
               return {found->second, index};
           }

           seen[nums[index]] = index;
       }

       return {};
   }

行内代码
--------

标识符、表达式、复杂度和文件路径使用双反引号：

* ``unordered_map``
* ``left <= right``
* ``O(n)``
* ``state/PROGRESS.toml``

外部链接
--------

使用标准 RST 链接：

.. code-block:: rst

   `LeetCode 1 <https://leetcode.com/problems/two-sum/>`_

仓库内部关联使用普通相对链接，不使用依赖 Sphinx 的 ``:doc:`` 角色：

.. code-block:: rst

   `0001. Two Sum <../0001-0100/0001-two-sum.rst>`_

说明与警告
----------

只有确实需要突出边界时才使用指令：

.. code-block:: rst

   .. note::

      这里补充不会打断主线的信息。

   .. warning::

      这里说明会导致错误的关键边界。

不要把普通段落全部包装成 ``note`` 或 ``warning``。

表格
----

简单对比优先使用 ``.. list-table::``，复杂内容优先改写成列表或段落。不要为了视觉效果制造难维护的网格表格。

.. code-block:: rst

   .. list-table::
      :header-rows: 1

      * - 方法
        - 时间复杂度
        - 空间复杂度
      * - 哈希表
        - ``O(n)``
        - ``O(n)``

Mermaid 图
----------

RST 中使用 ``.. mermaid::`` 表达指针、结构和状态变化。Mermaid 是教学工具，不是装饰。

适合使用的情况：

* 链表指针改向；
* 树的层级、遍历和递归关系；
* 图搜索路径；
* 动态规划状态转移；
* 回溯选择树；
* 状态机和多阶段流程。

示例：

.. code-block:: rst

   .. mermaid::

      flowchart LR
          A["prev"] --> B["current"]
          B --> C["next"]

图的规则：

* 一张图只解释一个核心问题；
* 节点数量保持必要最小；
* 标签简短，变量名与代码一致；
* 指针改变前后应拆成两张图或明确分组；
* 图后补一段文字，指出读者应观察的状态或边；
* 简单线性流程不强行画图；
* Mermaid 源码本身需要可读，即使当前查看器不渲染也能理解。

数学表达
--------

简单表达式使用行内代码。只有推导确实需要数学排版时才使用 ``.. math::``。算法题正文优先让读者理解状态与推理，避免无必要的公式化。

多解法排版
----------

主解法使用完整章节，并提供 10 种核心语言实现。对照解法只有在算法、复杂度或状态表示存在实质差异时保留。

推荐结构：

.. code-block:: rst

   解法选择
   --------

   主解法：哈希表
   --------------

   工程写法：标准库排序
   --------------------

   对照解法：暴力枚举
   --------------------

对照解法通常只提供算法说明、伪代码或少量代表语言。不得为每个低价值变体复制 10 份代码。

基础类型说明
------------

``ListNode``、``TreeNode``、``Node`` 等平台提供类型不在每道题重复声明。首次出现时在代码块中用短注释标明来源，并用 Mermaid 解释结构。

.. code-block:: python

   # ListNode 由平台提供，next 保存下一个节点引用。
   def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
       ...

Julia 和 R 的仓库级节点约定首次出现时完整给出，后续直接复用。题目专属的 ``TrieNode``、并查集或状态结构仍在当前题目中定义。

单题内容取舍
------------

题目模板提供可选结构，不是强制目录：

* 简单题删除没有内容的“证明”“第二解法”等章节；
* 复杂题补充状态定义、不变量、证明、反例、状态表或 Mermaid；
* 只保留有教学差异的多种解法；
* 主解法完整覆盖核心语言，对照解法按价值选取语言；
* 只解释当前读者真正需要的语言知识；
* 每题保留复杂度、易错边界和最小自检。

提交前检查
----------

#. 题号、标题、文件名和原题链接一致。
#. 题目重述为原创表达。
#. 标题层级连续，指令缩进正确。
#. 所有代码块都标明语言。
#. 代码行优先不超过 88 列，任何行不超过 100 列。
#. 语法解释位于对应代码块内，注释密度符合知识账本。
#. 主解法和对照解法的取舍有明确教学理由。
#. 标准库写法没有掩盖必须学习的算法过程。
#. 基础类型没有被无意义地重复定义。
#. Mermaid 只用于必要结构，并且源码可读。
#. 多语言代码实现相同算法语义。
#. 复杂度与代码一致。
#. 内部相对链接指向真实文件。
#. ``state/PROGRESS.toml`` 与 ``state/CONCEPT_LEDGER.toml`` 已同步更新。

0001–0050 逐题审查提炼记录
========================

用途
----

本文件只记录从题目 RST 正文中提炼出的后续优化方法。它不是旧题修复清单，也不触发
``0001`` 至 ``0050`` 的回改。

每项规则必须能够追溯到具体题目正文。PR 描述、提交信息和自动任务报告不作为内容证据。

0001. Two Sum
~~~~~~~~~~~~~

观察：

* 不变量和正确性依据能够解释“先查询、后插入”为什么避免重复使用同一元素；
* 哈希复杂度主要写成期望 ``O(n)``，C 版本只说明极端碰撞会退化，没有统一给出最坏情况；
* 多个语言代码块依赖标准容器，但没有统一说明导入由平台预置还是需要读者补充。

规则候选：

* 哈希题同时写明期望复杂度与最坏复杂度；
* 每个代码块包含必要导入，或在语言标题下明确声明平台预置导入。

0002. Add Two Numbers
~~~~~~~~~~~~~~~~~~~~~

观察：

* 结果空间与辅助空间已经分开说明，是后续链表构造题的正向样本；
* C 版本在节点分配失败时直接返回 ``dummy.next``，可能把不完整结果伪装成正常答案，
  且没有释放此前创建的节点；
* Rust 版本通过 ``take`` 消费输入节点所有权，正文没有单独强调输入会被消费。

规则候选：

* C 的失败路径必须选择一种明确契约：完整清理后返回失败，或者明确依赖平台分配成功；
  禁止返回看似合法的部分结果；
* Rust、C++、Go 等实现若消费、移动或原地修改输入，必须在正文或代码注释中说明。

0003. Longest Substring Without Repeating Characters
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 正文知道不同语言存在字节、UTF-16 代码单元和 Unicode 字符差异；
* 字符单位说明使用“常见测试字符”作为依据，没有把代码假设绑定到题目的精确字符约束；
* Go 版本使用 ``[]byte(s)``，会创建输入副本；R 版本先 ``strsplit``，也会创建字符向量；
  总体复杂度只写 ``O(k)`` 空间，没有列出这些语言的 ``O(n)`` 转换成本；
* C++、Java 等代码依赖标准库类型，但导入边界仍不统一。

规则候选：

* 每道字符串题必须明确题目字符域，并据此选择字节、代码单元、码点或字形簇；
* 十种语言只有在题目约束保证等价时，才能使用不同字符单位；
* ``[]byte(s)``、``collect(s)``、``strsplit``、切片和重新编码产生的复制必须计入空间与时间；
* 若语言复杂度不同，复杂度章节必须增加“语言差异”小项，不能用一条结论覆盖十种实现。

0004. Median of Two Sorted Arrays
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 正文充分解释了合法分割如何得到中位数；
* 正确性依据主要证明“找到合法分割后答案正确”，对二分方向为什么能安全排除一半候选、
  合法分割为什么一定能被搜索到，说明仍不够完整；
* C 和 C++ 在不可能到达的结尾返回 ``0.0``，这个值本身可能是合法中位数，无法区分失败；
* Go 版本使用预声明 ``max`` / ``min``，依赖较新的 Go 版本，但正文没有声明版本前提。

规则候选：

* 二分题证明至少覆盖搜索区间、单调方向、排除安全性、存在性和终止性；
* 不可达路径不得返回普通合法值，使用断言、异常、明确错误或平台保证说明；
* 使用版本相关 API 时声明最低版本，或提供本地兼容辅助函数。

0005. Longest Palindromic Substring
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 中心扩展的覆盖性证明完整，能解释奇偶两类中心；
* 字符单位仍依赖“题目常见字符范围”，没有直接列出精确字符约束；
* Julia 使用 ``collect(s)``，R 使用 ``strsplit``，两者都有 ``O(n)`` 输入规范化空间；
  总体复杂度只写辅助空间 ``O(1)``，没有说明语言差异；
* 多种语言返回子串时发生复制，正文只统一写“不计算返回字符串”，缺少每种语言的实际复制说明。

规则候选：

* 字符串算法的复杂度必须区分算法核心空间、输入规范化空间和返回子串复制；
* ``collect``、``strsplit``、切片、``substring``、``to_string`` 等操作需要按目标语言真实语义计费；
* 空字符串、单字符和最小合法长度是否需要处理，必须由精确约束决定，不能在十种语言中各自猜测。

首批提升为前向规则
------------------

以下模式已经在多题中重复出现，或属于单次出现即高风险的问题，从 ``0051`` 起强制执行。

精确约束先于实现
~~~~~~~~~~~~~~~~

* 题目重述必须列出会影响代码的数值范围、长度下界、字符集合和返回顺序；
* 字符串题先定义算法字符单位，再选择语言 API；
* 不能用“常见测试”“通常是 ASCII”等模糊表述代替题目约束。

复杂度按真实语言实现计算
~~~~~~~~~~~~~~~~~~~~~~~~

* 统一算法复杂度之外，列出会改变渐进空间或时间的语言差异；
* 必查 ``[]byte(s)``、``collect(s)``、``strsplit``、切片、字符串拼接和结果复制；
* 区分算法额外空间、输入规范化、递归栈和返回结果空间。

失败路径不能伪装成答案
~~~~~~~~~~~~~~~~~~~~~~

* C 分配失败不得返回部分链表、部分数组或部分组合结果；
* 不可达分支不得返回 ``0``、空数组或 ``0.0`` 等可能合法的答案；
* 若依赖平台保证，必须明确写出该前提，不编造半可靠错误处理。

证明覆盖算法真正的决策
~~~~~~~~~~~~~~~~~~~~~~

* 二分查找不仅证明成功条件，还要证明移动方向和候选排除；
* 哈希题说明期望与最坏情况；
* 回溯、贪心、动态规划和滑动窗口分别证明其特有决策，不只描述循环。

代码环境与版本前提明确
~~~~~~~~~~~~~~~~~~~~~~

* 必要导入、辅助函数和平台类型必须明确；
* 版本相关标准库 API 声明最低版本，或使用本地兼容写法；
* 输入被消费、移动、排序或原地修改时，正文必须说明。

0006. Zigzag Conversion
~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 周期长度、竖列位置、斜线位置以及首尾行去重的推导完整，可作为索引映射题正向样本；
* Rust 按字节重排并调用 ``String::from_utf8``，正确性依赖输入字符均为单字节 ASCII；正文只说明
  “题目字符范围允许”，没有在题目重述中列出精确字符域；
* Julia 的 ``collect`` 和 R 的 ``strsplit`` 都分配 ``O(n)`` 输入表示，统一的 ``O(1)`` 辅助空间
  不能覆盖这两个实现；
* C++ 使用 ``int`` 下标与 ``size_t`` 长度比较，C++ 和 C# 使用的标准库类型也缺少直接导入说明。

前向规则：

* 依赖单字节字符的重排、切片或索引必须在题目重述中写出精确 ASCII 约束；
* 容器长度和循环下标使用一致类型，避免有符号与无符号比较及差值下溢；
* 标准库类型和函数必须直接导入，不依赖传递性头文件或隐含命名空间。

0007. Reverse Integer
~~~~~~~~~~~~~~~~~~~~~

观察：

* 正负边界、截断除法和压入前判溢出的推导完整，十语言差异也有明确解释；
* 同一溢出推导在题目重述、问题抽象、边界推导、正确性、易错点和自检中多次展开，
  信息密度被重复内容稀释；
* Julia 使用 ``Int(-2)^31`` 构造边界，幂运算发生在宿主 ``Int`` 中，随后才得到结果，
  在窄宿主整数上不具可移植性。

前向规则：

* 一个核心推导只保留一个完整主位置；易错点和自检只引用结论并提出不同问题；
* 边界常量和危险中间值必须先扩宽操作数再运算，例如 ``Int64(2)^31``，不能写成
  ``Int64(2^31)``。

0008. String to Integer (atoi)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 空格、符号和数字三个阶段的顺序、停止条件和钳制边界解释清楚，是确定性扫描题的正向样本；
* R 先把整个字符串 ``strsplit`` 为字符向量，实际增加 ``O(n)`` 空间，正文仍统一写 ``O(1)``；
* Julia 的 ``Int64(2^31)`` 同样在转换前使用宿主 ``Int`` 完成幂运算；
* 0007 已完整讲过压入前判溢出，本题再次大段重复同一背景，复现知识没有充分执行解释衰减。

前向规则：

* 复现知识只完整讲新增差异；共享推导通过明确引用复用，避免每题重新铺陈；
* 语言转换产生的输入副本继续单列，不能被“核心算法 O(1)”掩盖；
* 类型扩宽必须发生在算术之前。

0009. Palindrome Number
~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 半反转的停止条件、奇数位中心消除和结构性溢出规避证明完整；
* 复杂度先定义数字位数 ``d``，随后又写“等价于 ``O(log x)``”。当 ``x = 0`` 时
  ``log x`` 无定义，数学记号的定义域不完整。

前向规则：

* 整数逐位算法优先使用位数 ``d``；需要对数表达时写 ``O(log(|x| + 1))``，或者明确限定
  ``x > 0``。

0010. Regular Expression Matching
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

观察：

* 后缀状态、星号零次/多次分支和结构归纳证明完整，是记忆化搜索题的正向样本；
* C 的记忆表分配失败直接返回 ``false``，资源失败与合法的不匹配结果无法区分；
* C++ 调用 ``std::move`` 却没有直接包含 ``<utility>``，依赖传递性头文件；
* R 以矩阵保存记忆表，并通过 ``<<-`` 更新父作用域绑定。``<<-`` 只说明绑定查找位置，
  不能证明矩阵单元更新为常数时间原地写入；写时复制可能改变真实实现成本；
* 正文给出递归栈 ``O(m+n)``，但没有把最坏深度与题目长度约束和 Python、R 等语言栈限制对应。

前向规则：

* 资源分配失败不得静默变成合法布尔答案；
* C++ 每个标准库符号使用其直接定义头文件，例如 ``std::move`` 对应 ``<utility>``；
* R 的可变记忆状态优先放入 ``environment``；使用矩阵或列表加 ``<<-`` 时必须说明并验证复制成本；
* 递归解法必须用题目最大规模证明栈深安全，无法保证时改用自底向上 DP 或显式栈。

第二批提升为前向规则
--------------------

推导只完整出现一次
~~~~~~~~~~~~~~~~~~

* 一个核心公式、边界推导或状态证明只有一个主讲位置；
* 后续“易错点”“强化知识”“答案要点”承担不同教学功能，不复制整段推导；
* 相邻题复现已有知识时只解释新状态、新边界或新语言差异。

危险算术先扩宽操作数
~~~~~~~~~~~~~~~~~~~~

* 转换结果类型不能修复已经在窄类型中发生的溢出；
* 幂、移位、取负、乘法和加法在运算前把操作数提升到目标宽类型；
* Julia、Java、C#、C 和 C++ 都要检查“先运算还是先转换”的顺序。

数值复杂度写明定义域
~~~~~~~~~~~~~~~~~~~~

* 整数逐位算法使用十进制位数 ``d`` 最清楚；
* 写对数时使用 ``log(|x| + 1)`` 或声明输入严格为正；
* 不把 ``x = 0``、负数或固定宽度边界留在符号定义之外。

R 可变状态不能假定原地
~~~~~~~~~~~~~~~~~~~~~~

* ``<<-`` 表示向父环境寻找并更新绑定，不表示底层矩阵或列表一定原地修改；
* 记忆化、回溯共享状态和频繁单元更新优先使用 ``environment`` 或其他明确引用语义结构；
* 若使用向量、矩阵或列表，复杂度需要计入可能的写时复制，并通过运行证据确认关键假设。

递归深度由约束证明
~~~~~~~~~~~~~~~~~~

* 复杂度章节同时写递归深度和题目最大长度；
* 检查 Python、R、JavaScript、JVM、CLR 等目标运行时的实际栈限制；
* 深度无法安全覆盖约束时，主解法改为迭代、显式栈或自底向上动态规划。

直接导入与索引类型
~~~~~~~~~~~~~~~~~~

* 标准库符号使用其直接定义头文件、包或命名空间，禁止依赖传递性导入；
* C++ 容器长度与循环下标选择一致类型，差值前先证明不会下溢；
* 平台预置导入必须显式声明，不能让代码块看似可独立编译却缺少依赖。

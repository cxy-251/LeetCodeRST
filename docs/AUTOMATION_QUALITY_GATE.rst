对话批次质量门
==============

文件定位
--------

本文件保留历史路径 ``AUTOMATION_QUALITY_GATE.rst``，实际用于当前对话驱动批次的验收。完整技术规则
位于 ``docs/FORWARD_RULES_0051_0100.rst``，本文件只说明如何使用这些规则完成一轮工作。

适用阶段
--------

当前 ``state/PROGRESS.toml`` 的 ``phase = "lessons_started"``。新题从 ``next_problem`` 继续生成。

历史审查资料用于追溯，不作为新题逐项读取清单。需要定位规则来源时读取
``docs/REVIEW_CATALOG_0001_0050.rst`` 和对应批次证据。

开始前
------

每轮读取：

#. ``AGENTS.md``；
#. ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``docs/FORWARD_RULES_0051_0100.rst``；
#. ``docs/PROBLEM_TEMPLATE.rst``；
#. ``docs/SOLUTION_AND_TYPES_POLICY.rst``；
#. ``docs/RST_STYLE_GUIDE.rst``；
#. ``state/CONCEPT_LEDGER.toml``；
#. 当前题及最近相关题目。

批次范围
--------

从 ``next_problem`` 开始按题号连续处理：

* Easy = 1；
* Medium = 2；
* Hard = 4；
* 一轮目标总分 4 至 6；
* 加入下一题超过 6 时结束；
* 同一轮不安排两道 Hard；
* 连续三道 Easy 可以按 3 分结束。

质量优先于题量。只有连续且完整通过质量门的题目进入本轮提交。

单题准备
--------

每道题完成：

#. 原创题目重述和影响实现的精确约束；
#. 至少一个正常示例，以及真正有区分度的边界示例；
#. 问题抽象、解法选择和主算法状态；
#. 正确性证明；
#. 时间、空间、输出和语言特有成本；
#. C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R 十语言实现；
#. 关键边界、易错点、新增与强化知识；
#. 验证计划、自检和答案要点。

执行规则
--------

单题逐项应用 ``docs/FORWARD_RULES_0051_0100.rst``。重点确认：

* 题目契约支撑索引、字符、数值、所有权和特殊输入；
* 证明覆盖算法真正的决策、完整性、无重复和终止；
* 十语言实现与正文是同一问题语义；
* 数值、容量、分配、失败和生命周期路径闭合；
* 复杂度包含具体容器、规范化、搜索节点、输出载荷、快照和峰值空间；
* 标准库导入、版本、编译器扩展和平台接口明确；
* 正文中的优化、剪枝和错误处理已真实进入主代码。

验证证据
--------

报告明确区分：

``运行验证``
   执行了正常、边界、随机或穷举用例。

``编译验证``
   通过编译器、严格警告或类型检查；不能据此宣称算法运行正确。

``静态验证``
   检查接口、索引、作用域、所有权、复杂度或逻辑，但未执行目标代码。

``基准对拍``
   与独立、明显正确的基准比较，基准不复用被测算法核心逻辑。

一种语言的运行结果不能外推为其余语言全部运行通过。

批次同步
--------

通过质量门后，同步：

* 新题 RST；
* ``problems/0001-0100/README.rst``；
* 根 ``README.rst``；
* ``state/PROGRESS.toml``；
* ``state/CONCEPT_LEDGER.toml``；
* 确实需要更新的公共规则。

提交与复查
----------

当前工作由用户在对话中触发。一次性准备本轮全部文件，形成一个原子提交直接写入 ``main``，随后
重新读取目标文件，确认：

#. 完成范围连续；
#. ``next_problem`` 正确推进；
#. README、题目索引和知识账本同步；
#. 提交差异不包含半成品或无关文件；
#. 对话报告与 ``main`` 实际状态一致。

分支和 PR 只在用户明确选择代码评审、多人协作或隔离实验时使用。

单题完成判定
------------

单题同时满足以下条件才计入完成：

#. 教学主线和主代码完整；
#. 十语言接口与算法语义一致；
#. 精确约束支撑全部代码假设；
#. 正确性证明覆盖真实决策；
#. 复杂度覆盖语言差异和输出成本；
#. 资源、失败和所有权路径闭合；
#. 导入、版本和辅助接口完整；
#. 验证证据描述准确；
#. RST、索引、进度和知识账本同步。

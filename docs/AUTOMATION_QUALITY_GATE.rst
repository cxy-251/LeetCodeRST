对话批次质量门
==============

文件定位
--------

本文件用于题解生成批次的最低验收。完整技术规则位于
``docs/FORWARD_RULES_0101_0150.rst``，直接主分支规则位于
``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``。

适用阶段
--------

``0001`` 至 ``0135`` 已完成，下一批从 ``0136`` 开始。历史审查资料默认不读取。

开始前
------

每轮只读取一次并在当前对话复用：

#. ``AGENTS.md`` 与根 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections；
#. 当前阶段前向规则与本质量门；
#. 当前范围 README、知识账本和最近相关题目。

模板、专项策略和归档只在本题确实涉及对应问题时读取。禁止为了重复确认而重新扫描仓库。

批次范围
--------

从 ``next_problem`` 开始连续处理：Easy = 1、Medium = 2、Hard = 4；一轮目标 4 至 6 分，
加入下一题超过 6 时结束，同一轮不安排两道 Hard。

单题内容
--------

每题保持：原创重述、精确约束、算法状态、正确性证明、复杂度、十语言实现、关键边界和自检。
简单题保持紧凑，代码必须与正文方案一致。

默认验证
--------

普通题默认只执行：

#. 人工核对算法状态、转移和代码映射；
#. 官方示例；
#. 2 至 4 个有区分度的关键边界；
#. Python 主实现运行；
#. C++ 主实现编译，必要时运行相同样例；
#. 其余语言检查接口、索引、容器、所有权和明显语法问题。

随机对拍、穷举、sanitizer 和全部语言运行不是常规要求。只有以下情况才增加针对性验证：

* 算法存在复杂去重、状态压缩、图映射或高风险下标；
* 样例结果与推导不一致；
* 静态检查发现可疑分支；
* 用户明确要求生产级可靠性。

即使增加随机验证，也应控制规模并说明它解决的具体疑点，禁止用大量案例重复证明已经明确的实现。

验证证据
--------

``运行验证`` 表示目标代码实际执行；``编译验证`` 只证明编译通过；``静态验证`` 表示未执行的人工检查；
``基准对拍`` 必须使用独立基准。不得把一种语言的运行结果外推为十语言全部运行通过。

状态同步
--------

生成批次同步题目 RST、范围 README、根 README、``PROGRESS`` 和知识账本。
``REVIEW_INDEX`` 只有 active corrections 或审查动作变化时才修改，不再为每个普通生成批次重复改写。

产物与提交
----------

提交前确认没有 marker、草稿、日志、缓存、临时分支、PR 或组装工作流。基于最新 ``main`` 树创建
blob、tree 和单父 commit，以非强制 fast-forward 更新 ``main``。最终差异只包含正式题解和必要状态文件。

完成判定
--------

算法方案、代码实现、少量针对性验证、索引和状态一致即可计入完成。大规模随机测试不是完成条件。

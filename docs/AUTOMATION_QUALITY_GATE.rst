对话批次质量门
==============

文件定位
--------

本文件用于题解生成批次的最低验收。技术规则按题号选择：

* ``0150`` 使用 ``docs/FORWARD_RULES_0101_0150.rst``；
* ``0151`` 起全部题目使用 ``docs/FORWARD_RULES_0151_ONWARD.rst``。

直接主分支规则位于 ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``。

适用阶段
--------

``0001`` 至 ``0149`` 已完成，下一批从 ``0150`` 开始。``0151`` 起不再建立新的分段前向规则文件，
发现通用问题时直接维护长期规则。

开始前
------

每轮只读取一次并在当前对话复用：

#. ``AGENTS.md`` 与根 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections；
#. 当前题号对应的前向规则与本质量门；
#. 当前范围 README、知识账本和最近相关题目。

模板、专项策略和归档只在本题确实涉及对应问题时读取。禁止为了重复确认而重新扫描仓库。

批次范围
--------

从 ``next_problem`` 开始连续处理：Easy = 1、Medium = 2、Hard = 4；一轮目标 4 至 6 分，
加入下一题超过 6 时结束，同一轮不安排两道 Hard。发现难度登记错误时先修正批次范围和状态。

单题内容
--------

每题保持：原创重述、精确约束、算法状态、正确性证明、复杂度、十语言实现、关键边界和自检。
简单题保持紧凑，代码必须与正文方案一致。

默认验证
--------

普通题默认只执行：

#. 人工核对算法状态、转移和代码映射；
#. 官方示例；
#. 2 至 4 个有区分度的关键边界；
#. Python 主实现运行；
#. C++ 主实现严格编译，必要时运行相同样例；
#. C 在涉及分配、指针或宽度风险时严格编译并运行；
#. 其余语言检查接口、索引、容器、所有权和明显语法问题。

随机对拍、穷举、sanitizer 和全部语言运行不是常规要求。只有以下情况才增加针对性验证：

* 算法存在复杂去重、几何规范化、状态压缩、图映射或高风险下标；
* 数值宽度、位运算、哈希键、对象身份或所有权路径存在疑点；
* 样例结果与推导不一致；
* 静态检查发现可疑分支；
* 用户明确要求生产级可靠性。

即使增加随机验证，也应控制规模并说明它解决的具体疑点，禁止用大量案例重复证明已经明确的实现。

验证证据
--------

``运行验证`` 表示目标代码实际执行；``编译验证`` 只证明编译通过；``静态验证`` 表示未执行的人工检查；
``基准对拍`` 必须使用独立基准；``属性测试`` 必须检查独立性质。不得把一种语言的运行结果外推为十语言
全部运行通过。

状态同步
--------

生成批次同步题目 RST、范围 README、根 README、``PROGRESS`` 和知识账本。
``REVIEW_INDEX`` 只有 active corrections 或审查动作变化时才修改。

规则维护提交至少同步长期规则、``PROGRESS``、根 README、``AGENTS.md`` 和所有受影响入口，禁止留下指向
废弃分段规则的下一动作。

产物与提交
----------

提交前确认没有 marker、草稿、日志、缓存、临时分支、PR 或组装工作流。基于最新 ``main`` 树创建
blob、tree 和单父 commit，以非强制 fast-forward 更新 ``main``。最终差异只包含正式题解、长期规则和
必要状态文件。

完成判定
--------

算法方案、代码实现、少量针对性验证、索引和状态一致即可计入完成。大规模随机测试不是完成条件。
通用缺陷只有在写入 ``docs/FORWARD_RULES_0151_ONWARD.rst`` 后才算完成规则维护。

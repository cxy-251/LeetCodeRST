对话驱动质量门
==============

文件职责
--------

本文件定义普通生成、针对性抽查和历史题返工写入 ``main`` 前必须通过的最低检查。
单文件结构正确、代码数量足够或构建成功，都不能代替教学内容质量验收。

权威入口
--------

检查优先级为：

#. ``state/PROGRESS.toml``；
#. ``state/BATCH_CONTRACT.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections；
#. ``docs/TUTORIAL_QUALITY_BASELINE.rst``；
#. 当前前向规则与本文件；
#. 当前范围 README、知识账本和合同列出的事实来源；
#. ``state/DRIFT_LOG.toml``、历史归档和提交。

最近完成题目只提供事实连续性，不具有格式、解释深度、证明密度或静态审查标准的示范权。

一、开始前检查
------------

#. 读取最新 ``main``、``AGENTS.md``、根 README、``PROGRESS`` 和当前 ``BATCH_CONTRACT``。
#. 确认合同阶段、范围与 ``PROGRESS`` 完全一致。
#. 读取 active corrections、冻结基线、合同选择的黄金题和当前前向规则。
#. 只读取合同列出的事实来源，不以“最近三题”替代黄金样本。
#. 检查 ``DRIFT_LOG``，列出当前批次命中的事故和对应回归检查。
#. ``needs_revision`` 非空且新题暂停时，只处理返工范围，不推进 ``next_problem``。
#. 只直接更新 ``main``，不创建分支、PR 或临时上传工作流。

二、批次可承载性
--------------

批次开始前同时评估：

* 算法分数；
* 证明风险；
* 语言语义风险；
* 平台类型与资源风险；
* 输出体积风险。

两个或以上风险维度为 ``high`` 时，允许缩小为连续前缀。出现以下迹象时必须缩批：

* 后一题开始删除示例、证明义务、语言说明或答案要点；
* 十语言实现只剩机械翻译；
* 为控制文件长度产生 ``.inc``、``include`` 或代码分片；
* 静态审查被笼统写成“已检查”，没有覆盖范围和剩余风险；
* 当前题无法在本轮完整对照黄金样本。

不得为了达到 4–6 分而降低单题质量。

三、黄金样本隔离
--------------

每题至少对照合同选择的两个黄金题：

#. 一个匹配证明形状或难度；
#. 一个匹配语言、数值、对象或资源风险。

对照目标是信息覆盖、状态映射、证明粒度、复杂度诚实度和语言审查深度，
不是复制标题数量、段落长度或题目内容。

以下行为直接判失败：

* 把最近完成题目作为唯一格式样本；
* 因最近题更短而删除冻结基线中的核心信息；
* 自动把本批完成题加入黄金样本；
* 用黄金题中的历史技术事实覆盖 active correction。

四、教学内容质量
--------------

每道普通算法题必须根据实际需要覆盖：

#. **精确契约**：输入输出、值域、字符域、结构前提、顺序、副作用、平台类型和资源责任；
#. **自建示例**：至少一个正常例；存在典型错误路径时给出可区分反例；
#. **问题抽象**：从题面转化为真实算法模型，不直接跳到代码；
#. **解法选择**：比较真正有教学差异的方法，说明主解法取舍；
#. **状态与不变量**：状态名称、合法范围、更新时机和代码变量逐项对应；
#. **完整证明**：覆盖当前题需要的合法性、完整性、无重复、排除安全性、最优性和终止性；
#. **真实复杂度**：区分核心状态、栈/队列、输入物化、标准库、输出载荷、期望/最坏/摊还界；
#. **十语言实现**：固定顺序，保持同一问题语义；特化算法单独解释、证明和计复杂度；
#. **静态审查证据**：说明人工推演、逐语言语义核对、未运行未编译事实和剩余风险；
#. **边界与失败路径**：优先给出真实反例；
#. **学习链**：新增知识、强化知识、关联题目、自检与答案要点。

只有“算法、正确性、复杂度、十语言代码、几个问题”的摘要骨架不能通过。
简单题可以合并相邻章节，核心答案不能消失。

五、状态、证明与复杂度
------------------

#. 状态定义能够逐项映射到实际代码。
#. 循环、递归、搜索、回溯、贪心、滑动窗口、双指针和动态规划写出核心不变量。
#. 多阶段算法分别证明阶段产物及阶段接口。
#. 正确性不能只写“遍历全部所以正确”。
#. 贪心题必须说明局部选择为何安全；最优化题必须给出下界、交换或支配论证。
#. 不同语言采用不同算法时，不共用一段模糊证明。
#. 复杂度包含哈希条件、复制、物化、输出载荷、所有权和目标语言适配成本。

六、十语言与接口
--------------

固定顺序为 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R。

逐代码块检查：

#. 必要导入、辅助函数和平台签名；
#. 数值宽度、容量乘加和边界运算；
#. 字符单位、索引转换和位运算语义；
#. 输入修改、所有权、可变对象共享和结果快照；
#. 分配、扩容、失败清理和返回资源；
#. 标准库 API 与最低版本；
#. 主算法与正文状态、证明和复杂度一致。

``ListNode``、``TreeNode``、``Node`` 等平台类型不在每题重复定义。
C++ 默认兼容 C++17；使用更新 API 必须声明。Julia 与 R 复用仓库统一节点模型。

七、唯一单文件结构
----------------

#. 每道公开题只对应一个 ``<题号>-<slug>.rst``。
#. 正文、证明、静态审查记录和全部语言代码直接写入该文件。
#. 不得出现 ``.. include::``。
#. 不得存在同题号或 slug 的 ``.inc``、代码分片或正文分片。
#. Premium 题只登记状态，不生成猜测性 RST。

结构通过但教学内容未通过时，题目仍保留在 ``needs_revision``。

八、静态审查
------------

题解代码、接口或算法发生变化时统一执行：

#. 人工核对契约、状态、证明和代码映射；
#. 人工推演官方示例与 2–4 个有区分度的关键边界；
#. 逐语言静态检查平台接口、导入、索引、容器、位宽、所有权、字符单位和明显语法；
#. 高风险状态增加针对性推导、反例分析或目标语言官方语义资料核对；
#. 记录静态审查覆盖范围、未运行未编译事实和无法确认的剩余风险。

禁止运行或编译题解代码，禁止对拍、穷举、属性测试、sanitizer 和目标语言最小程序。允许执行 RST、TOML、
文件结构、Git 对象和状态一致性检查，因为这些检查不执行题解代码。历史运行证据不作为当前批次的完成要求，
也不得把静态审查写成测试、编译或运行通过。

九、漂移回归
----------

提交前逐项检查当前批次命中的 ``DRIFT_LOG``：

* 单题拆分事故：``include`` 和题目分片均为零；
* 摘要骨架事故：契约、例子、抽象、状态、证明、复杂度、语言差异和答案要点完整；
* 最近样本污染：最终结构由合同黄金题支撑，最近题只作为事实来源；
* 难度预算失真：高风险叠加时没有通过压缩单题维持原范围。

发现新通用漂移时，当前提交必须同时更新漂移记录、永久规则和回归检查。

十、状态与提交
------------

#. README、范围索引、``PROGRESS``、知识账本和合同同步。
#. 完成当前批次后，在同一提交中把 ``BATCH_CONTRACT`` 替换为下一批合同。
#. 缩批时只删除已完整通过题目的 ``needs_revision``，未完成题进入下一合同。
#. 不提交日志、缓存、marker、草稿、分片或一次性分析报告。
#. 写入前重新读取最新 ``main``；主分支变化时重新计算目标树。
#. 多文件变化使用 Git blob、tree、单父 commit 和 ref 构造一个原子提交。
#. 只执行非强制 fast-forward。
#. 提交后比较父提交与新提交，核对文件范围、状态、合同和下一步。
#. 对话报告必须说明实际黄金样本、静态审查范围、剩余风险、是否缩批和剩余题数。

完成判定
--------

题目只有在冻结基线对照、内容质量、十语言语义、静态审查证据、漂移回归、唯一自包含 RST、
索引、进度和下一合同全部一致，并成功非强制 fast-forward 写入 ``main`` 后才算完成。

对话批次质量门
==============

文件定位
--------

本文件用于当前对话驱动批次的验收。完整技术规则位于 ``docs/FORWARD_RULES_0101_0150.rst``，阶段产物
清理规则位于 ``docs/ARTIFACT_LIFECYCLE_POLICY.rst``。

适用阶段
--------

当前 ``state/PROGRESS.toml`` 的阶段为 ``generation_ready``，``0101`` 至 ``0107`` 已完成，下一批从
``0108`` 开始。历史审查资料已经归档，不属于新题生成时的默认读取清单。

开始前
------

每轮读取：

#. ``AGENTS.md``；
#. 根 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml``；
#. ``docs/FORWARD_RULES_0101_0150.rst``；
#. ``docs/PROBLEM_TEMPLATE.rst``；
#. ``docs/SOLUTION_AND_TYPES_POLICY.rst``；
#. ``docs/RST_STYLE_GUIDE.rst``；
#. ``docs/ARTIFACT_LIFECYCLE_POLICY.rst``；
#. ``state/CONCEPT_LEDGER.toml``；
#. 当前题及最近相关题目。

只有追溯历史规则或修复历史题时，才根据 ``archive/README.rst`` 和对应 manifest 读取归档。

批次范围
--------

从 ``next_problem`` 开始按题号连续处理：

* Easy = 1；
* Medium = 2；
* Hard = 4；
* 一轮目标总分 4 至 6；
* 加入下一题超过 6 时结束；
* 同一轮不安排两道 Hard；
* 连续三道 Easy 可以按 3 分结束。

用户明确指定连续范围时，以用户范围为准。质量优先于题量。

单题准备
--------

每道题完成：

#. 原创题目重述和影响实现的精确约束；
#. 至少一个正常示例和有区分度的边界示例；
#. 问题抽象、解法选择和主算法状态；
#. 正确性证明；
#. 时间、核心工作空间、适配器物化、返回载荷和峰值空间；
#. C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R 十语言实现；
#. 关键边界、易错点、新增与强化知识；
#. 验证计划、自检和答案要点。

单题正文、代码和验证按题号逐题闭合。禁止先为整批生成统一骨架，再用同一组模板句、验证计划或知识条目
批量填充。

执行规则
--------

单题逐项应用 ``docs/FORWARD_RULES_0101_0150.rst``。重点确认：

* 题目契约支撑索引、字符、数值、所有权和特殊输入；
* 证明覆盖真实决策、完整性、无重复和终止；
* 十语言实现与正文是同一问题语义；
* 数值、容量、分配、失败和生命周期路径闭合；
* 复杂度包含具体容器、规范化、输出载荷、快照和峰值空间；
* 标准库导入、版本、编译器扩展和平台接口明确；
* 正文中的优化、剪枝和错误处理真实进入主代码；
* 简单题保持紧凑，Medium 与 Hard 题提供与状态复杂度匹配的推导深度。

验证证据
--------

报告明确区分：

``运行验证``
   执行了正常、边界、随机或穷举用例。

``编译验证``
   通过编译器、严格警告或类型检查；不能据此声称算法运行正确。

``静态验证``
   检查接口、索引、作用域、所有权、复杂度或逻辑，但未执行目标代码。

``基准对拍``
   与独立、明显正确的基准比较，基准不复用被测算法核心逻辑。

一种语言的运行结果不能外推为其余语言全部运行通过。

产物清理门
----------

提交前必须检查：

#. 没有临时 marker、草稿计划、构建日志、缓存或未引用报告；
#. 普通题目生成没有创建可由题目正文和状态完全推导的一次性分析文件；
#. 审查批次文件只在当前审查轮次未归并时保留在活动目录；
#. 已消费且有证据价值的阶段文件已经移动到 ``archive`` 并登记 manifest；
#. 被移动路径在 ``AGENTS``、README、``PROGRESS``、``REVIEW_INDEX`` 和策略中同步更新；
#. 活动目录不存在指向已删除路径的引用。

批次同步
--------

通过质量门后同步：

* 新题 RST；
* 对应范围题目 README；
* 根 ``README.rst``；
* ``state/PROGRESS.toml``；
* ``state/CONCEPT_LEDGER.toml``；
* 确实需要更新的公共规则；
* 本轮涉及的 archive manifest。

提交与复查
----------

一次性准备本轮全部文件，形成一个原子提交进入 ``main``，随后重新读取目标文件，确认：

#. 完成范围连续；
#. ``next_problem`` 正确推进；
#. README、题目索引和知识账本同步；
#. 提交差异不包含半成品或无关文件；
#. 活动目录没有已消费中间产物；
#. 对话报告与 ``main`` 实际状态一致。

单题完成判定
------------

单题只有在教学主线、十语言接口、精确约束、证明、复杂度、资源路径、导入版本、验证证据、索引和状态全部
闭合时才计入完成。

自动化批次质量门
================

适用范围
--------

本规则专门约束定时任务和无人值守批次。自动任务可以在一轮中处理连续多题，但每道题都必须
独立达到完整教学质量，不能因难度预算、运行频率或批次题量压缩教学主线。无法完成完整题目时，
不得把半成品登记为已完成。

审查阶段和历史缺陷处理同时受 ``docs/REVIEW_AND_PREVENTION_POLICY.rst`` 约束。风格和结构问题
优先转化为公共规则；已经确认的算法、代码、复杂度或接口错误必须修复对应题目，不能仅更新模板。

基准文件
--------

每次开始前必须读取：

#. ``AGENTS.md``；
#. ``docs/PROJECT_VISION.rst``；
#. ``docs/LANGUAGE_SCOPE.rst``；
#. ``docs/SOLUTION_AND_TYPES_POLICY.rst``；
#. ``docs/CONTENT_LANGUAGE_POLICY.rst``；
#. ``docs/RST_STYLE_GUIDE.rst``；
#. ``docs/RELATED_PROBLEMS_POLICY.rst``；
#. ``docs/REVIEW_AND_PREVENTION_POLICY.rst``；
#. 本文件；
#. ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst``；
#. ``state/PROGRESS.toml`` 与 ``state/CONCEPT_LEDGER.toml``；
#. 最近至少 5 道已经进入 ``main`` 的完整题目。

0001 至 0007 是初始质量基准，最新已完成题目是当前直接基准。自动任务需要学习其教学密度、
论证方式、代码注释风格和多语言覆盖，不得只复用标题骨架。

开始前缺陷优先级
----------------

生成新题前必须先检查：

* ``state/PROGRESS.toml`` 的 ``needs_revision``；
* 开放的 ``fix:`` PR；
* 最近一次合并后的验证报告；
* 已经确认但尚未修复的正确性、编译、索引、作用域、所有权、内存或复杂度问题。

存在确定性缺陷时必须先修复，禁止继续生成新题。只有风格、解释密度或结构建议时，更新公共规则，
不得因此批量回改历史题目。

批次范围
--------

一轮从 ``next_problem`` 开始，按 ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst`` 的难度预算连续处理
1 至 3 道题。禁止跳过中间可访问题目后继续更大题号。

每道题完成后立即执行本质量门，再决定是否把下一题加入批次：

* 已完成题目必须先独立通过质量门；
* 批次尾部题目无法完成时，应删除该题的半成品并缩小批次；
* 已通过题目可以作为连续前缀提交，不必因尾部题失败而全部作废；
* Premium 或题意无法可靠确认时，只登记跳过或阻塞，不猜测题意。

必备教学主线
------------

每道普通算法题必须根据实际内容完整覆盖以下教学功能：

#. 标题与题目信息；
#. 原创题目重述，明确输入、输出和关键约束；
#. 至少一个自建正常示例，并在边界容易出错时增加边界示例；
#. 问题抽象，说明题目真正要求维护或计算的对象；
#. 解法选择，解释主解法与主要替代方法的复杂度和取舍；
#. 主解法的状态、变量含义、执行过程或核心不变量；
#. 独立的正确性依据，不能只把代码流程换一种说法；
#. 时间复杂度与空间复杂度，并说明复杂度中的变量含义；
#. 10 种核心语言的完整主解法；
#. 各语言真正需要提醒的接口、数值、索引、内存、所有权、作用域或字符语义；
#. 易错点与关键边界；
#. 本题新增或强化的知识；
#. 最小自检问题与答案要点；
#. 只有存在强关联时才写关联题目，通常 1 至 3 个，最多 5 个。

章节名称可以随题目调整，教学功能不得被静默删除。简单题可以减少重复背景，不能省略
问题抽象、核心不变量或状态、正确性、复杂度、关键边界、多语言实现和自检。

正确性与复杂度质量
------------------

正确性依据必须覆盖当前算法真正需要的证明目标：

* 状态或不变量为什么成立；
* 每次排除、移动、选择或剪枝为什么安全；
* 搜索是否完整，是否会重复，是否能够终止；
* 贪心局部选择为什么不会损失最优解；
* 讲解与十语言代码是否使用同一个算法。

复杂度必须：

* 定义 ``n``、``m``、``k``、``U`` 等变量；
* 区分最坏、平均和摊还复杂度；
* 区分算法额外空间、递归栈和返回结果空间；
* 在排列、组合、枚举和字符串构造题中计入输出数量与复制成本；
* 与实际代码中的排序、哈希、回退、重复扫描和标准库调用保持一致。

多语言质量
----------

每道题的主解法必须覆盖 C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R。
代码需要符合各语言接口习惯，并特别检查：

* C 的缓冲区、容量证明、返回结构、内存所有权、整数范围和失败路径；
* C++ 标准库调用、比较器、迭代器、无符号长度和整数转换；
* Python 的整数、切片、可变对象共享和递归深度语义；
* Java 与 C# 的固定宽度整数、溢出、装箱和集合接口；
* Rust 的所有权、借用生命周期、转换和 ``Option`` / ``Result`` 边界；
* Go 的切片底层数组共享、字符串字节与字符单位和数值转换；
* TypeScript / JavaScript 的 ``number`` 精度、32 位位运算转换和 ``undefined`` 判断；
* Julia 的一基索引、递减范围、原地 ``!`` 接口和数值类型；
* R 的一基索引、``<-`` / ``<<-`` 作用域、``environment`` 引用状态、值语义和空序列。

不得为了缩短篇幅去掉中文教学注释。已经进入 ``familiar`` 的普通语法可以衰减，当前
算法的状态变化、关键分支、溢出风险、索引换算和 API 陷阱仍需解释。

代码独立性检查
--------------

每种语言的主代码必须能在题目声明的接口环境中独立理解：

* 所有非平台辅助函数必须出现；
* 所需标准库导入或依赖必须明确；
* 平台类型省略时必须写明由平台提供；
* 返回值、输入是否修改、内存释放责任和结果顺序要求必须与正文一致；
* 不得留下伪代码变量、未定义容量、隐含全局状态或只在另一语言中存在的辅助逻辑。

验证证据
--------

验证报告必须区分：

``运行验证``
   已执行测试，并列出正常、边界、随机或对拍范围。

``编译验证``
   已通过编译器、严格警告或类型检查；不能据此宣称算法已经运行正确。

``静态验证``
   只检查接口、语法结构、索引、作用域、所有权或逻辑；缺少运行时必须如实说明。

``基准对拍``
   与独立基准实现比较；基准不能复用被测算法的核心逻辑。

禁止把静态检查写成“运行通过”，也禁止把某一种语言的运行结果外推为其余九种语言全部正确。

单题完成判定
------------

只有全部满足以下条件，某一道题才能计入本轮完成范围：

#. RST 教学主线完整；
#. 10 种语言均有完整主解法；
#. 代码与讲解采用同一算法；
#. 正确性和复杂度能够独立阅读；
#. 代码独立性和高风险语言边界已经检查；
#. 验证报告准确区分运行、编译、静态和对拍证据；
#. RST 标题、指令、缩进、链接和代码块无明显结构错误；
#. 题目相关知识账本条目已经准备；
#. 与最近题目对照后不存在明显的骨架化或教学密度骤降。

禁止用文件行数作为唯一质量指标，也禁止以“题目简单”为理由只留下定义、代码和一句
复杂度。发现质量不足时继续完善当前题，或从批次尾部移除该题；不得保留半成品后继续下一题。

批次完成判定
------------

只有全部满足以下条件，才能更新 ``completed_count`` 和 ``next_problem``：

#. 所有提交题目均逐题通过质量门；
#. 题号从原 ``next_problem`` 开始连续；
#. 题数为 1 至 3，难度预算符合固定分支策略；
#. 所有题目文件、范围索引、根 README、进度和知识账本同步；
#. ``next_problem`` 指向批次末题之后的第一个未处理题号；
#. PR 中不存在批次外题目、半成品或无关规则修改。

审查检查点
----------

当 ``phase = "review_checkpoint"`` 或 ``next_batch.status = "blocked_by_review_checkpoint"`` 时：

* 禁止生成新题和推进 ``next_problem``；
* 按 ``docs/REVIEW_AND_PREVENTION_POLICY.rst`` 审查当前范围；
* A 类发现只升级公共规则；
* B 类确定性缺陷创建独立 ``fix:`` PR；
* C 类证据不足项记录验证限制或加入 ``needs_revision``；
* 未经用户明确解除检查点，不得恢复内容批次。

自动 Git 流程
------------

自动任务必须遵守 ``docs/AUTOMATION_DIRECT_MAIN_POLICY.rst`` 中的固定分支批次策略：

#. 永远只使用 ``automation/leetcode-current``；
#. 禁止创建题号分支、时间戳分支和 finalize 分支；
#. 每轮提交 1 至 3 道连续完整题目及其索引、进度和知识账本；
#. 所有内容组成一个提交和一个非 Draft PR；
#. 逐题质量门和批次一致性全部通过后 squash merge；
#. 合并后重新读取 ``main``，确认题目文件存在且 ``next_problem`` 正确推进；
#. 未成功合并、主分支未推进或质量不确定时必须报告失败；
#. 同一时刻存在未关闭自动化内容 PR 时不得创建第二个内容 PR；
#. 合并后发现确定性缺陷时，允许并要求创建独立 ``fix:`` PR，不能以单 PR 规则留下错误。

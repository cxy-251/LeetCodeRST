对话驱动质量门
==============

文件职责
--------

本文件定义普通生成、针对性抽查和历史题修复在写入 ``main`` 前必须完成的最低检查。质量门由当前对话中的
明确指令触发，不是后台定时任务，也不要求固定题数的全量审查。

规则入口
--------

检查优先级为：

#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections；
#. 当前生效的前向规则；
#. 本文件和专项策略；
#. 历史归档。

``0151`` 起统一执行 ``docs/FORWARD_RULES_0151_ONWARD.rst``。每道公开题必须是唯一且自包含的 RST，
禁止用 ``.inc`` 或 ``.. include::`` 拆分题目正文和语言代码。

一、开始前检查
------------

#. 读取最新 ``main``、``AGENTS.md``、根 README 和 ``state/PROGRESS.toml``。
#. 确认 ``next_problem``、已完成范围、Premium 列表和下一批预算一致。
#. 读取 active corrections 与当前长期前向规则。
#. 只读取当前题真正需要的模板、专项策略、知识账本和最近相关题目。
#. 确认本轮只直接更新 ``main``，不创建分支、PR 或临时上传工作流。

二、单题内容检查
--------------

每道公开题必须同时满足：

#. 文件名、题号、难度、原题链接和平台访问状态一致。
#. 原创重述明确输入、输出、强前提、副作用和返回顺序。
#. 主算法状态、转移、不变量和终止条件完整。
#. 正确性覆盖合法性、完整性和必要的终止性。
#. 时间复杂度、工作空间、递归栈、输入物化和输出载荷与实际代码一致。
#. C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia 和 R 的实现语义一致。
#. 数值宽度、对象身份、所有权、字符单位和语言适配器单独核对。
#. 关键边界和最小自检能够区分常见错误实现。

三、单文件结构检查
----------------

这是不可省略的结构验收项：

#. 每道公开题在 ``problems/`` 中只对应一个 ``<题号>-<slug>.rst``。
#. 题目重述、算法、证明、复杂度、验证和十语言代码全部直接写在该 RST 中。
#. 题目 RST 中不得出现 ``.. include::``。
#. 当前题号和 slug 不得存在 ``.inc``、代码分片或其他可拼装正文文件。
#. 同一题的十种核心语言代码块都能在唯一 RST 中直接检索到。
#. Premium 题只登记状态，不生成猜测性 RST 或代码分片。

任一条件不满足时，该题不得计入完成，也不得提交。

四、默认验证
----------

普通题默认执行：

#. 人工核对题目契约、状态、证明和代码映射；
#. 运行官方示例与 2 至 4 个关键边界；
#. Python 主实现实际运行；
#. C++ 主实现使用严格警告编译，必要时运行；
#. C 涉及分配、指针、宽整数或所有权时严格编译并运行；
#. 其余语言检查接口、索引、容器、所有权和明显语法问题；
#. 对有现成运行时且成本低的语言可以增加实际运行，并如实记录。

不得把 Python 或 C++ 的通过外推为十语言全部运行通过。

五、风险触发增强
--------------

以下情况增加最小必要验证：

* 位运算、几何规范化、对象身份、图映射或复杂状态压缩；
* 数值边界、危险乘加、哈希键、所有权或字符编码；
* 重复值导致二分或状态识别退化；
* 样例、推导、编译和运行结果不一致；
* active correction 与当前规则发生冲突；
* 用户明确要求生产级验证或指定范围返工。

可选手段包括独立基准对拍、受控随机测试、穷举、属性测试、sanitizer、目标语言最小编译程序和官方文档核对。
验证规模只覆盖真实风险，不用大量案例重复证明已明确实现。

六、RST 与索引检查
----------------

#. 标题层级、代码块语言、相对链接和行宽正确。
#. 题号、难度、函数签名、正文方案和代码一致。
#. 当前范围 README 与根 README 的完成范围、Premium 登记和下一批一致。
#. ``state/PROGRESS.toml`` 与知识账本同步。
#. 搜索当前范围，确认 ``.. include::`` 和题目 ``.inc`` 数量均为零。
#. 不提交日志、缓存、marker、未引用草稿或一次性分析报告。

七、结构修复检查
--------------

对仅改变题目文件组织的返工：

#. 合并前后正文、代码块顺序和算法语义保持一致；
#. 每个被删除片段的内容已经完整出现在对应唯一 RST 中；
#. 删除全部被消费的 ``.inc``，不保留重复来源；
#. 结构修复不改变完成题数、Premium 状态或下一题；
#. 验证报告只能声明结构检查和内容保全，不能虚构重新运行算法测试。

八、提交检查
----------

#. 写入前重新读取最新 ``main``；主分支变化时重新计算目标树。
#. 多文件变化通过 Git blob、tree、单父 commit 和 ref 构造一个原子提交。
#. 使用非强制 fast-forward 更新 ``main``。
#. 禁止创建分支、PR、上传分片分支或临时组装工作流。
#. 提交后比较父提交与新提交，核对文件范围、状态和下一步。
#. 对话报告必须与 ``main`` 的实际提交、文件数和验证范围一致。

完成判定
--------

题目内容、十语言实现、验证证据、唯一自包含 RST、索引、进度和知识账本全部一致，活动目录不存在对应
``.inc`` 或未消费中间文件，并且提交通过非强制 fast-forward 写入 ``main`` 后，本轮才算完成。

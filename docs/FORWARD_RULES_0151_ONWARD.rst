0151 起长期前向质量规则
=======================

文件定位
--------

:生效起点: 0151
:终止题号: 不设终点
:维护方式: 原位修订
:规则角色: 后续全部题目的唯一长期前向规则

``docs/FORWARD_RULES_0101_0150.rst`` 保存 ``0101–0150`` 阶段的稳定规则与历史来源。
从 ``0151`` 开始，不再按每 50 题或其他题号区间新建前向规则文件。所有后续题目统一执行本文；
发现新的通用问题时，直接修订本文，并在同一原子提交中同步受影响的状态和入口文件。

本文继承旧规则中已经稳定的要求，并把质量门、语言边界、验证策略和直接主分支工作流收敛为一个长期规范。

规则优先级
----------

出现重复或冲突时按以下顺序解释：

#. ``state/PROGRESS.toml``：当前进度、下一批和实际启用规则；
#. ``state/REVIEW_INDEX.toml``：仍生效的 active corrections；
#. 本文件；
#. 专项策略、题目模板、语言与类型策略、质量门；
#. ``archive/`` 中的历史证据；
#. 历史提交和对话报告。

低优先级材料不得覆盖更高优先级的当前状态。旧前向规则只作为来源和历史证据，不再作为 ``0151`` 之后
生成任务的并行规则入口。

一、批次与执行工作流
------------------

开始前只读取一次
~~~~~~~~~~~~~~~~

每轮优先读取：

#. ``AGENTS.md`` 和根 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections 与 review policy；
#. 本文件和 ``docs/AUTOMATION_QUALITY_GATE.rst``；
#. 当前题号范围 README、知识账本和最近相关题目。

模板、专项策略和归档只在当前题确实涉及对应风险时读取，禁止为了重复确认而重新扫描仓库。

批次范围
~~~~~~~~

#. 从 ``next_problem`` 开始连续处理题号。
#. 难度预算固定为 Easy = 1、Medium = 2、Hard = 4。
#. 单批目标总分为 4 至 6；加入下一题超过 6 时结束。
#. 同一批不安排两道 Hard。
#. Premium、题面不可可靠确认或平台接口不完整时，登记状态后继续处理下一个可执行题目。
#. 题目难度必须以真实题目为准；发现状态登记错误时，在当前批次先修正范围和状态。

单题完成顺序
~~~~~~~~~~~~

每道题依次完成：

#. 精确题目契约和平台接口；
#. 核心状态、算法选择与不变量；
#. 正确性、完整性和终止性证明；
#. 十语言实现及必要语言适配器；
#. 数值、容量、资源、所有权和失败路径；
#. 时间、工作空间、物化空间、返回载荷和峰值空间；
#. 官方示例、关键边界和风险触发验证；
#. RST、索引、进度和知识账本同步。

每题写完立即核对正文与代码，不把所有验证推迟到批次末尾。

二、单题交付结构
----------------

普通算法题默认提供：

* 原创题目重述；
* 精确约束、输入域、返回值和副作用；
* 主算法、状态定义和不变量；
* 正确性证明；
* 真实复杂度；
* C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R 十语言完整实现；
* 关键边界；
* 准确区分运行、编译、对拍和静态检查的验证记录；
* 2 至 3 个最小自检问题。

简单题保持紧凑。复杂题提供足够推导，不为满足固定章节数量而扩写。数据库题使用 SQL，Shell 题使用
Bash 或 POSIX Shell，并按对应平台接口调整结构。

三、题目契约与输入域
------------------

精确契约
~~~~~~~~

#. 写明长度、数值、字符集合、结构形状、输入合法性、输出顺序和输入是否允许修改。
#. 公开函数名、参数、返回类型、平台节点模型和辅助函数与真实平台接口一致。
#. 非空、已排序、无环、唯一父节点、不共享节点、矩阵规则性等强前提集中列出。
#. 官方输入域与主动支持的扩展分别定义；空输入、零维和单元素扩展不得默认继承。
#. 默认或通配分支代表唯一剩余值时，必须由题意、类型或运行检查锁定完整输入域。
#. 抽象端点、半开终点和插入位置可以位于容器外；只有通过真实下标检查后才能读取元素。
#. 字符串题明确比较单位和返回下标单位：字节、UTF-16 代码单元、码点或字形簇。
#. 原地接口分别声明调用者可观察的对象修改、返回值和资源责任。

强前提降阶
~~~~~~~~~~

#. 利用有序、不重叠、方阵、固定字符域或可达区间闭包降低复杂度时，证明该前提删除了哪些工作。
#. 输入前提弱化后，重新评估算法、守卫和复杂度。
#. 把离散状态压缩为连续前缀或区间前，证明动作覆盖全部中间端点。
#. 只检查一个维度却访问另一维边界时，证明形状或同步收缩使条件等价。

四、状态、转移与证明
------------------

统一要求
~~~~~~~~

#. 状态含义直接对应代码变量、数组槽位或容器关系。
#. 循环或递归入口写出不变量，更新后说明不变量如何保持。
#. 正确性覆盖合法性、完整性、无重复、终止性和接口副作用。
#. 证明真实算法决策，不逐行翻译代码。
#. 某语言采用不同算法或所有权结构时，重新说明其语义、证明和复杂度。
#. 同一核心推导只完整出现一次；关联题复用结论并解释新增边界。

动态规划与记忆化
~~~~~~~~~~~~~~~~

#. 状态必须足以决定子问题；转移完整、初始化正确、遍历顺序符合依赖。
#. 一维覆盖二维 DP 时，标明旧同列、旧对角和新邻居的语义，并据此确定更新方向。
#. 滚动标量在覆盖前保存旧值；较短维度交换后同步更新角色、坐标和复杂度。
#. 记忆化键包含决定子问题语义的全部字段；失败结果也缓存。
#. 未计算、成功和失败状态分离，不使用输入域内普通值冒充不存在状态。
#. 必要条件剪枝只能提前否定，不能当作充分条件。
#. 使用 ``break`` 剪枝时证明后续候选单调不可能恢复合法，否则使用 ``continue``。

计数、枚举与输出
~~~~~~~~~~~~~~~~

#. 空结构作为组合单位元时，区分内部“一个空选择”和公开空输入返回值。
#. 乘法组合证明笛卡尔积双射和分支互斥。
#. 中间计数上界独立推导，不用最终答案范围掩盖中间溢出。
#. 饱和或截断状态证明截断算子与全部转移兼容。
#. 保存结果时保证历史快照不会被后续修改。
#. 去重限定作用层级，定义保留的规范代表并证明覆盖被跳过分支。
#. 枚举复杂度分别记录结果数量、元素总载荷、快照复制、当前路径和递归栈。

搜索与顺序
~~~~~~~~~~

#. 二分统一搜索区间、谓词、移动方向、排除安全性、终止条件和返回语义。
#. 闭区间与半开区间不得混用更新规则。
#. lower bound 和 upper bound 明确相等元素归属。
#. 重复值、碰撞或等价类降低区分能力时，分别给出平均和最坏复杂度。
#. 双指针移动一端时，证明被排除的一批候选不可能更优。
#. 单调栈弹栈时同时证明左右阻断位置和内部合法区间。
#. 摊还复杂度按每个元素进入和离开数据结构的次数计算。

五、拓扑、原地修改与所有权
------------------------

读写前沿
~~~~~~~~

#. 正向覆盖证明写指针不领先未读位置；逆向覆盖证明写位置已越过全部未读元素。
#. 覆盖前保存当前值，遍历期间不让容器长度变化或迭代器失效。
#. 复用输入区域作为标记时，先保存原始见证，再分阶段应用修改。
#. 不可逆写入延迟到见证收集和资源申请成功之后。
#. 失败、短路和提前退出不得留下未声明的部分修改。

临时修改与恢复
~~~~~~~~~~~~~~

#. 临时环、线索、哨兵链接、访问标记或字符哨兵列出进入点、恢复点和全部退出路径。
#. 成功、失败与短路路径都经过恢复。
#. 哨兵值必须位于合法输入域之外。
#. 所有权语言拥有局部副本时，区分内部恢复和调用者可观察的恢复。

链表、树与图
~~~~~~~~~~~~

#. 链表重连列出前驱、固定尾、移动节点和后缀的修改前后边。
#. 证明节点身份守恒、数量不变、目标区间外顺序、连通性、无重复和无环。
#. 稳定算法同时证明值顺序和重复值的原相对顺序。
#. 节点离开原链时断开旧边，或给出最终尾部终止证明。
#. 不使用访问集合的树遍历依赖无环、唯一父节点和无共享子树；图或 DAG 必须增加访问机制。
#. 显式栈说明保存的递归续点和节点提交时机。
#. Rust 等语言采用消费输入、``take``、线性拼接或索引节点池时，重新证明身份、修改范围和峰值空间。
#. ``clone``、引用计数克隆、借用和移动分别说明是否复制载荷或仅转移所有权。

六、数值、几何、容量与失败
------------------------

数值宽度
~~~~~~~~

#. 危险算术先扩宽操作数，再执行加法、乘法、取负、绝对值、差值、叉积、面积和移位。
#. 最终返回范围不能修复已经发生的中间溢出。
#. 聚合上界由元素数量乘单项最大贡献推导。
#. TypeScript 验证 ``number`` 安全整数；整数算法避免未审计的 32 位位运算。
#. 平台 ``int``、``Int`` 和无符号类型位宽必须覆盖输入和中间状态。

规范化键
~~~~~~~~

#. 分数、方向、斜率或比例使用最大公约数约分时，统一零分量和整体符号。
#. 哈希键相等必须与题目等价关系完全一致。
#. 重复对象、零向量和非法分母单独处理，不能混入普通规范化路径。
#. 几何或比例键属于高风险状态，至少使用独立基准或受控随机对拍确认。

容量与分配
~~~~~~~~~~

#. 固定缓冲容量包含载荷、终止符、分隔符、哨兵和元数据。
#. 元素数量乘元素大小、矩阵尺寸、容量翻倍和组合容量使用容量类型逐步检查。
#. C 在首次写入前检查分配；``realloc`` 使用临时指针。
#. 多缓冲、二维结果、路径和元数据采用整体成功或整体清理。
#. 顺序容器中间删除按移动或复制成本计费。
#. 复制型容器反复拼接、删除或切片重建按每轮长度累计成本。

失败语义
~~~~~~~~

#. 资源失败值与合法 ``false``、``0``、空结果和部分答案区分。
#. 已分配资源在所有失败路径完整清理。
#. 非空解包、断言和强制取值由紧邻的不变量支撑。
#. ``void`` 原地接口发生资源失败时，保证没有部分修改，或明确接口无法报告的限制。

七、字符串、索引与物化
--------------------

#. ASCII 字节实现由精确字符域支撑；扩展 Unicode 时重新选择索引和长度单位。
#. ``strlen``、trim、split、编码转换和索引建立按真实调用次数计费。
#. ``codeunits``、``collect``、``utf8ToInt``、切片和重新编码区分视图与副本。
#. 循环内不变的分类表、正则和整串转换移到热循环外。
#. 返回子串区分共享底层存储、不可变别名和新分配副本。
#. Go 子串可能保留完整原字符串；需要独立存储时明确复制。
#. 输出缓冲说明最终是否直接采用，或在 reverse、join、冻结和重编码时产生第二份载荷。
#. 大型输出的时间与空间至少包含写出全部载荷的下界。
#. 零基算法坐标转换为一基数组位置时逐项核对，不依赖直觉平移。

八、复杂度表达
------------

复杂度必须与实际代码一致，并分别说明：

* 主算法时间；
* 平均、最坏或摊还条件；
* 核心工作状态；
* 递归栈或显式搜索前沿；
* 输入规范化与按值参数复制；
* 字符、切片和容器物化；
* 输出元素总载荷与返回副本；
* 峰值同时存活空间；
* 因目标语言所有权或值语义产生的额外成本。

不得用“原地”“常数空间”“哈希 O(1)”等抽象词覆盖运行库、适配器或最坏情况的真实成本。

九、十语言检查清单
----------------

C
~

* 分配、扩容、二维结果和失败清理形成闭合事务。
* 比较器使用关系比较，避免减法溢出。
* 节点断链、返回内存和释放责任明确。
* 返回行数、列长度和容量元数据同步。

C++
~~~

* 按值参数复制、引用生命周期和输入重排分别说明。
* ``size_t`` 与有符号坐标转换由上界支撑。
* 标准容器和算法包含直接头文件，比较器满足严格弱序。
* 危险差值和乘积先转换到宽类型。

Python
~~~~~~

* 切片、列表复制、路径快照、字符串构造和递归深度计入成本。
* 任意精度整数能力不能外推到固定宽语言。
* 类型注解、平台类型和版本相关 API 可解析。

Java 与 C#
~~~~~~~~~~

* 危险中间值在运算前提升到 ``long``。
* 集合、装箱、对象数组排序缓冲、字符串复制和递归计入成本。
* 对象字段在公共入口初始化或清空。
* 哈希键需要稳定的值相等和哈希语义。

Rust
~~~~

* 代码符合真实借用检查，不以伪代码绕过所有权。
* ``take``、``clone``、``Rc``、``RefCell`` 和消费输入的载荷与峰值明确。
* 无符号递减使用显式分支或有符号控制坐标。
* 字节字符串操作由 ASCII 契约支撑。

Go
~~

* ``int`` 位宽由平台前提或固定宽类型支撑。
* 切片共享、``append`` 扩容和子串保留语义明确。
* 版本相关 API 与最低 Go 版本一致。
* map 键必须可比较且与规范化等价关系一致。

TypeScript
~~~~~~~~~~

* ``number`` 安全整数和位运算 32 位转换独立验证。
* ``Map.get`` 的 ``undefined`` 与合法零值分开。
* 字符串下标按 UTF-16 代码单元解释。
* 严格类型检查与运行测试分别记录。

Julia
~~~~~

* 一基数组槽位与零基算法坐标逐项映射。
* ``a:b`` 是步长 ``+1`` 的 ``UnitRange``；递减遍历使用显式负步长。
* ``codeunits(s)`` 是轻量 wrapper，``collect`` 才物化数组。
* ``Vector`` 参数共享可变对象，元素修改对调用者可见。
* ``collect``、切片、字符串重建和宿主 ``Int`` 位宽单独说明。

R
~

* 普通复杂赋值绑定到当前调用帧；递归共享状态使用参数、环境或审计后的 ``<<-``。
* ``seq.int`` 的端点和步长方向在构造前验证。
* ``utf8ToInt``、``charToRaw``、``c`` 拼接、负下标删除和返回副本计入复制成本。
* 反复追加与删除可能产生平方级累计复制。
* 形式参数局部更新不保证修改调用者变量；无法表达原地接口时返回修改后的适配器结果。

十、验证策略
----------

默认质量门
~~~~~~~~~~

普通题默认执行：

#. 人工核对契约、状态、转移、证明和代码映射；
#. 官方示例；
#. 2 至 4 个有区分度的关键边界；
#. Python 主实现运行；
#. C++ 主实现严格警告编译，必要时运行；
#. C 在涉及分配、指针或宽度风险时严格编译并运行；
#. 其余语言检查接口、索引、容器、所有权和明显语法问题；
#. 有现成运行时且验证成本低时，可运行更多语言，但必须如实记录。

风险触发增强
~~~~~~~~~~~~

出现以下情况时增加最小必要验证：

* 复杂去重、几何规范化、状态压缩、图映射或高风险下标；
* 数值宽度、位运算、哈希键、对象身份或所有权路径；
* 样例推导、运行结果和静态检查不一致；
* 新规则与 active correction 冲突；
* 用户明确要求生产级可靠性或专项审查。

可选手段包括独立基准对拍、受控随机测试、穷举、小规模属性测试、sanitizer、目标语言最小编译程序和官方文档
核对。验证规模只覆盖实际疑点，不用大量案例重复证明已经明确的实现。

证据用词
~~~~~~~~

* ``运行验证``：目标代码实际执行；
* ``编译验证``：只证明编译通过；
* ``静态检查``：未执行的人工核对；
* ``对拍``：与独立基准比较；
* ``属性测试``：检查独立性质。

不得把一种语言的运行结果外推为十语言全部运行通过。

十一、文档、状态与 Git
--------------------

状态同步
~~~~~~~~

每个生成批次在同一提交中同步：

* 题目 RST 和五个十语言 include 文件；
* 当前范围 README；
* 根 README；
* ``state/PROGRESS.toml``；
* ``state/CONCEPT_LEDGER.toml`` 和当前概念分段；
* 只有 active corrections 或审查策略变化时才修改 ``state/REVIEW_INDEX.toml``。

RST 检查
~~~~~~~~

#. 标题层级、代码块语言、include 路径和相对链接正确。
#. 题号、难度、文件名、函数签名、正文方案和代码一致。

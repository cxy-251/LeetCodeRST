0151 起长期前向质量规则
=======================

文件定位
--------

:生效起点: 0151
:终止题号: 不设终点
:维护方式: 原位修订
:规则角色: 后续全部题目的唯一长期前向规则

``docs/FORWARD_RULES_0101_0150.rst`` 保存 ``0101–0150`` 阶段的稳定规则与历史来源。
从 ``0151`` 开始，不再按每 50 题或其他题号区间新建前向规则文件。所有后续题目统一执行本文；
发现新的通用问题时，直接修订本文，并在同一原子提交中同步受影响的状态和入口文件。

本文继承旧规则中已经稳定的要求，并把质量门、语言边界、静态审查策略和直接主分支工作流收敛为一个长期规范。

规则优先级
----------

出现重复或冲突时按以下顺序解释：

#. ``state/PROGRESS.toml``：当前进度、下一批和实际启用规则；
#. ``state/REVIEW_INDEX.toml``：仍生效的 active corrections；
#. 本文件；
#. 专项策略、题目模板、语言与类型策略、质量门；
#. ``archive/`` 中的历史证据；
#. 历史提交和对话报告。

低优先级材料不得覆盖更高优先级的当前状态。旧前向规则只作为来源和历史证据，不再作为 ``0151`` 之后
生成任务的并行规则入口。

一、批次与执行工作流
------------------

开始前只读取一次
~~~~~~~~~~~~~~~

每轮优先读取：

#. ``AGENTS.md`` 和根 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections 与 review policy；
#. 本文件和 ``docs/AUTOMATION_QUALITY_GATE.rst``；
#. 当前题号范围 README、知识账本和最近相关题目。

模板、专项策略和归档只在当前题确实涉及对应风险时读取，禁止为了重复确认而重新扫描仓库。

批次范围
~~~~~~~~

#. 从 ``next_problem`` 开始连续处理题号。
#. 难度预算固定为 Easy = 1、Medium = 2、Hard = 4。
#. 单批目标总分为 4 至 6；加入下一题超过 6 时结束。
#. 同一批不安排两道 Hard。
#. Premium、题面不可可靠确认或平台接口不完整时，登记状态后继续处理下一个可执行题目。
#. 题目难度必须以真实题目为准；发现状态登记错误时，在当前批次先修正范围和状态。

单题完成顺序
~~~~~~~~~~~~

每道题依次完成：

#. 精确题目契约和平台接口；
#. 核心状态、算法选择与不变量；
#. 正确性、完整性和终止性证明；
#. 十语言实现及必要语言适配器；
#. 数值、容量、资源、所有权和失败路径；
#. 时间、工作空间、物化空间、返回载荷和峰值空间；
#. 官方示例、关键边界的人工推演和风险触发静态审查；
#. RST、索引、进度和知识账本同步。

每题写完立即核对正文与代码，不把静态审查推迟到批次末尾。

二、单题交付结构
----------------

普通算法题默认提供：

* 原创题目重述；
* 精确约束、输入域、返回值和副作用；
* 主算法、状态定义和不变量；
* 正确性证明；
* 真实复杂度；
* C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R 十语言完整实现；
* 关键边界；
* 说明覆盖范围、未运行未编译事实和剩余风险的静态审查记录；
* 2 至 3 个最小自检问题。

每道公开可访问题目对应且只对应一个 ``<题号>-<slug>.rst``。题目重述、算法、证明、复杂度、静态审查与全部
语言代码必须直接内联在该文件中。禁止为单题创建 ``.inc``、代码分片或使用 ``.. include::`` 组装题目正文。

简单题保持紧凑。复杂题提供足够推导，不为满足固定章节数量而扩写。数据库题使用 SQL，Shell 题使用
Bash 或 POSIX Shell，并按对应平台接口调整结构。

三、题目契约与输入域
------------------

精确契约
~~~~~~~~

#. 写明长度、数值、字符集合、结构形状、输入合法性、输出顺序和输入是否允许修改。
#. 公开函数名、参数、返回类型、平台节点模型和辅助函数与真实平台接口一致。
#. 非空、已排序、无环、唯一父节点、不共享节点、矩阵规则性等强前提集中列出。
#. 官方输入域与主动支持的扩展分别定义；空输入、零维和单元素扩展不得默认继承。
#. 默认或通配分支代表唯一剩余值时，必须由题意、类型或运行检查锁定完整输入域。
#. 抽象端点、半开终点和插入位置可以位于容器外；只有通过真实下标检查后才能读取元素。
#. 字符串题明确比较单位和返回下标单位：字节、UTF-16 代码单元、码点或字形簇。
#. 原地接口分别声明调用者可观察的对象修改、返回值和资源责任。

强前提降阶
~~~~~~~~~~

#. 利用有序、不重叠、方阵、固定字符域或可达区间闭包降低复杂度时，证明该前提删除了哪些工作。
#. 输入前提弱化后，重新评估算法、守卫和复杂度。
#. 把离散状态压缩为连续前缀或区间前，证明动作覆盖全部中间端点。
#. 只检查一个维度却访问另一维边界时，证明形状或同步收缩使条件等价。

四、状态、转移与证明
------------------

统一要求
~~~~~~~~

#. 所有关键状态在首次使用前定义语义、合法范围和更新时机。
#. 循环、递归、搜索、回溯、滑动窗口、双指针和并查集方案写出核心不变量。
#. 多阶段算法分别证明每阶段产物，以及阶段接口为何保持下一阶段前提。
#. 使用证明过的上界分配，计数时不得写入；避免“估一个容量再填充”。
#. 回溯路径、二维结果和共享缓冲在保存时创建独立快照。
#. 哈希或规范化键必须同时满足完备性与唯一性，不得只写构造公式。
#. 图、树和链表比较节点身份时，静态审查与实现都不能退化为值比较。
#. 最终证明至少覆盖合法性、完整性和终止性；唯一性只有在题目或算法依赖时说明。

数值与状态机
~~~~~~~~~~~~

#. 中点、差值、乘积、绝对值、斜率、面积、编码和累计和在运算前提升到足够宽类型。
#. 有符号、无符号、宿主 ``int`` 和 JavaScript ``number`` 的边界分别解释。
#. 位掩码状态写出每一位的真实状态，禁止只把公式称为“技巧”。
#. 更新依赖旧状态时使用临时变量、同时赋值，或证明更新顺序正确。
#. 重复值导致二分、哈希或状态识别能力下降时，准确写出最坏复杂度退化。

五、容器、资源与失败路径
----------------------

C 资源事务
~~~~~~~~~

动态结果按以下顺序：

#. 证明结果行数、列数、节点数或上界；
#. 计算容量并检查 ``size_t`` 乘加溢出；
#. 分配外层容器、长度数组和必要元数据；
#. 逐项构造，同时记录成功数量；
#. 失败时按已成功数量清理；
#. 最后写入返回计数和列长度；
#. 返回所有权与调用者释放责任明确。

若平台签名无法表达资源失败，不伪造“安全返回值”。可以说明评测环境假设分配成功，或把资源缺陷作为接口限制
明确记录。

动态容器
~~~~~~~~

#. 扩容前检查容量倍增和 ``capacity * sizeof(T)``。
#. ``realloc`` 使用临时指针，失败时保留旧对象。
#. 队列、栈、并查集、哈希表和结果容器区分逻辑大小与分配容量。
#. 标准容器仍需说明扩容、迭代器失效、切片共享和字符串保留行为。
#. 写入数量、返回数量、列长度和容器实际大小同步。

失败路径
~~~~~~~~

#. 构造过程采用全成功或全失败语义。
#. 返回值本身可能是合法结果时，不把同一值当作资源失败信号。
#. 分配、解析或转换失败无法通过平台接口报告时，明确限制，不把静默错误写成正式契约。
#. 托管语言中的异常、越界、空解包和不可达分支需要由输入前提或显式检查支撑。

六、输入修改、所有权与平台类型
----------------------------

节点与可变对象
~~~~~~~~~~~~~~

#. ``ListNode``、``TreeNode``、``Node`` 等平台类型不在每题重复定义。
#. 首次出现某类节点时解释字段、引用关系和可变性，后续只说明当前题的新差异。
#. Julia 以 ``mutable struct`` 表达引用语义，R 以 ``environment`` 表达共享可变对象。
#. 节点断链、重连、删除、克隆和共享后缀分别说明调用后旧引用是否仍有效。
#. C/C++ 说明释放责任；Rust 说明移动、借用、``take``、``clone`` 和 ``Rc`` 语义。

原地与返回值
~~~~~~~~~~~~

#. “原地”只描述核心算法状态，不能掩盖语言适配器产生的输入副本、返回副本或字符串物化。
#. C++ 按值参数、Python 切片、Java/C# 子串与装箱、Go 切片共享、Julia ``collect``、R 写时复制分别计入成本。
#. R 无法表达平台原地接口时，使用返回修改后对象的适配器，并明确调用方式。
#. 输出数组、路径、子串和节点集合的所有权与快照语义一致。

七、字符串与索引
--------------

比较单位
~~~~~~~~

#. 题目限定 ASCII 时可以按字节或代码单元实现，并在正文中声明依赖。
#. 题目支持 Unicode 时，根据契约选择码点、UTF-16 代码单元、字节或字形簇。
#. Go、Rust、Julia 的字节切片只能用于已证明的字符边界。
#. JavaScript/TypeScript 字符串索引返回 UTF-16 代码单元，不等于 Unicode 码点。
#. R ``utf8ToInt``、``charToRaw`` 等物化成本计入适配器复杂度。

下标与缓冲
~~~~~~~~~~

#. 半开区间端点可以等于长度，只有真实元素读取需要 ``index < length``。
#. 输出缓冲说明最终是否直接采用，或在 reverse、join、冻结和重编码时产生第二份载荷。
#. 大型输出的时间与空间至少包含写出全部载荷的下界。
#. 零基算法坐标转换为一基数组位置时逐项核对，不依赖直觉平移。

八、复杂度表达
------------

复杂度必须与实际代码一致，并分别说明：

* 主算法时间；
* 平均、最坏或摊还条件；
* 核心工作状态；
* 递归栈或显式搜索前沿；
* 输入规范化与按值参数复制；
* 字符、切片和容器物化；
* 输出元素总载荷与返回副本；
* 峰值同时存活空间；
* 因目标语言所有权或值语义产生的额外成本。

不得用“原地”“常数空间”“哈希 O(1)”等抽象词覆盖运行库、适配器或最坏情况的真实成本。

九、十语言检查清单
----------------

C
~

* 分配、扩容、二维结果和失败清理形成闭合事务。
* 比较器使用关系比较，避免减法溢出。
* 节点断链、返回内存和释放责任明确。
* 返回行数、列长度和容量元数据同步。

C++
~~~

* 按值参数复制、引用生命周期和输入重排分别说明。
* ``size_t`` 与有符号坐标转换由上界支撑。
* 标准容器和算法包含直接头文件，比较器满足严格弱序。
* 危险差值和乘积先转换到宽类型。

Python
~~~~~~

* 切片、列表复制、路径快照、字符串构造和递归深度计入成本。
* 任意精度整数能力不能外推到固定宽语言。
* 类型注解、平台类型和版本相关 API 可解析。

Java 与 C#
~~~~~~~~~~

* 危险中间值在运算前提升到 ``long``。
* 集合、装箱、对象数组排序缓冲、字符串复制和递归计入成本。
* 对象字段在公共入口初始化或清空。
* 哈希键需要稳定的值相等和哈希语义。

Rust
~~~~

* 代码符合真实借用检查，不以伪代码绕过所有权。
* ``take``、``clone``、``Rc``、``RefCell`` 和消费输入的载荷与峰值明确。
* 无符号递减使用显式分支或有符号控制坐标。
* 字节字符串操作由 ASCII 契约支撑。

Go
~~

* ``int`` 位宽由平台前提或固定宽类型支撑。
* 切片共享、``append`` 扩容和子串保留语义明确。
* 版本相关 API 与最低 Go 版本一致。
* map 键必须可比较且与规范化等价关系一致。

TypeScript
~~~~~~~~~~

* ``number`` 安全整数和位运算 32 位转换独立静态核对。
* ``Map.get`` 的 ``undefined`` 与合法零值分开。
* 字符串下标按 UTF-16 代码单元解释。
* 手工核对静态类型约束与 JavaScript 运行时语义，不调用类型检查器或运行代码。

Julia
~~~~~

* 一基数组槽位与零基算法坐标逐项映射。
* ``a:b`` 是步长 ``+1`` 的 ``UnitRange``；递减遍历使用显式负步长。
* ``codeunits(s)`` 是轻量 wrapper，``collect`` 才物化数组。
* ``Vector`` 参数共享可变对象，元素修改对调用者可见。
* ``collect``、切片、字符串重建和宿主 ``Int`` 位宽单独说明。

R
~

* 普通复杂赋值绑定到当前调用帧；递归共享状态使用参数、环境或审计后的 ``<<-``。
* ``seq.int`` 的端点和步长方向在构造前静态核对。
* ``utf8ToInt``、``charToRaw``、``c`` 拼接、负下标删除和返回副本计入复制成本。
* 反复追加与删除可能产生平方级累计复制。
* 形式参数局部更新不保证修改调用者变量；无法表达原地接口时返回修改后的适配器结果。

十、静态审查策略
---------------

统一静态质量门
~~~~~~~~~~~~~~

普通题统一执行：

#. 人工核对契约、状态、转移、证明和代码映射；
#. 人工推演官方示例与 2 至 4 个有区分度的关键边界；
#. 逐语言静态核对接口、导入、索引、容器、所有权、位宽、字符单位和明显语法问题；
#. 检查复杂度是否覆盖适配器物化、复制、输出载荷与峰值空间；
#. 记录未运行未编译事实、静态审查覆盖范围和剩余风险。

题解代码不得运行或编译，不做随机对拍、穷举、属性测试、sanitizer、严格类型检查或目标语言最小程序。
允许执行 RST、TOML、目录结构、Git 对象和状态一致性检查，因为这些检查不执行题解代码。

风险触发增强
~~~~~~~~~~~~

复杂去重、状态压缩、位运算、对象身份、所有权或高风险下标只增加针对性静态推导、反例分析与官方语义资料
核对。新规则与 active correction 冲突或某项语义无法静态确认时，记录剩余风险，不用执行代码消除不确定性。

证据用词
~~~~~~~~

题解统一使用 ``静态审查``，明确表示没有执行、编译或测试代码。不得使用“运行通过”“编译通过”“对拍通过”
或“全部语言验证通过”等表述。人工推演只能证明所列案例在纸面上与算法一致，不能写成运行证据。

十一、文档、状态与 Git
--------------------

状态同步
~~~~~~~~

每个生成批次在同一提交中同步：

* 每道公开题唯一且自包含的题目 RST；
* 当前范围 README；
* 根 README；
* ``state/PROGRESS.toml``；
* ``state/CONCEPT_LEDGER.toml`` 和当前概念分段；
* 只有 active corrections 或审查策略变化时才修改 ``state/REVIEW_INDEX.toml``。

RST 检查
~~~~~~~~

#. 每道公开题只有一个 ``.rst``，全部正文与语言代码直接内联。
#. 题目 RST 不含 ``.. include::``，目录中不存在对应 ``.inc`` 分片。
#. 标题层级、代码块语言和相对链接正确。
#. 题号、难度、文件名、函数签名、正文方案和代码一致。
#. 行宽优先控制在 88 个显示列以内，硬上限 100。
#. import 语法可解析。
#. 不提交未引用草稿、日志、缓存、marker 或一次性分析报告。

直接主分支
~~~~~~~~~~

#. 所有生产、修复、规则维护和归档只允许直接更新 ``main``。
#. 禁止创建临时分支、工作分支、PR、上传分片分支或临时组装工作流。
#. 多文件变化使用 Git blob、tree、单父 commit 和 ref 构造一个原子提交。
#. 写入前重新读取最新 ``main``；主分支变化时重新计算目标树。
#. 只执行非强制 fast-forward，禁止覆盖并发修改。
#. 提交后比较父提交与新提交，复查文件范围、状态、活动目录和下一步。

十二、规则维护
------------

长期维护原则
~~~~~~~~~~~~

#. 本文件从 ``0151`` 起永久生效，不再创建 ``FORWARD_RULES_0201_0250.rst`` 等分段文件。
#. 发现通用缺陷时直接修改本文件，不把修正只留在对话、单题正文或临时审查报告中。
#. 修正规则时写成可执行条件：触发场景、错误风险、必须动作和检查方式。
#. 只影响一道历史题的问题执行独立修复，不污染通用规则。
#. 新规则与旧规则重复时合并原条目，避免不断追加同义句。
#. 删除或放宽规则时保留充分理由，并确认不再依赖对应 active correction。
#. 规则维护提交同时更新 ``PROGRESS`` 的规则状态和所有入口引用。
#. 本文件只维护当前有效规则；来源证据、旧版本和已消费审查材料留在 ``archive/``。

完成判定

0001–0050 审查证据与历史题处理规则
================================

状态
----

``0001`` 至 ``0050`` 的逐题审查已经完成。审查结果用于改进 ``0051`` 至 ``0100``，当前不再处于
规则提炼阶段。

审查目的
--------

逐题审查完成了三件事：

#. 从真实 RST 和十语言代码中识别正向样本与风险；
#. 把可复用模式整理为前向质量规则；
#. 保留每项规则的题目来源，方便后续追溯。

审查证据
--------

内容结论来自：

* 对应题目的完整 RST；
* 题意、示例、算法状态、证明和复杂度；
* 十语言代码块；
* 与该题直接相关的仓库约定。

PR 描述、提交信息、合并状态和对话报告只说明工作发生过，不证明题解质量。

资料位置
--------

完整目录见 ``docs/REVIEW_CATALOG_0001_0050.rst``。

* 结构化记录：``state/REVIEW_0001_0050.toml`` 与 ``state/reviews/*.toml``；
* 详细证据：``docs/REVIEW_FINDINGS_0001_0050.rst`` 与 ``docs/review-findings/*.rst``；
* 覆盖和更正索引：``state/REVIEW_INDEX.toml``；
* 最终执行规则：``docs/FORWARD_RULES_0051_0100.rst``。

记录分层
--------

单题观察
~~~~~~~~

只描述某一道题的具体表现。它可以是正向样本、风险、语言差异或验证限制。

跨题模式
~~~~~~~~

多个题目出现相同根因，或单次出现就属于高风险内存、所有权、索引、数值或语言语义问题时，形成
跨题模式。

前向规则
~~~~~~~~

跨题模式只有转换为明确检查动作后，才进入 ``docs/FORWARD_RULES_0051_0100.rst``。例如“注意边界”
不构成规则；“容量乘积在目标容量类型中逐步检查溢出”才是可执行规则。

冲突处理
--------

批次记录是审查快照，可能保留后来被更正的观察。出现冲突时：

#. 先读取 ``state/REVIEW_INDEX.toml`` 的 ``corrections``；
#. 再执行 ``docs/FORWARD_RULES_0051_0100.rst``；
#. 批次记录只用于追溯证据来源。

当前已登记的 Julia ``UnitRange`` 更正覆盖所有早期相反描述。

历史题边界
----------

``0001`` 至 ``0050`` 的题目正文保持原样。审查记录中的问题不会自动触发回改。

用户明确指定某一道历史题需要修复时：

#. 重新读取该题完整 RST 和相关规则；
#. 明确缺陷属于算法、编译、运行、复杂度、接口、内存、所有权还是文档；
#. 只修改该题和确实受影响的公共文件；
#. 使用针对性验证；
#. 形成独立原子提交，题号进度保持不变。

后续维护
--------

从 ``0051`` 起，新题直接执行最终前向规则。新的稳定模式可以继续补充到
``docs/FORWARD_RULES_0051_0100.rst``，专项文件只保留各自职责，不重复抄写完整规则。

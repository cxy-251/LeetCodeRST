审查证据、风险抽查与历史题处理规则
==================================

当前状态
--------

``0001`` 至 ``0050`` 的第一次逐题规则提炼和 ``0051`` 至 ``0100`` 的第二轮逐题审查均已完成。第二轮
81 条 promoted rules 与 14 项 active corrections 已归并为 ``docs/FORWARD_RULES_0101_0150.rst``。

已完成审查产物统一保存在：

* ``archive/reviews/0001-0050/MANIFEST.rst``；
* ``archive/reviews/0051-0100/MANIFEST.rst``。

新题生成不逐份读取归档批次。

审查策略
--------

固定“每 50 题一次”的全量逐题审查已经取消，后续不再因为题号到达 ``0150``、``0200`` 等边界自动启动
整段复查。普通批次自身的质量门仍是完成条件，不属于额外审查轮次。

只有以下情况才启动针对性抽查：

#. 用户明确指定某题、某范围或某类问题；
#. 新算法依赖高风险位运算、对象身份、所有权、编码、溢出或语言运行时语义；
#. 某语言适配器改变主算法复杂度、输入修改或返回所有权；
#. 样例人工推导、正文证明和逐语言静态检查出现不一致；
#. 新结论与 active correction、前向规则或平台接口冲突；
#. 同一缺陷在多个新题中重复出现，需要提炼前向规则。

抽查只覆盖触发风险所需的最小题目集合。没有风险信号时，不创建五题批次、五十题轮次、findings 目录或
规则归并任务。

批次自检
--------

每个普通生成批次仍必须：

#. 核对题目契约、算法状态、证明和代码映射；
#. 人工推演官方示例和少量有区分度的关键边界；
#. 静态检查十语言的接口、导入、索引、位宽、所有权、语法和代码映射；
#. 记录未运行未编译事实、静态审查覆盖范围和剩余风险；
#. 同步索引、进度和知识账本。

题解代码不运行、不编译，不做随机对拍、穷举、属性测试、sanitizer 或目标语言最小程序。

历史证据
--------

历史逐题审查完成了三件事：

#. 从真实 RST、证明、复杂度和十语言代码中识别正向样本、确定性问题与静态审查限制；
#. 把可复用模式转换为带来源、可执行的前向质量规则；
#. 保留足以追溯规则来源和修复历史题的证据。

内容结论只来自题目完整 RST、真实代码、仓库接口和策略，以及必要的目标语言官方文档静态核对。
PR 描述、提交信息和对话摘要只能证明工作发生过，不能证明题解正确。

活动记录与归档
--------------

针对性抽查进行期间，必要状态和 findings 可以暂存在 ``state/reviews`` 与 ``docs/review-findings``。
抽查完成并被正式规则吸收后，这些文件必须在同一个归并提交中移入 ``archive/reviews/<range>/``。

``state/REVIEW_INDEX.toml`` 只保留当前 active corrections、审查策略、归档 manifest、规则归并状态和
下一动作，不展开全部历史批次路径。

规则优先级
----------

#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections 与 review policy；
#. 当前阶段完整前向规则；
#. 专项策略、模板和质量门；
#. ``archive/`` 中的历史批次与 findings；
#. 提交、PR 和对话摘要。

历史题边界
----------

已完成题目正文默认保持原样。只有用户明确指定修复某道历史题时才：

#. 读取该题完整 RST、active correction 和当前规则；
#. 根据 archive manifest 定位必要证据；
#. 明确缺陷类别；
#. 只修改该题和确实受影响的公共文件；
#. 使用针对性静态审查并记录剩余风险；
#. 形成独立原子提交，题号进度保持不变。

事实更正
--------

active correction 高于历史正文和批次快照。完整文本保存在 ``state/REVIEW_INDEX.toml``。当前重点包括：

* Julia ``UnitRange``、``codeunits`` 和 ``Vector`` 修改可见性；
* R 递归绑定、``seq.int`` 方向、字符物化和复制型容器累计成本；
* 一行 DP 核心工作空间与 C++、Julia、R 适配器物化空间分层；
* Go 子串共享与 ``strings.Clone``；
* Gray Code 零维退化约定；
* 跨题 R 树构造器符号一致性；
* 历史题修复范围、风险抽查和对话触发工作流。

语言语义与复杂度证据
--------------------

闭包赋值、范围构造、无符号算术、写时复制、所有权、对象身份、标准排序、字符串转换、子串存储和修改
可见性必须按目标语言规范静态核对；无法确认时标记为静态未确认并记录剩余风险。

复杂度同时覆盖显式代码与标准库隐藏工作：完整扫描、排序缓冲、参数按值复制、编码转换、切片、子串共享、
返回副本、容器重建、输出载荷和峰值并存。核心算法空间不能覆盖适配器物化。

完整生命周期规则见 ``docs/ARTIFACT_LIFECYCLE_POLICY.rst``。

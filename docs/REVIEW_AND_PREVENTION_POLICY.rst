审查目的
--------

每轮逐题审查完成三件事：

#. 从真实 RST、证明、复杂度和十语言代码中识别正向样本、确定性问题与验证限制；
#. 把可复用模式转换为带来源、可执行的前向质量规则；
#. 保留结构化证据和事实更正，支持后续追溯与独立修复。

证据来源
--------

内容结论只来自：

* 对应题目的完整 RST；
* 题意、示例、状态、证明和复杂度；
* 十语言代码块；
* 仓库真实接口与策略文件；
* 必要时使用目标语言官方文档和最小可执行测试。

PR 描述、提交信息、合并状态和对话报告只能证明工作发生过，不能证明题解正确。

规则优先级
----------

出现重复或冲突时按以下顺序：

#. ``state/PROGRESS.toml``；
#. ``state/REVIEW_INDEX.toml`` 的 active corrections；
#. 当前阶段已完成归并的完整前向规则；
#. 专项策略和模板；
#. 批次记录与详细 findings；
#. 提交、PR 和对话摘要。

高优先级内容覆盖低优先级快照。批次记录不会因为后续更正而重写，它们保留当时审查证据。

历史题边界
----------

被审查题目正文默认保持原样。发现确定性问题、复杂度偏差或语言适配器缺陷，不自动触发历史题回改。

只有用户明确指定修复某道历史题时才执行：

#. 重新读取该题完整 RST、对应批次记录、findings、active correction 和当前规则；
#. 明确缺陷属于算法、编译、运行、复杂度、接口、内存、所有权还是文档；
#. 只修改该题和确实受影响的公共文件；
#. 使用针对性运行、对拍或静态验证；
#. 形成独立原子提交，已完成题号进度保持不变。

事实更正
--------

active correction 代表已确认且优先级高于历史正文和批次快照的事实。完整文本保存在
``state/REVIEW_INDEX.toml``。

目前重点包括：

* Julia ``UnitRange``、``codeunits`` 和 ``Vector`` 修改可见性；
* R 递归绑定、``seq.int`` 方向、字符物化和复制型容器累计成本；
* 一行 DP 核心工作空间与 C++、Julia、R 适配器物化空间分层；
* Go 子串共享与 ``strings.Clone``；
* Gray Code 零维退化约定；
* 跨题 R 树构造器符号一致性；
* 历史题修复范围与对话触发的原子提交工作流。

语言语义验证
------------

闭包赋值、范围构造、无符号算术、写时复制、所有权、标准排序、字符串转换、子串存储和修改可见性必须按
目标语言验证，不能由其他语言测试替代。

缺少目标运行时时：

* 标记为静态未验证；
* 使用官方文档核对高风险语义；
* 不声称已经完成运行验证；
* 后续获得运行时后补最小语义测试。

复杂度证据
----------

复杂度审查必须覆盖显式代码和标准库隐藏工作：

* 完整扫描、排序缓冲、递归栈；
* 参数按值复制、编码转换、``collect``、``split``；
* 切片、子串共享、返回副本；
* 容器中间删除、反复拼接和负下标重建；
* 输出载荷、元数据和峰值并存。

算法核心工作空间不能覆盖语言适配器物化。峰值空间、累计复制和总分配行为分别记录。

所有权与调用者可观察性
----------------------

输入不变性按调用者在函数返回后仍能观察到的对象定义：

* 借用或共享对象的修改对调用者可见；
* 局部变量重绑定不等于修改调用者绑定；
* 独占消费的输入允许复用缓冲区作为结果；
* 返回同一对象、不可变别名或新副本分别说明；
* 节点断链、所有权转移、立即释放和垃圾回收分别说明。

恢复、快照与身份
----------------

临时哨兵、访问标记、环和线索必须让成功、失败和短路路径经过统一恢复点。保存结果时证明快照独立；原地
链表和树算法使用节点身份、节点数量、相对顺序和无环性验证，不能只比较值序列。

#. 更新 ``PROGRESS``、``REVIEW_INDEX``、README 和资料目录。

后续维护
--------

每个生成、审查、修复或归并批次：

#. 读取最新 ``main``、``PROGRESS``、``REVIEW_INDEX`` 和当前阶段规则；
#. 确定唯一范围；
#. 完成内容、验证和状态同步；
#. 历史题默认不修改；
#. 以一个原子提交更新 ``main``；
#. 复查差异、状态和下一步。

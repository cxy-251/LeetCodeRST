后续题解防复发规则
==================

目的
----

本规则把已经暴露过的风险转化为后续题解的公共约束。它不是一份针对 ``0001`` 至
``0050`` 的逐题审查报告，也不表示这 50 道题已经完成全量复核。

已知样本只用于提炼规则，例如 R 递归作用域、Julia 递减范围、TypeScript 位运算边界、
C 返回容量与所有权、复杂度遗漏输出复制成本等。规则升级的目标是让 ``0051`` 至
``0100`` 不再重复这些问题。

适用边界
--------

* ``0001`` 至 ``0050`` 视为已完成历史内容；
* 不启动逐题全量审查；
* 不因风格、结构、解释密度或公共规则升级主动回改历史 RST；
* 不主动搜索并修复历史题目的潜在问题；
* 只有用户明确指定某一道历史题需要修复时，才处理该题；
* 本规则从 ``0051`` 起完整约束新题生成、验证与合并。

发现分流
--------

每个在后续生成过程中发现的问题先分类，再决定处理范围。

A 类：公共规则问题
~~~~~~~~~~~~~~~~~~

包括结构、解释密度、注释风格、证明组织、检查顺序和常见语言风险提醒不足。

处理方式：

* 修改 ``docs/PROBLEM_TEMPLATE.rst``；
* 修改 ``docs/AUTOMATION_QUALITY_GATE.rst``；
* 修改 ``docs/SOLUTION_AND_TYPES_POLICY.rst``；
* 必要时修改 ``docs/RST_STYLE_GUIDE.rst``；
* 不回填 ``0001`` 至 ``0050``。

B 类：新题确定性缺陷
~~~~~~~~~~~~~~~~~~~~

包括：

* 算法返回错误结果、漏解、重复答案或不能终止；
* 代码无法编译、存在确定性运行错误或越界访问；
* C 存在未定义行为、错误容量、所有权或释放契约；
* Rust 无法通过借用检查、所有权转移错误或接口不匹配；
* R 存在 ``<-`` / ``<<-`` 作用域错误、错误引用语义或危险下标序列；
* Julia 存在一基索引错误、递减范围误用或原地接口语义错误；
* TypeScript / JavaScript 因 32 位位运算、整数精度或 ``undefined`` 判断产生错误；
* 复杂度与代码明确不一致；
* 正确性证明依赖不成立的前提；
* 题意、接口或返回格式被明确写错。

处理方式：当前新题不得合并；已经合并的新题使用独立 ``fix:`` PR 修复，并把根因写入
公共规则。修复不得顺带回改 ``0001`` 至 ``0050``。

C 类：证据不足
~~~~~~~~~~~~~~

无法确认题意、缺少运行环境、某种语言只能静态检查，或怀疑存在问题但尚未构造反例时：

* 不得宣称存在确定性错误；
* 不得宣称运行或编译通过；
* 明确记录验证范围和缺失证据；
* 新题未达到质量门时不得合并；
* 不扩大到历史题目检查。

后续题解强制检查
----------------

从 ``0051`` 起，每题至少检查：

#. 题意、接口、自建示例和关键约束一致；
#. 主算法满足约束，核心状态或不变量真实成立；
#. 正确性依据证明实际需要的合法性、完整性、无重复和终止性；
#. 时间复杂度、额外空间、递归栈、结果空间和输出复制成本区分清楚；
#. 十种语言实现同一个算法语义；
#. 辅助函数、导入、平台类型、返回结构和内存责任完整；
#. 数值、索引、字符单位、作用域、所有权、可变性和标准库 API 边界正确；
#. RST 标题、指令、缩进、链接、代码块和知识账本一致。

验证证据等级
------------

``运行验证``
   已在当前环境执行测试，并说明覆盖的正常、边界、随机或对拍用例。

``编译验证``
   已用对应编译器或类型检查器通过；编译通过不等于算法正确。

``静态验证``
   只检查接口、语法结构、索引、作用域、所有权或逻辑，不能写成“运行通过”。

``基准对拍``
   与独立、明显正确的基准实现比较；基准不能复用被测代码的核心逻辑。

高风险语言检查
--------------

C
~

* 分配容量必须由题目上界或动态增长规则证明；
* 返回二维数组时检查外层容量、每行容量、``returnSize`` 和 ``returnColumnSizes``；
* 明确输入是否被修改、谁释放返回内存、失败路径是否泄漏；
* 单独检查无符号长度相减、整数提升、空指针和零长度分配。

Rust
~~~~

* 检查所有权转移、``clone`` 的必要性、可变借用生命周期和 ``Option`` 处理；
* 不能用伪代码式接口掩盖无法通过借用检查的实现；
* 平台签名与辅助函数的所有权约定必须一致。

TypeScript / JavaScript
~~~~~~~~~~~~~~~~~~~~~~~

* 位运算会把 ``number`` 转为 32 位有符号整数；涉及 ``2^31`` 边界时使用算术方法；
* 区分 ``Map.get`` 的 ``undefined`` 与合法零值；
* 超过安全整数范围时不能假设 ``number`` 保持精确；
* 类型检查和运行验证分别记录。

Julia
~~~~~

* 明确零基算法坐标与一基数组位置的转换；
* ``a:b`` 在 ``a > b`` 时可能形成递减范围，空区间使用显式守卫；
* ``!`` 命名、原地修改、返回值和容器类型与题目接口一致；
* 检查整数除法、取模和切片是否改变算法语义。

R
~

* ``<-`` 修改当前调用环境，``<<-`` 搜索父环境；递归层局部变量不得误用 ``<<-``；
* 跨递归共享可变状态时优先使用显式 ``environment``；
* 避免用 ``1:n`` 表达可能为空的序列，使用 ``seq_len``、``seq_along`` 或守卫；
* 一基索引、写时复制和原地题接口需要明确说明。

复杂度与证明
------------

* 复杂度定义变量含义；
* 枚举、组合、排列和字符串构造题计入输出数量与复制成本；
* 区分算法额外空间、递归栈和返回结果空间；
* 平均、摊还和最坏复杂度不得混写；
* 正确性依据不能只复述循环；
* 贪心证明局部选择不损失最优解；
* 回溯证明搜索空间覆盖和去重规则。

防复发闭环
----------

每个确认根因至少落实到一个后续检查项：

#. 模板增加写作或验证提示；
#. 质量门增加完成判定；
#. 语言规则增加语义边界；
#. 知识账本登记需要持续提醒的高风险概念；
#. 后续同类题执行针对性测试或静态检查。

本文件只约束 ``0051`` 及之后的新内容，不自动触发历史题目的审查或修订。

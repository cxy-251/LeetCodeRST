阶段产物生命周期规则
====================

目的
----

本规则防止审查记录、临时计划、逐批 findings 和已被归并的规则长期堆积在活动目录。仓库主入口只保存当前
阶段真正需要执行的文件，历史证据统一进入 ``archive/``。

文件分类
--------

活动文件
~~~~~~~~

活动文件会直接影响下一轮工作，包括：

* ``AGENTS.md``、根 ``README.rst``；
* ``state/PROGRESS.toml``、``state/REVIEW_INDEX.toml``、知识账本；
* 当前阶段前向规则、质量门、模板和长期策略；
* 已完成题目正文与题目索引。

活动文件留在原目录，并保持引用路径有效。知识账本必须在 ``state/concepts/`` 直接保存有效数据，
不得依赖 ``archive/`` 才能解析。

阶段性中间文件
~~~~~~~~~~~~~~

阶段性文件只服务于尚未结束的工作，例如：

* ``state/reviews/NNNN-NNNN.toml``；
* ``docs/review-findings/NNNN-NNNN.rst``；
* 临时检查清单、迁移标记、草稿计划和一次性报告；
* 尚未完成归并的规则候选与范围目录。

阶段性文件只有在当前 ``PROGRESS`` 明确需要时才能进入仓库。任务完成后必须删除或归档，不能继续作为默认
读取入口。

归档产物
~~~~~~~~

已经完成且仍有追溯价值的内容移入 ``archive/``，包括：

* 已结束审查轮次的批次状态与详细 findings；
* 已被新规则替代的完整旧前向规则；
* 规则归并记录、历史目录和阶段总结；
* 后续历史题修复仍可能需要的证据。

归档文件保持原始内容，只更新 manifest，不在原文件内追加新结论。归档文件不得成为活动状态或知识账本的
必需数据源。

阶段结束动作
------------

每次规则归并、审查轮次结束或大型迁移完成时，同一个原子提交必须完成：

#. 生成当前阶段最终规则或正式产物；
#. 将已消费的批次记录和 findings 移入对应 ``archive`` 范围；
#. 删除临时标记、草稿和不再使用的中间文件；
#. 更新 ``AGENTS.md``、README、``PROGRESS``、``REVIEW_INDEX`` 和相关策略中的路径；
#. 创建或更新 archive manifest；
#. 检查活动目录中不存在指向已删除路径的引用；
#. 复查提交只包含正式产物、归档移动和必要入口更新。

保留与删除判断
--------------

* 能由正式产物完整推导、且没有独立证据价值的临时文件直接删除。
* 包含逐题证据、确定性问题、语言语义依据或 rule ID 来源的文件归档。
* 已被替代但仍可能用于历史追溯的规则全文归档；活动路径最多保留简短兼容指针。
* 构建缓存、日志、导出临时文件、一次性 marker 和未引用草稿不得进入 ``main``。
* Git 历史不能替代 archive manifest；manifest 负责说明归档内容和使用方式。

新批次约束
----------

新题生成通常不创建逐题中间报告。审查类工作可以在活动阶段创建批次证据，但必须在该审查轮次规则归并完成
时立即归档。任何新阶段开始前，质量门应确认上一个阶段的中间目录已经清空。

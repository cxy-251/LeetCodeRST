0051–0100 前向质量规则
=====================

适用范围
--------

本文件汇总从 ``0001`` 至当前已审查 RST 正文中提炼出的可执行规则，只约束 ``0051`` 至
``0100`` 的新题。历史题目不因本文件升级而回改。

证据边界
--------

* 规则必须来自完整题目 RST、十语言代码、证明和复杂度正文；
* PR 标题、提交信息、合并状态和自动报告不构成内容质量证据；
* 验证结果区分运行、编译、静态检查和基准对拍；
* 正文确认的必要守卫、导入或修复必须进入主代码块，代码后的补丁说明不能替代可执行实现。

题意、约束与平台接口
--------------------

#. 列出会影响实现的精确约束：长度下界与上界、数值范围、字符集合、输入合法性、结果顺序和是否允许修改输入。
#. 官方题目契约与主动支持的通用扩展分开；禁止用“通常”“常见”“似乎保证”代替精确约束。
#. 十语言对非空、正长度、等长和合法输入采用同一官方前提；个别语言的额外防御必须标记为适配器行为。
#. 公开函数名、参数类型、返回类型、返回结构和平台元数据必须与题目接口完全一致。
#. 内部可使用宽类型，最终返回前必须由精确约束证明窄化安全。
#. ``size_t``、``usize``、容器长度和边界位置转换到 ``int`` / ``i32`` 前，精确最大长度必须同时覆盖最大元素下标和末尾边界 ``n``。
#. 依赖非空、合法语法、固定字符集或 ``n`` 合法时，正文明确写成前提。
#. 非空断言、``unwrap``、``something``、``unreachable`` 和省略默认分支只能由精确前提支撑。
#. 平台节点类型、``Optional``、辅助构造器和访问函数直接定义、导入，或明确引用仓库统一接口。
#. 链表和图结构说明是否要求无环、节点互不相交、无共享后缀；共享节点会改变正确性时必须列为前提。
#. 有效前缀题同时定义返回长度、允许检查的前缀、尾部未定义语义、稳定性要求和底层容器是否缩短。
#. 二分函数明确返回命中下标、插入边界、末尾外位置或失败哨兵；边界坐标未经验证不得作为元素下标访问。

字符模型与字符串成本
--------------------

#. 字符串题先定义算法比较单位：字节、UTF-16 代码单元、Unicode 码点或字形簇。
#. 返回下标单位单独定义，并证明内部字节或代码单元坐标可正确映射到平台要求的坐标。
#. 十语言采用不同字符单位时，由题目精确字符域证明它们等价。
#. 按字节重排或切片后重新构造字符串时，证明不会拆散多字节编码。
#. ``[]byte``、``collect``、``strsplit``、``utf8ToInt``、切片、重新编码和返回子串复制计入复杂度。
#. 整串解码、正则编译、哈希构建和排序等预处理移出内层热循环，只执行必要次数。
#. 标准库 ``find``、``IndexOf`` 等 API 也必须确认返回的是字节、代码单元、码点还是其他坐标。

数值表达式与容量
----------------

#. 危险算术在运算前扩宽操作数，不能先在窄类型中溢出后再转换结果。
#. 数值安全覆盖整条表达式链：连续加法、乘法、取负、目标差值、绝对值、剪枝上下界、哨兵和最终窄化。
#. 特别检查最小有符号值取绝对值、平台 ``int`` 位宽和 TypeScript 位运算的 32 位转换。
#. ``Int``、``int``、``long`` 等平台相关宽度必须声明目标平台，或改用固定宽类型承载题目边界。
#. 数值宽度由精确输入上界推导，不使用“常见约束”“通常不会溢出”等表述。
#. 固定缓冲区容量由最大输出长度推导，并包含终止符、哨兵、列长度和其他元数据空间。
#. 元素数量乘元素大小、分支数乘积、单词长度乘单词数和矩阵尺寸乘积使用目标容量类型逐步检查溢出。
#. Catalan、排列和组合数量用于预分配、循环边界或索引前，检查公式中间乘积、除法顺序与类型转换。
#. C 的 ``malloc``、``calloc``、行分配和并行数组分配采用一致失败契约，并在首次解引用或写入前检查。
#. 多个相关缓冲区、哈希表和计数数组必须整体成功；任一失败时清理全部已分配状态。
#. C 的 ``realloc`` 使用临时指针；多个并行缓冲区全部成功后才提交新状态。

复杂度与输出
------------

#. 定义 ``n``、``m``、``d``、``P``、输出数量、单词长度 ``w`` 和唯一键数量 ``u`` 等变量。
#. 区分最坏、平均、期望和摊还复杂度；哈希题同时说明期望与最坏情况。
#. 区分算法工作空间、输入规范化空间、递归栈、结果空间和返回复制。
#. 排列、组合、枚举、分组和字符串构造计入完整输出字符或元素数量。
#. 返回索引数组、组合或字符串集合的输出空间单独写成 ``O(A)``、``O(P)`` 或完整载荷大小。
#. 结果追加按语言真实语义计费；R 禁止在大量输出循环中反复 ``c(result, value)``。
#. 可预知输出数量时优先精确预分配；不可预知时使用具有明确摊还追加语义的容器。
#. 抽象数据结构复杂度必须由目标语言具体表示支撑；写时复制列表实现的堆不能无证据沿用数组堆 ``O(log k)`` 更新。
#. 哈希空间不能只数键数量；拥有或复制字符串键时按 ``O(u*w)`` 计入键载荷。
#. 区分逻辑窗口或哈希操作次数与切片、哈希、比较实际读取的字符总量；逻辑 ``O(n)`` 可能对应字符工作 ``O(nw)``。
#. 固定输入域题目同时说明约束内常数界与推广模型下的输出敏感复杂度。
#. 整数逐位和倍增算法使用位数、表长或 ``O(log(|x| + 1))``，禁止让 ``x = 0`` 落入 ``log 0``。
#. 递归解法写出最坏深度，并与最大输入长度和目标运行时栈限制对应。
#. 原地抽象算法在 R 等复制型适配器中的真实复制成本单独报告，不能只写常数个局部变量。

证明质量
--------

#. 正确性依据证明算法决策，不只复述循环。
#. 二分查找覆盖区间形式、单调谓词、移动方向、排除安全性、返回语义、答案存在性和终止性。
#. lower bound、upper bound 或复用边界辅助函数时，参数名与调用点明确相等值被放在哪一侧。
#. 双指针证明被删除端点对应的整批候选为什么不可能更优或命中。
#. 原地压缩证明有效前缀只含应保留元素、没有遗漏、顺序性质和 ``write <= read`` 的覆盖安全。
#. 原地排列变换证明元素多重集不变、结果严格增大或减小、变化幅度最小或最大，以及无后继时的回绕分支。
#. 贪心使用交换论证、上界排除、单调性或规范表示语法证明局部选择。
#. 回溯证明状态含义、完整性、无重复、撤销恢复和终止性。
#. 动态规划证明状态充分、转移无遗漏以及初始化和遍历顺序。
#. 滑动窗口证明重置与收缩只排除不可能候选，并证明每个元素或块进入、离开次数上界。
#. 链表局部重连列出改写前后的边，证明组前、组内、组后连通、节点守恒且不会形成环。
#. 可能因边界不足而放弃的破坏性操作，先完成只读可行性探测，并证明失败路径保持输入不变。
#. 无边界递减扫描、``pop``、``unwrap`` 或非空断言前，紧邻代码证明满足条件的见证元素、哨兵或非空状态必然存在。
#. 哨兵栈说明初始化、每次弹出前非空、弹空后的恢复，以及哨兵不是普通数据下标。
#. 一个核心推导只完整出现一次；复现题只解释新增状态、边界或语言差异。

讲解与十语言实现一致
--------------------

#. 十语言实现同一问题语义，不要求逐行相同。
#. 正文宣称为主解法组成部分的剪枝、去重和优化必须在对应实现中出现。
#. 只在部分语言采用的优化标记为可选，并说明采用范围。
#. 某语言因所有权、借用、字符串、容器复制或运行时语义使用不同算法时，单独写状态、证明和复杂度。
#. 某语言无法表达平台原地接口而返回副本或复合对象时，明确标记为适配器，并单独说明复制和调用后语义。
#. 主代码块必须是文档最终认可的实现；禁止在代码后声明“工程实现还应添加”一个决定正确性的必要守卫。
#. 边界清单、证明、复杂度和代码使用同一个最终版本，不能各自描述不同实现。
#. 复杂度与证明覆盖实际代码，不以某个语言的优化外推其余语言。

导入、版本与辅助代码
--------------------

#. 每个标准库符号使用直接定义它的头文件、包、命名空间或 ``using``。
#. 禁止依赖传递性头文件或隐含导入。
#. 版本相关 API 声明最低版本，或改用本地兼容辅助函数；包括 ``clear``、``GetValueOrDefault`` 和标准优先队列。
#. 非平台辅助函数、比较器、状态对象和节点访问函数完整。
#. 堆比较器满足严格弱序或对应语言的顺序契约；相等键不得继续比较不支持排序的节点对象。
#. ``pop``、非空断言和类型断言由紧邻的非空不变量支撑。
#. 代码块依赖平台预置内容时，在语言标题或代码注释中明确说明。

失败路径
--------

#. 资源失败不得返回部分链表、部分组合或半成品数组。
#. 资源失败和不可达状态不得静默返回 ``false``、``0``、空数组、空字符串或 ``0.0`` 等合法答案。
#. 分配结果在首次写入前验证；已分配资源完整清理，或明确依赖平台保证分配成功并省略伪错误处理。
#. 返回数组的尺寸元数据、失败返回和调用者释放责任保持一致。
#. 输入保证合法时直接依赖前提，不增加只覆盖部分非法情况的伪校验。
#. 十语言失败契约允许按语言机制表达，但不能混淆失败与正常答案。

输入修改、所有权与节点生命周期
------------------------------

#. 排序、交换、移动、消费或原地修改输入时明确说明。
#. 原地数组题说明返回后底层长度不变、有效前缀范围和尾部不属于结果。
#. 原地排列题说明调用后旧排列不再存在，以及 R 等适配器返回新向量的差异。
#. 复用并重连输入节点时，明确调用后原入口、原拓扑和外部节点引用是否仍可使用。
#. Rust 的 ``take``、``clone``、移动和借用生命周期符合真实借用检查，并说明输入所有权是否被消费。
#. 链表删除、拼接、交换和重排说明节点由平台、调用方还是函数拥有。
#. C/C++ 的 ``free`` / ``delete`` 只在平台契约允许时执行；托管语言说明断链后的回收语义。
#. 局部重连在首次写入前保存仍需使用的后缀，避免覆盖后丢失节点。
#. 语言特化的两遍法、显式栈、递归所有权或复制方案单独说明其输入和资源影响。

高风险语言补充
--------------

C
~

* 二维返回检查外层容量、每行容量、``returnSize`` 和 ``returnColumnSizes``；
* ``malloc`` / ``calloc`` 在首次写入前检查，答案元数据与失败契约同步；
* 比较器避免减法溢出；
* 长度转换、无符号下溢、容量 ``n + 1``、乘法和并行扩容重点检查；
* 复合哈希状态的所有分配必须整体成功或整体清理。

C++
~~~

* ``size_t`` 与有符号下标保持一致；
* 窄化为 ``int`` 前由精确长度上界证明安全，并覆盖边界位置 ``n``；
* 检查迭代器失效、引用生命周期和比较器严格弱序；
* ``vector``、``swap``、``reverse`` 等标准库符号直接包含对应头文件。

Python
~~~~~~

* 切片、列表复制、闭包可变状态和递归深度计入真实成本；
* ``heapq`` 相等键需要序号或其他可比较字段，禁止回退比较节点对象；
* 大整数能力不能被外推为固定宽度语言安全。

Java 与 C#
~~~~~~~~~~

* 中间运算先提升到 ``long``；
* 集合、装箱、子串复制、递归和最低语言版本明确；
* 定长 ``n + 1`` 栈容量由精确上界支撑；
* ``PriorityQueue``、``GetValueOrDefault`` 等版本相关 API 声明目标运行时；
* ``import``、``using`` 或平台预置边界完整。

Rust
~~~~

* 通过真实借用检查；
* ``usize`` 转 ``i32`` 前证明最大合法边界 ``n`` 可表示；
* 无符号索引不能依赖递减到 ``-1``，使用显式分支或有符号控制坐标；
* 输入所有权被消费时明确说明；
* ``clone``、字节键复制和输出复制计入复杂度；
* 字节转 ``String`` 或按字节返回下标由精确 ASCII 约束证明有效。

Go
~~

* ``int`` 位宽不能默认为 64 位；
* ``[]byte``、切片底层数组共享和 ``append`` 成本明确；
* ``clear`` 等内建函数声明最低 Go 版本；
* 手写堆缩短切片时，长生命周期容器考虑清空已移除引用以避免对象滞留。

TypeScript / JavaScript
~~~~~~~~~~~~~~~~~~~~~~~

* 检查 ``number`` 安全整数范围和位运算 32 位转换；
* ``Map.get`` 的 ``undefined`` 与合法零值区分；
* 字符串下标是 UTF-16 代码单元坐标；
* ``pop`` 返回值被忽略时，仍由紧邻哨兵或非空不变量证明操作安全；
* 非空断言紧邻建立事实的条件，不能跨越可能改变结构的写操作；
* 使用 ``--strict``，类型检查与运行验证分开记录。

Julia
~~~~~

* 一基索引与零基算法坐标逐项转换；
* ``a:b`` 在 ``a > b`` 时的递减范围按循环真实起点显式守卫；只检查空输入不足以保护 ``2:n``；
* 正文发现的空串或短数组守卫必须并入主代码，不能仅在代码后给出建议；
* ``collect``、普通切片和字符串重构计入复制；
* 性能结论依赖具体容器时避免无必要的 ``Any`` 元素类型；
* 宽类型常量在目标类型中构造，宿主 ``Int`` 位宽前提明确。

R
~

* 局部变量使用 ``<-``，跨层共享状态优先使用 ``environment``；
* ``<<-`` 不代表向量、矩阵或列表原地修改；
* 普通 ``list`` 配合 ``<<-`` 实现频繁堆交换时，按写时复制重新分析复杂度，或改用明确引用语义结构；
* 可能为空或过短的序列使用 ``seq_len``、``seq_along`` 或按真实起点守卫；
* ``strsplit``、``utf8ToInt``、``substr``、向量扩展和写时复制计入复杂度；
* 无法提供原地数组接口时，将返回副本明确标为适配器；
* 大量结果使用预分配列表和索引写入。

单题完成判定
------------

新题只有同时满足以下条件才可计入完成：

#. 精确官方约束支撑全部代码假设，包括空输入、正长度、字符坐标、索引窄化和链表别名条件；
#. 公开接口与平台一致，二分返回语义和语言适配器差异已明确；
#. 十语言主代码完整、自洽且问题语义一致，必要修复已经合入代码；
#. 正确性证明覆盖真实决策、排列邻接、二分谓词、哨兵见证、有效前缀、滑动窗口排除、局部重连和失败不修改性质；
#. 数值、容量、首次写入前分配检查、失败和所有权路径闭合；
#. 复杂度包含具体容器、键载荷、字符工作、语言特有复制、输出和递归深度；
#. 文档承诺、边界说明与代码实际实现一致；
#. 导入、版本、比较器和辅助接口完整；
#. 验证证据描述准确；
#. RST、索引、进度和知识账本同步。

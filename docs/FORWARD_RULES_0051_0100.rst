0051–0100 前向质量规则
=====================

适用范围
--------

本文件汇总从 ``0001`` 至当前已审查 RST 正文中提炼出的可执行规则，只约束 ``0051`` 至
``0100`` 的新题。历史题目不因本文件升级而回改。

证据边界
--------

* 规则必须来自完整题目 RST、十语言代码、证明和复杂度正文；
* PR 标题、提交信息、合并状态和自动报告不构成内容质量证据；
* 验证结果区分运行、编译、静态检查和基准对拍。

题意、约束与平台接口
--------------------

#. 列出会影响实现的精确约束：长度下界与上界、数值范围、字符集合、输入合法性、结果顺序和是否允许修改输入。
#. 公开函数名、参数类型、返回类型、返回结构和平台元数据必须与题目接口完全一致。
#. 内部可使用宽类型，最终返回前必须由精确约束证明窄化安全。
#. 依赖非空、合法语法、固定字符集或 ``n`` 合法时，正文明确写成前提。
#. 非空断言、``unwrap``、``something``、``unreachable`` 和省略默认分支只能由精确前提支撑。
#. 平台节点类型、``Optional``、辅助构造器和访问函数直接定义、导入，或明确引用仓库统一接口。

字符模型与字符串成本
--------------------

#. 字符串题先定义算法单位：字节、UTF-16 代码单元、Unicode 码点或字形簇。
#. 十语言采用不同字符单位时，由题目精确字符域证明它们等价。
#. 按字节重排或切片后重新构造字符串时，证明不会拆散多字节编码。
#. ``[]byte``、``collect``、``strsplit``、``utf8ToInt``、切片、重新编码和返回子串复制计入复杂度。
#. 整串解码、正则编译、哈希构建和排序等预处理移出内层热循环，只执行必要次数。

数值表达式与容量
----------------

#. 危险算术在运算前扩宽操作数，不能先在窄类型中溢出后再转换结果。
#. 数值安全覆盖整条表达式链：连续加法、乘法、取负、目标差值、绝对值、剪枝上下界、哨兵和最终窄化。
#. 特别检查最小有符号值取绝对值、平台 ``int`` 位宽和 TypeScript 位运算的 32 位转换。
#. 数值宽度由精确输入上界推导，不使用“常见约束”“通常不会溢出”等表述。
#. 固定缓冲区容量由最大输出长度推导，并包含终止符、列长度和其他元数据空间。
#. 元素数量乘元素大小、分支数乘积和矩阵尺寸乘积使用目标容量类型逐步检查溢出。
#. C 的 ``malloc``、``calloc``、行分配和并行数组分配采用一致失败契约。
#. C 的 ``realloc`` 使用临时指针；多个并行缓冲区全部成功后才提交新状态。

复杂度与输出
------------

#. 定义 ``n``、``m``、``d``、``P``、输出数量等变量。
#. 区分最坏、平均、期望和摊还复杂度；哈希题同时说明期望与最坏情况。
#. 区分算法工作空间、输入规范化空间、递归栈、结果空间和返回复制。
#. 排列、组合、枚举、分组和字符串构造计入完整输出字符或元素数量。
#. 结果追加按语言真实语义计费；R 禁止在大量输出循环中反复 ``c(result, value)``。
#. 可预知输出数量时优先精确预分配；不可预知时使用具有明确摊还追加语义的容器。
#. 固定输入域题目同时说明约束内常数界与推广模型下的输出敏感复杂度。
#. 整数逐位算法使用位数 ``d``，或写 ``O(log(|x| + 1))``。
#. 递归解法写出最坏深度，并与最大输入长度和目标运行时栈限制对应。

证明质量
--------

#. 正确性依据证明算法决策，不只复述循环。
#. 二分查找覆盖搜索区间、移动方向、排除安全性、答案存在性和终止性。
#. 双指针证明被删除端点对应的整批候选为什么不可能更优或命中。
#. 贪心使用交换论证、上界排除、单调性或规范表示语法证明局部选择。
#. 回溯证明状态含义、完整性、无重复、撤销恢复和终止性。
#. 动态规划证明状态充分、转移无遗漏以及初始化和遍历顺序。
#. 一个核心推导只完整出现一次；复现题只解释新增状态、边界或语言差异。

讲解与十语言实现一致
--------------------

#. 十语言实现同一问题语义，不要求逐行相同。
#. 正文宣称为主解法组成部分的剪枝、去重和优化必须在对应实现中出现。
#. 只在部分语言采用的优化标记为可选，并说明采用范围。
#. 某语言因所有权、借用、字符串或运行时语义使用不同算法时，单独写状态、证明和复杂度。
#. 复杂度与证明覆盖实际代码，不以某个语言的优化外推其余语言。

导入、版本与辅助代码
--------------------

#. 每个标准库符号使用直接定义它的头文件、包、命名空间或 ``using``。
#. 禁止依赖传递性头文件或隐含导入。
#. 版本相关 API 声明最低版本，或改用本地兼容辅助函数。
#. 非平台辅助函数、比较器、状态对象和节点访问函数完整。
#. 代码块依赖平台预置内容时，在语言标题或代码注释中明确说明。

失败路径
--------

#. 资源失败不得返回部分链表、部分组合或半成品数组。
#. 资源失败和不可达状态不得静默返回 ``false``、``0``、空数组、空字符串或 ``0.0`` 等合法答案。
#. 已分配资源完整清理，或明确依赖平台保证分配成功并省略伪错误处理。
#. 输入保证合法时直接依赖前提，不增加只覆盖部分非法情况的伪校验。
#. 十语言失败契约允许按语言机制表达，但不能混淆失败与正常答案。

输入修改、所有权与节点生命周期
------------------------------

#. 排序、交换、移动、消费或原地修改输入时明确说明。
#. Rust 的 ``take``、``clone``、移动和借用生命周期符合真实借用检查。
#. 链表删除、拼接、交换和重排说明节点由平台、调用方还是函数拥有。
#. C/C++ 的 ``free`` / ``delete`` 只在平台契约允许时执行；托管语言说明断链后的回收语义。
#. 语言特化的两遍法、显式栈或复制方案单独说明其输入和资源影响。

高风险语言补充
--------------

C
~

* 二维返回检查外层容量、每行容量、``returnSize`` 和 ``returnColumnSizes``；
* 比较器避免减法溢出；
* 长度转换、无符号下溢、乘法和并行扩容重点检查。

C++
~~~

* ``size_t`` 与有符号下标保持一致；
* 检查迭代器失效、引用生命周期和比较器严格弱序；
* 标准库符号直接包含对应头文件。

Python
~~~~~~

* 切片、列表复制、闭包可变状态和递归深度计入真实成本；
* 大整数能力不能被外推为固定宽度语言安全。

Java 与 C#
~~~~~~~~~~

* 中间运算先提升到 ``long``；
* 集合、装箱、子串复制、递归和最低语言版本明确；
* ``import``、``using`` 或平台预置边界完整。

Rust
~~~~

* 通过真实借用检查；
* 输入所有权被消费时明确说明；
* ``clone`` 和输出复制计入复杂度；
* 字节转 ``String`` 由精确 ASCII 约束证明有效。

Go
~~

* ``int`` 位宽不能默认为 64 位；
* ``[]byte``、切片底层数组共享和 ``append`` 成本明确；
* 版本相关预声明函数说明 Go 版本。

TypeScript / JavaScript
~~~~~~~~~~~~~~~~~~~~~~~

* 检查 ``number`` 安全整数范围和位运算 32 位转换；
* ``Map.get`` 的 ``undefined`` 与合法零值区分；
* 使用 ``--strict``，类型检查与运行验证分开记录。

Julia
~~~~~

* 一基索引与零基算法坐标逐项转换；
* ``a:b`` 在 ``a > b`` 时的递减范围显式守卫；
* ``collect``、普通切片和字符串重构计入复制；
* 宽类型常量在目标类型中构造。

R
~

* 局部变量使用 ``<-``，跨层共享状态优先使用 ``environment``；
* ``<<-`` 不代表向量、矩阵或列表原地修改；
* 可能为空的序列使用 ``seq_len``、``seq_along`` 或守卫；
* ``strsplit``、``utf8ToInt``、向量扩展和写时复制计入复杂度；
* 大量结果使用预分配列表和索引写入。

单题完成判定
------------

新题只有同时满足以下条件才可计入完成：

#. 精确约束支撑全部代码假设；
#. 公开接口与平台一致；
#. 十语言代码完整且问题语义一致；
#. 正确性证明覆盖真实决策；
#. 数值、容量、失败和所有权路径闭合；
#. 复杂度包含语言特有复制、输出和递归深度；
#. 文档承诺与代码实际优化一致；
#. 导入、版本和辅助接口完整；
#. 验证证据描述准确；
#. RST、索引、进度和知识账本同步。

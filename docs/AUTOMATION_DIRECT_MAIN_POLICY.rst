自动任务固定分支批次策略
========================

兼容说明
--------

本文件保留原路径 ``AUTOMATION_DIRECT_MAIN_POLICY.rst``，供既有任务继续读取。实际策略复用
单一固定分支，通过一个 PR 完成一轮连续题号批次，再 squash merge 到 ``main``。

规则优先级
----------

本规则只适用于用户明确授权的 LeetCode 定时自动任务，并与
``docs/AUTOMATION_QUALITY_GATE.rst`` 共同构成自动任务的最高执行规则。自动任务遇到
``AGENTS.md`` 中“直接提交 main”或其他批次规则时，以本文件的“难度预算、固定分支、
单 PR”规则为准。普通人工协作继续遵守 ``AGENTS.md``。

批次预算
--------

每轮从最新 ``state/PROGRESS.toml`` 的 ``next_problem`` 开始，严格按题号连续处理：

* Easy 计 1 分，Medium 计 2 分，Hard 计 4 分；
* 每轮最多处理 3 道题；
* 优先让总难度达到 4 至 6 分；
* 加入下一题后若总分超过 6，则在当前题结束批次；
* 同一批次禁止包含两道 Hard；
* 若连续三道都是 Easy，允许以 3 分结束；
* Premium 或题意无法可靠确认时，按仓库规则登记跳过或阻塞，不猜测题意。

质量门按每道题分别执行。若批次尾部题目无法达到质量门，必须从尾部缩小批次，只提交所有
已经完整通过质量门的连续前缀；不得提交半成品，也不得跳过中间题继续后面的题。

核心原则
--------

* 永远只使用固定分支 ``automation/leetcode-current``；
* 禁止创建带题号、时间戳、批次号或随机后缀的新分支；
* 同一时刻最多存在一个由该任务创建的开放 PR；
* 每轮只创建一个非 Draft PR，并只执行一次 squash merge；
* RST 教学质量优先于难度积分、题量和运行时间；
* 任一纳入批次的题目未达到质量门时，不得把该题登记为完成。

开始前同步
----------

每轮开始时：

#. 读取最新 ``main`` 和 ``state/PROGRESS.toml``；
#. 检查 ``automation/leetcode-current`` 是否存在；
#. 若存在，将该分支重置到最新 ``main``；
#. 若不存在，从最新 ``main`` 创建该固定分支；
#. 若该固定分支仍有未关闭 PR，优先恢复并完成原 PR，不得创建其他分支或 PR；
#. 根据最新题号和难度计算本轮候选批次，最多三题。

批次提交范围
------------

提交前一次性准备并检查：

#. 本批次所有连续题目的完整 RST；
#. 涉及的范围目录 ``README.rst``；
#. 根目录 ``README.rst``；
#. ``state/PROGRESS.toml``；
#. ``state/CONCEPT_LEDGER.toml``。

所有文件必须彼此一致。不得先提交部分题目，再等待后续任务补索引或状态。
``PROGRESS.toml`` 不得记录本轮提交自身 SHA，避免为了回填 SHA 创建第二个提交或 PR。

PR 与合并
---------

#. 只向 ``automation/leetcode-current`` 写入本批次相关文件；
#. 所有题目和状态文件组成一个提交；
#. 创建一个非 Draft PR，目标分支为 ``main``；
#. 检查 PR 题号连续、题数不超过 3、难度预算符合规则；
#. 对批次中的每道题分别执行质量检查；
#. 全部通过后执行一次 squash merge；
#. 禁止创建第二个 ``finalize``、``state`` 或 ``fixup`` 分支和 PR。

并发更新恢复
------------

合并前必须再次读取最新 ``main``。若人工任务或另一轮自动任务已经推进主分支：

#. 重新读取最新 ``next_problem``；
#. 放弃已经被 ``main`` 完成的重叠题目；
#. 从新的 ``next_problem`` 重新计算连续难度批次；
#. 在同一个固定分支上，以最新 ``main`` 为父提交原子重建；
#. 强制更新原分支并复用原 PR；
#. 禁止创建第二个分支或第二个 PR。

写入后验证
----------

合并后重新读取最新 ``main``，确认：

* 本批次题目全部存在且题号连续；
* 本轮新增 1 至 3 道完整题目，没有半成品；
* ``next_problem`` 恰好推进到批次末题之后；
* ``completed_count`` 和 ``completed_ranges`` 正确；
* 根 README、范围索引和知识账本已经同步；
* 本轮最多使用 ``automation/leetcode-current`` 一个分支；
* 本轮只有一个内容 PR，且 ``merged = true``。

失败恢复
--------

任一验证失败都必须如实报告，并只结束当前这一轮。不得自行暂停、禁用、删除或修改定时任务，
也不得修改下一次调度时间。若尚未写入仓库，则保持 ``main`` 不变并在下一小时从同一
``next_problem`` 重试；若存在唯一开放 PR，则下一小时优先恢复和完成该 PR。
只有用户明确要求时，才能暂停或禁用小时任务。

自动任务直接主分支策略
======================

适用范围
--------

本规则只适用于用户明确授权的 LeetCode 定时自动任务。普通人工协作继续遵守
``AGENTS.md`` 中的 Git 规则。

核心原则
--------

* 每次运行只处理 ``state/PROGRESS.toml`` 中 ``next_problem`` 指向的一道题；
* 不按难度积分组批，不提前编写后续题目；
* 不创建分支，不创建 PR，不保留 Draft；
* RST 教学质量优先于运行时间和产量；
* 0001 至 0006 是当前教学密度和完整度基准；
* 当前题未达到 ``docs/AUTOMATION_QUALITY_GATE.rst`` 时，本轮不得写入仓库。

写入前准备
----------

自动任务必须先在写入仓库之前完整准备并检查：

#. 当前题的完整 RST；
#. 当前范围目录的 ``README.rst``；
#. 根目录 ``README.rst`` 中的进度说明；
#. ``state/PROGRESS.toml``；
#. ``state/CONCEPT_LEDGER.toml``。

所有文件必须彼此一致。不得先提交题目文件，再等待后续运行补索引或状态。

原子提交
--------

写入 ``main`` 时必须形成一个 Git 提交：

#. 读取最新 ``main`` 提交作为父提交；
#. 为本轮所有新增或修改文件创建 blob；
#. 基于最新 ``main`` 的 tree 创建新 tree；
#. 创建一个包含全部文件的 commit；
#. 仅在父提交仍然是当前 ``main`` 时，将 ``main`` 快进到新 commit。

优先使用 GitHub 的 ``create_blob``、``create_tree``、``create_commit`` 和
``update_ref`` 操作。禁止通过多次独立 ``create_file`` 或 ``update_file`` 提交把
一个题目拆成多个非原子提交。

并发与失败
----------

* 写入前再次确认 ``main`` 和开始时读取的父提交相同；
* 若 ``main`` 已变化，本轮放弃写入，下次重新从最新状态开始；
* 若无法创建原子提交，本轮不写任何文件；
* 若正文、十语言代码、索引或状态任一项不完整，本轮不写任何文件；
* 不允许留下临时分支、Draft PR 或只包含部分文件的提交；
* 失败时报告具体阻塞，不得宣称题目完成。

写入后验证
----------

提交后重新读取最新 ``main``，确认：

* 当前题文件存在；
* 只新增了当前一道题；
* ``next_problem`` 恰好增加一；
* 完成数量和范围正确；
* 根 README、范围索引和知识账本已经同步；
* 本轮没有创建新分支或 PR。

任一验证失败都必须报告异常，并暂停后续自动运行，等待修复。

对话驱动直接 main 策略
======================

兼容说明
--------

本文件保留原路径 ``AUTOMATION_DIRECT_MAIN_POLICY.rst``，避免旧 README、历史记录和交接说明失效。
文件名中的 ``AUTOMATION`` 仅是历史兼容名称；仓库已经停止 LeetCode 定时任务和无人值守执行。

唯一执行入口
------------

LeetCode 题解生成、逐题审查、规则提炼和缺陷修复，只能由用户在当前对话中明确发起。

* 不设置小时任务、深夜任务或其他周期任务；
* 不在用户未发消息时继续生成或审查；
* 不进行后台执行、条件监控或自动重试；
* 每次工作都在当前回复周期内完成，并立即报告实际结果；
* 仓库文件仍是跨对话的唯一共享状态。

规则优先级
----------

本文件是 Git 执行方式的最高规则。内容质量继续遵守：

* ``AGENTS.md``；
* ``docs/AUTOMATION_QUALITY_GATE.rst``；
* ``docs/FORWARD_RULES_0051_0100.rst``；
* 当前阶段对应的审查记录和状态文件。

历史文件中关于定时任务、固定自动化分支、自动 PR、下一小时重试和无人值守合并的说明全部失效。

Git 规则
--------

默认由对话直接修改 ``main``：

* 不创建题号分支、批次分支、时间戳分支、审查分支或 ``finalize`` 分支；
* 不创建 PR，除非用户在当前对话中明确要求使用 PR；
* 一轮工作形成一个可理解的原子提交；
* 提交前一次性准备全部目标文件，避免用第二个提交补索引或状态；
* ``PROGRESS.toml`` 不记录本轮提交自身 SHA；
* 写入前重新读取最新 ``main``，发现主分支变化时按最新状态重建本轮内容；
* 不复用任何旧 ``automation/*`` 或 ``manual/*`` 分支作为工作状态。

对话审查阶段
------------

当 ``phase = "review_extracting_rules"`` 时：

#. 从 ``state/REVIEW_INDEX.toml`` 的 ``review.current`` 开始；
#. 按用户要求或默认五题一批，完整读取每道题的正文和十语言代码；
#. 结论只来自实际 RST 内容，不以 PR、提交说明或历史自动报告代替；
#. 只更新批次审查记录、前向规则、索引、README 和状态；
#. 不修改 ``0001`` 至 ``0050`` 的历史题目 RST，除非用户明确指定；
#. 审查完成前不生成 ``0051``，也不推进 ``next_problem``；
#. 直接把完整批次作为一个提交写入 ``main``。

对话生成阶段
------------

当规则提炼完成并进入新题生成阶段时：

#. 从最新 ``next_problem`` 开始连续处理；
#. 默认沿用 Easy=1、Medium=2、Hard=4 的难度预算，每批最多三题、目标总分 4 至 6；
#. 每道题独立通过质量门，未完成题不得推进状态；
#. 同步题目 RST、范围 README、根 README、``PROGRESS.toml`` 和 ``CONCEPT_LEDGER.toml``；
#. 所有目标文件作为一个提交直接写入 ``main``；
#. 合并后发现缺陷时，由下一次用户对话明确发起修复，不自动创建修补任务。

写入前检查
----------

每轮写入前确认：

* 用户已经在当前对话中明确要求执行；
* 没有开放的旧自动化 PR 会与本轮重叠；
* 本轮范围从最新状态文件推导；
* 所有目标文件彼此一致；
* 质量检查已经覆盖实际代码和正文；
* 本轮不会创建新分支或 PR。

写入后验证
----------

写入 ``main`` 后重新读取相关文件，确认：

* 提交确实进入 ``main``；
* 题号、审查范围或修复范围准确；
* README、索引、进度和知识账本一致；
* 没有把半成品登记为完成；
* 没有创建新的工作分支或 PR；
* 下一步只会在用户再次发起对话后执行。

失败处理
--------

任一验证失败都必须在当前对话中如实报告。不得创建定时重试、后台重试、备用分支或第二个补状态提交。
无法安全完成时保持 ``main`` 不变，等待用户下一次明确指令。

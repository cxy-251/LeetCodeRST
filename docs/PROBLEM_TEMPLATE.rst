主解法：名称
------------

思路
~~~~

解释为什么采用该方法，以及状态如何变化。不要只复述代码步骤。

状态定义与核心不变量
~~~~~~~~~~~~~~~~~~~~

明确每个关键变量、容器或递归参数表示什么。简单题可以缩短，不能让代码中的核心状态只靠变量名猜测。

正确性依据
~~~~~~~~~~

根据算法实际需要证明：

* 状态或不变量为什么持续成立；
* 指针移动、候选排除、剪枝或贪心选择为什么安全；
* 搜索是否完整、是否会重复、是否能终止；
* 最终返回条件为什么等价于题目目标。

不能只把代码流程改写成自然语言。简单题可以与“思路”合并，但判断依据不能消失。

复杂度
~~~~~~

* 定义 ``n``、``m``、``k``、``U`` 等变量；
* 时间复杂度：``O(...)``；
* 算法额外空间：``O(...)``；
* 递归栈：``O(...)``，没有递归时删除；
* 返回结果空间：``O(...)``，结果不计入额外空间时必须明确；
* 排列、组合、枚举和字符串构造题必须计入输出数量与复制成本；
* 区分最坏、平均和摊还复杂度，不能混写。

核心语言实现
~~~~~~~~~~~~

语言顺序固定为：C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R。

十种语言必须实现同一个主算法语义。可以为所有权、索引和平台接口调整数据表示，不能悄悄换成
不同复杂度或无法证明等价的算法。

语言语法、标准库 API 和类型语义的解释写在对应代码块内。短解释使用行尾注释；较长解释放到
目标代码上一行。代码优先不超过 88 个显示列，任何行不超过 100 个显示列。

每个语言代码块还要检查：

* 非平台辅助函数和必要导入是否完整；
* 输入是否被修改、返回结构和结果顺序是否与正文一致；
* 固定宽度整数、索引、字符单位、作用域、所有权和内存责任；
* 保存结果时是否复制了仍会继续变化的路径、数组或切片；
* 代码是否可以在声明的 LeetCode 接口或等价独立函数环境中理解。

工程写法：标准库方法
--------------------

只有现成轮子能够自然解决问题，或能展示实际开发写法时保留。

* 说明使用了什么 API；
* 在代码注释中说明复杂度和前提；
* 若 API 隐藏了本题核心算法，主解法仍需要展示教学写法；
* 工程写法通常不需要重复 10 种语言。

对照解法：名称
--------------

只在复杂度、数据结构、状态表示或算法演进存在实质差异时保留。

通常提供：

* 方法思路；
* 与主解法的差异；
* 复杂度；
* 伪代码或 1 至 2 种代表语言。

只有对照解法本身也是核心学习目标时，才提供完整 10 种语言实现。

验证计划与证据
--------------

写题时先确定需要验证的风险，不在完成后只跑一个示例。

* 正常用例：覆盖题目主路径；
* 边界用例：覆盖空输入、重复值、极值、无解或单元素等当前风险；
* 基准对拍：存在简单独立基准时，用随机或穷举输入比较；
* 编译验证：编译型语言尽量启用严格警告或类型检查；
* 静态验证：缺少运行时时只声明检查过的接口、索引、作用域或所有权范围。

最终报告必须准确使用“运行验证”“编译验证”“静态验证”“基准对拍”，不能把静态检查写成运行通过。

关联题目规则
============

目的
----

“关联题目”用于帮助读者迁移已经学过的结构，不用于记录题号相邻关系，也不用于罗列所有同标签题目。

保留条件
--------

只有满足下列至少一项时才建立关联：

* 使用相同的核心算法或数据结构；
* 维护相同或演进后的不变量；
* 前一题的方法可以直接迁移到后一题；
* 后一题是前一题的限制变化、复杂度升级或一般化；
* 存在相同且重要的语言语义或 API 风险。

“都使用循环”“都保存状态”“题号相邻”“都属于字符串题”不构成充分关联。

数量上限
--------

每道题的“关联题目”最多保留 5 个，通常控制在 1 至 3 个。

选择顺序：

#. 算法与不变量最接近；
#. 能形成明确难度阶梯；
#. 对当前题的复习价值最高；
#. 语言实现存在可迁移的关键差异。

没有强关联时，整节直接省略。不得为了模板完整制造弱关联。

双向回填
--------

按题号生成时，只能链接已经存在的题目。后续出现更强关联题时：

#. 新题链接旧题；
#. 旧题回填新题；
#. 若已达到上限，删除教学价值最低的旧链接。

专题索引
--------

大量同类题目不在单题末尾展开。后续通过独立专题索引维护完整集合，例如：

* 哈希表题目索引；
* 滑动窗口题目索引；
* 链表题目索引；
* 动态规划题目索引。

单题只保留最值得直接跳转的少量链接，专题索引负责完整导航。

链接说明
--------

每条链接必须用一句话说明真实关系，不能只写题名。例如：

.. code-block:: rst

   * `0001. Two Sum <0001-two-sum.rst>`_：两题都维护“元素到位置”的哈希映射，
     但本题还需要保证窗口左边界单调移动。

解法选择、标准库与类型边界
==========================

文件职责
--------

本文件只规定如何选择解法、何时使用标准库、如何处理平台类型和语言适配器。数值、容量、字符串、
失败路径和十语言高风险检查统一执行 ``docs/FORWARD_RULES_0051_0100.rst``，不在这里重复整套规则。

主解法
------

每道题选择一个主解法。主解法在正确性、复杂度、可读性和跨语言可实现性之间取得平衡，并提供
C、C++、Python、Java、Rust、Go、TypeScript、C#、Julia、R 十语言完整实现。

主解法需要讲清：

* 问题抽象；
* 核心状态或不变量；
* 正确性依据；
* 时间、空间和输出成本；
* 关键边界；
* 各语言真实差异。

十语言实现同一问题语义。语言的所有权、索引、字符表示或平台接口需要不同控制流时，单独解释状态、
证明和复杂度，不把语言特化实现伪装成逐行翻译。

对照解法
--------

只有存在实质教学差异时保留：

* 时间或空间复杂度改变；
* 数据结构或状态表示改变；
* 算法从暴力演进到优化；
* 递归、动态规划、贪心或图模型之间发生转换；
* 某语言存在真正不同的惯用实现。

对照解法通常给出思路、差异、复杂度和少量代表代码。只有它本身也是核心学习目标时，才提供十语言实现。

标准库
------

优先使用可靠、常见的标准库容器和算法，并说明：

* API 语义；
* 复杂度；
* 当前使用依赖的前提；
* 版本或运行时要求；
* 容易误解的边界。

标准库完全隐藏题目核心算法时，采用双轨表达：

``工程写法``
   展示实际开发中可以使用的标准库方案。

``教学写法``
   展开本题需要理解的状态和算法过程，承担主要证明与十语言实现。

只有题目目标就是实现某种结构，或标准库无法满足题意、复杂度或教学目标时，才手写通用队列、堆、
哈希表等基础设施。

平台类型
--------

LeetCode 提供的 ``ListNode``、``TreeNode``、``Node`` 等类型不在每道题重复定义。

首次遇到某种类型时：

* 简要说明字段、引用关系和可变性；
* 必要时使用 Mermaid 展示结构；
* 在代码旁注明由平台提供；
* 将约定登记到 ``state/CONCEPT_LEDGER.toml``。

Julia 与 R 使用仓库统一表示：

* Julia 以 ``mutable struct`` 表达需要引用语义的可变节点；
* R 以 ``environment`` 表达需要引用语义的可变节点；
* 后续题目复用约定，只解释当前题的新差异。

题目专属的 Trie、并查集、线段树节点和状态对象在当前题中完整定义。

代码独立性
----------

代码以 LeetCode 可提交接口或等价独立函数为目标。可以省略平台已经提供的基础类型，不能省略影响算法
理解的状态、辅助函数、比较器、哈希键和题目专属结构。

每种语言说明：

* 必要导入和最低版本；
* 输入是否被排序、交换、消费或原地修改；
* 返回顺序、返回结构和适配器差异；
* 内存、资源和返回对象由谁持有；
* 平台接口与正文是否一致。

语言适配器
----------

某种语言无法逐字表达平台接口时，可以使用适配器。例如 R 的值语义可能要求返回修改后的向量或矩阵。
适配器必须明确：

* 与平台接口的差异；
* 调用者如何获取结果；
* 是否产生输入或返回副本；
* 复杂度和所有权变化；
* 它与主算法语义为什么等价。

输入修改与所有权
----------------

排序、交换、链表重连、节点删除和原地矩阵操作都说明调用后状态：

* 原输入是否仍保持原顺序或拓扑；
* 调用者持有的旧引用是否仍可使用；
* Rust 输入是否被移动、借用或消费；
* C/C++ 节点是否由函数释放；
* 托管语言中的断链对象如何进入回收范围；
* 保存到结果中的路径、数组和切片是否拥有独立快照。

语言语义要点
------------

以下内容只列职责边界，完整检查见最终前向规则。

C
~

使用明确的平台签名、容量类型和返回所有权。动态结果的外层数组、每行、列长度和失败清理形成完整契约。

C++
~~~

明确有符号索引与 ``size_t`` 转换、迭代器和引用生命周期、比较器顺序契约以及输入原地修改。

Python
~~~~~~

计算切片、浅拷贝、可变对象共享、闭包状态和递归深度的真实成本。

Java 与 C#
~~~~~~~~~~

危险中间运算在运算前提升到宽类型，说明集合、装箱、子串复制、递归和对象字段生命周期。

Rust
~~~~

代码符合真实借用检查。``take``、``clone``、移动、借用、``Option`` 和返回快照与正文一致。

Go
~~

区分切片描述符复制和底层数组共享，说明 ``append``、字符串字节/码点和平台 ``int`` 宽度。

TypeScript / JavaScript
~~~~~~~~~~~~~~~~~~~~~~~

检查 ``number`` 安全整数、位运算 32 位转换、``undefined``、UTF-16 坐标和严格类型检查。

Julia
~~~~~

零基算法坐标逐项转换为一基位置。``a:b`` 是步长 ``+1`` 的 ``UnitRange``，当 ``a>b`` 时为空；
递减遍历使用显式负步长，例如 ``n:-1:1``。说明普通切片、``view``、原地 ``!`` 接口和宿主 ``Int``
宽度。

R
~

区分当前环境 ``<-``、父绑定 ``<<-`` 和显式 ``environment``。可能为空的迭代使用 ``seq_len``、
``seq_along`` 或明确边界；写时复制、返回副本和向量扩展计入成本。

复杂度表达
----------

复杂度与实际代码一致：

* 定义变量；
* 区分最坏、平均、期望和摊还；
* 计入排序、哈希、字符转换、重复扫描和标准库调用；
* 分开算法状态、输入规范化、递归栈、输出载荷和返回复制；
* 某语言因所有权或值语义改变成本时，单独说明。

历史题处理
----------

``0001`` 至 ``0050`` 的审查发现默认只用于前向规则。用户明确指定某一道历史题需要修改时，再执行该题
的独立修复流程。详细边界见 ``docs/REVIEW_AND_PREVENTION_POLICY.rst``。

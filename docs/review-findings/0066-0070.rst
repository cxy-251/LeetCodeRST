0066. Plus One
--------------

正向样本
~~~~~~~~

从最低位向左扫描的进位不变量完整：连续 ``9`` 后缀归零，首个非 ``9`` 数字吸收唯一进位；只有全
``9`` 输入需要扩展为 ``n+1`` 位。C 的容量和失败返回可区分，其他语言也明确建立返回快照。

结果快照与所有权消费
~~~~~~~~~~~~~~~~~~~~

C++、Python、Java、Go、TypeScript、C#、Julia 和 R 的输入在调用后仍可被调用者观察，因此复制结果能够
提供清晰的只读输入契约。Rust 的参数类型是按值接收 ``Vec<i32>``，调用者已经失去该向量的所有权；
实现仍然执行 ``digits.clone()``，会让原向量与结果向量在函数内部同时存在。

这不是正确性错误，渐进复杂度仍为 ``O(n)``。它说明“返回独立结果”需要结合语言调用模型解释：

* 借用或共享输入时，修改前应复制；
* 独占消费输入时，可以直接复用其缓冲区作为结果；
* 若规范要求内部也保留原值，才需要额外克隆；
* 峰值空间应记录输入与结果是否同时存活。

前向规则
~~~~~~~~

* 输入不变性以调用者可观察状态定义，不要求所有权语言机械复制已经被消费的容器；
* 输出载荷、算法工作空间和输入/结果峰值并存分别报告；
* 只有全进位分支需要前插或扩容时，仍按真实元素移动成本计入最坏时间；
* 原地版本与快照版本必须明确不同接口契约。

0067. Add Binary
----------------

正向样本
~~~~~~~~

两个字符串从最低位对齐，缺失高位按零处理；``total`` 最大为 ``3``，余数与进位转移安全。结果长度
上界 ``max(m,n)+1`` 同时支撑 C 终止符、预分配容量和末端写入实现。

输出构造的峰值空间
~~~~~~~~~~~~~~~~~~

各语言都属于 ``O(k)``，但峰值对象不同：

* C、C++、Rust、Go 和 Julia 可以在可变字节缓冲区中反转，再把该缓冲区作为或转换为结果；
* Java ``StringBuilder.toString``、C# ``new string``、Python/TypeScript 的连接通常会创建最终字符串；
* R 同时物化两个输入码点向量和固定结果缓冲区；
* Julia ``codeunits`` 是视图，不属于输入复制。

因此只写 ``O(k)`` 不足以解释工程资源；审查还应说明临时缓冲与最终不可变字符串是否在峰值时同时存在。

版本依赖
~~~~~~~~

Go 实现使用 Go 1.21 引入的预声明 ``max``，正文已经明确版本。语言标准库或预声明 API 具有最低版本时，
代码块、验证环境和兼容性说明必须一致；否则算法正确也可能无法编译。

前向规则
~~~~~~~~

* 结果容量上界同时覆盖字符载荷、终止符和可选最高位；
* 区分缓冲区原地反转、所有权采用、冻结复制和字符串连接的峰值空间；
* 语言版本门槛属于可编译性契约，必须在代码说明与验证环境中同时记录；
* ASCII 字节扫描必须由输入字符域支撑。

0068. Text Justification
------------------------

正向样本
~~~~~~~~

最大装行贪心由题目“每行尽量容纳最多单词”的要求唯一确定。普通行使用商余分配，前 ``extra`` 个间隔
多一个空格；末行和单词独占行统一左对齐。C 对多行结果采用事务式失败清理。

输出敏感复杂度
~~~~~~~~~~~~~~

每条输出行必须实际写出 ``maxWidth`` 个字符，因此任何实现的时间至少为
``Omega(L * maxWidth)``。正文把输入单词字符 ``S`` 与固定宽输出载荷分开计入，避免把大量补空格隐藏
在常数操作中。

语言适配仍有不同临时对象：

* Python 和 TypeScript 的当前行切片会建立引用数组；
* Java、C#、Go 和 Julia 使用可增长行缓冲；
* R 预分配普通行片段向量；
* C 在装行和构造阶段多次调用 ``strlen``，每个单词只被常数次扫描，所以总长度成本仍为 ``O(S)``。

前向规则
~~~~~~~~

* 输出固定宽度或固定规模时，复杂度显式包含不可避免的输出下界；
* 字符串长度 API 若不是常数时间，证明每个输入片段被重复扫描的次数；
* 切片只复制引用也属于临时容器空间；
* ASCII 字符数、UTF-8 字节数和终端显示宽度不能在通用文本中混用；
* 多对象返回的部分失败必须释放全部已完成成员和外层容器。

0069. Sqrt(x)
-------------

正向样本
~~~~~~~~

目标被表达为“最后一个满足单调谓词的整数”。闭区间二分保存最后可行值，并使用差值中点避免加法溢出。
搜索区间排除了零，因此每次除法都有正分母。

代数防溢出变换的定义域
~~~~~~~~~~~~~~~~~~~~~~

把：

.. code-block:: text

   mid * mid <= x

改写为：

.. code-block:: text

   mid <= x / mid

只有在 ``mid > 0``、``x >= 0`` 且使用对应的整数除法语义时才保持真假边界。当前题目和搜索区间满足这些
条件，所以改写正确。未来对含负数、向零截断或不同舍入方向的表达式，不能只凭代数外形套用。

前向规则
~~~~~~~~

* 用除法、重排或比较替代可能溢出的乘法时，先证明符号、非零分母和舍入方向；
* 二分谓词、搜索区间和返回边界必须使用同一整数语义；
* 防溢出证明覆盖中点、边界移动和比较表达式，而不只覆盖目标乘法；
* 找最后可行值时，命中合法候选后仍继续搜索右半区。

0070. Climbing Stairs
---------------------

正向样本
~~~~~~~~

按最后一步为 ``1`` 或 ``2`` 分类的两个集合互斥且完备。两状态滚动准确保存前两级计数，基础分支也使
R 的 ``3:n`` 只在合法递增范围内构造。

最终状态为什么约束全部中间状态
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

本题递推：

.. code-block:: text

   ways(step) = ways(step - 1) + ways(step - 2)

从正基础状态开始，每一步都严格非减。因而 ``ways(1)..ways(n)`` 均不超过 ``ways(n)``，最终答案上界
可以安全约束全部中间状态。这与 ``0063`` 的障碍路径不同：障碍会让较大前缀状态在终点前归零。

前向规则
~~~~~~~~

* 使用最终递推值证明中间状态宽度时，证明状态序列单调或给出其他支配关系；
* 滚动更新必须保存仍参与本轮计算的旧值；
* 标量计数返回不等于枚举全部方案，空间按实际状态而不是方案总数计算；
* 组合数基准同样需要控制乘法中间值，不能只依赖最终计数上界。

跨题统一归纳
------------

本批规则可以归并为五个检查动作：

#. **调用者可观察性。** 区分借用、共享、复制和独占消费，避免为了表面一致而制造无意义克隆。
#. **峰值对象图。** 同时记录输入、临时缓冲、最终不可变结果和输出元数据是否共存。
#. **运行时契约。** 版本限定 API、长度查询和字符串转换按目标语言真实语义验证。
#. **变换定义域。** 防溢出代数改写需要符号、除零和舍入方向证明。
#. **状态支配。** 最终值约束中间状态必须由单调性、单射或其他明确关系支撑。

用途
----

本文件只记录从 ``0016`` 至 ``0020`` 的完整 RST 正文和十语言代码中提炼出的前向规则。
它不触发历史题目回改。PR 描述、提交信息和自动任务报告不作为内容证据。

0016. 3Sum Closest
------------------

正向样本
~~~~~~~~

* ``best`` 由真实三元组初始化，不依赖可能泄漏到返回值的无穷大哨兵；
* 每轮先评价当前和，再按有序方向移动指针；
* 精确命中时使用绝对差下界 ``0`` 证明可以立即返回。

观察
~~~~

* 题目重述没有列出数组长度、元素值和 ``target`` 的精确数值范围；
* C、C++、Java、Rust、C# 扩宽三数和，但 Go、Julia 等仍依赖平台 ``int`` / ``Int``；
* 数值安全不仅涉及三数和，还包括 ``sum - target``、绝对值、最优候选差值以及最终转回平台返回类型；
* C++ 的 ``std::abs``、``vector``、``sort``，Java 的 ``Arrays``、``Math`` 缺少直接导入或平台预置说明。

前向规则
~~~~~~~~

* 数值宽度检查覆盖整条表达式链：输入提升、连续加法、减法、绝对值、比较、哨兵和最终窄化；
* 不能只把 ``sum`` 改成宽类型，就宣称全部溢出风险已经消失；
* 最终窄化必须由精确题目约束证明安全；
* 每个标准库符号直接导入，或明确说明平台预置。

0017. Letter Combinations of a Phone Number
-------------------------------------------

正向样本
~~~~~~~~

* 递归深度等于已确定输出位置数，状态含义清楚；
* 路径选择、递归和撤销形成完整回溯不变量；
* 每个合法组合有且只有一条递归路径，完整性和无重复证明充分；
* 复杂度计入每个叶子构造长度为 ``d`` 的输出字符串。

观察
~~~~

* 题目没有列出 ``digits`` 最大长度，C 却使用 ``int`` 连乘每层分支数得到组合总数；
* 组合数量既用于结果数组容量，也参与字节数乘法，需要在容量类型中检查乘积溢出；
* C 的结果数组、路径缓冲区和每个组合字符串都未检查分配失败；部分结果也没有清理路径；
* R 在每个叶子执行 ``result <<- c(result, value)``，已有结果可能被反复复制；
* R 使用 ``path[index] <<- letter`` 更新父绑定，不能自动视为常数时间原地覆盖。

前向规则
~~~~~~~~

* 组合数量先在 ``size_t`` 或目标容量类型中逐步乘法并检查溢出；
* 输出数量可预先计算时，优先精确预分配结果槽位；
* R 禁止在大量输出循环中反复 ``c(result, value)``，使用预分配列表、索引写入或明确引用语义；
* 输出敏感复杂度必须计入结果容器扩展和已有内容复制，而不仅是叶子字符串构造；
* 递归深度继续与精确最大输入长度对应。

0018. 4Sum
----------

正向样本
~~~~~~~~

* 双锚点把四数问题降为有序两数和；
* 第一锚点、第二锚点和双指针分别承担当前决策层的去重职责；
* 最小和、最大和剪枝以及双指针移动都有有序上下界依据。

观察
~~~~

* 正文把第一、第二锚点剪枝写成统一主解法组成部分；
* C、Python 只实现部分剪枝，C++、Java、Rust、Go、TypeScript、C#、Julia、R 等实现没有同步全部剪枝；
* 正确性仍成立，但文档将可选优化描述成十语言共有行为，形成讲解与代码不一致；
* C 再次直接覆盖 ``realloc`` 返回值，初始分配、行分配和并行数组扩容没有事务式失败处理；
* Julia 在 ``n < 4`` 时使用 ``1:(n - 3)``，会生成意外递减范围；
* Java 的 ``List.of`` 依赖 Java 9，未声明版本前提。

前向规则
~~~~~~~~

* 正文宣称为主解法组成部分的剪枝、去重和优化必须出现在所有对应语言实现中；
* 某些语言省略优化时，正文将其标为“可选优化”，并明确哪些实现采用；
* 十语言语义一致不要求逐行相同，但核心状态、剪枝承诺和复杂度声明必须对应；
* C 的并行数组扩容继续执行临时指针、全部成功后提交的事务规则；
* Julia、R 的空范围先守卫；版本相关 API 写明最低版本。

0019. Remove Nth Node From End of List
-------------------------------------

正向样本
~~~~~~~~

* 哑节点把删除头节点统一为修改前驱 ``next``；
* 快慢指针固定间距能够直接定位待删除节点前驱；
* Rust 因借用规则采用两遍法，并明确说明算法差异和相同渐进复杂度，是语言特化实现的良好示例。

观察
~~~~

* C 显式 ``free`` 被删除节点，C++ 与托管语言只断链；
* 正文没有说明节点由平台、调用方还是解法函数拥有，也没有统一断链后的释放责任；
* Python 使用 ``Optional``，R 使用 ``new_list_node``、``node_next``、``set_node_next``，代码块未直接定义、导入或引用统一辅助接口；
* TypeScript 的非空断言、Julia 的 ``something`` 和 Rust 的 ``unwrap`` 依赖“链表非空且 ``n`` 合法”的精确前提。

前向规则
~~~~~~~~

* 链表删除、拼接、交换和重排必须说明节点所有权、断链后释放责任以及平台是否继续访问原节点；
* C/C++ 的 ``free`` / ``delete`` 只能在平台契约允许时执行；
* 某语言因借用、所有权或运行时语义使用不同算法时，单独给出状态、证明和复杂度；
* 平台节点类型、辅助访问函数和类型别名必须直接定义、导入或明确引用统一接口；
* 非空断言、``unwrap``、``something`` 等必须由题目精确前提证明。

0020. Valid Parentheses
-----------------------

正向样本
~~~~~~~~

* 栈保存最近未闭合括号，状态是判断嵌套合法性的最小必要信息；
* 栈顶唯一匹配约束完整解释了为什么不能跨层闭合；
* 空栈右括号和类型冲突属于无法由后缀修复的前缀错误，可以提前失败；
* 题目明确输入只含六种 ASCII 括号，支撑按字节扫描和简化分支。

观察
~~~~

* C 按输入长度分配栈，但没有检查 ``malloc`` 失败，也没有由精确长度上界证明转成 ``int`` 安全；
* C++、Java、C# 的标准容器缺少直接导入或平台预置说明；
* R 先 ``strsplit`` 整串，再额外分配长度为 ``n`` 的栈，复杂度只写栈空间，没有区分输入规范化空间；
* 多种实现把“所有非左括号”直接视为右括号，该简化只有在六字符输入前提下成立。

前向规则
~~~~~~~~

* 精确字符域可以支撑简化分支；若字符域扩大，必须改为穷举匹配或显式非法输入处理；
* 前提驱动的 ``else``、``unreachable``、映射默认值和非空断言都要在正文指出支撑约束；
* 即使输入规范化与算法栈同为 ``O(n)``，也分别说明分配来源；
* C 的输入长度转换、容量分配和失败契约继续执行统一质量门。

本批提升的前向规则
------------------

数值表达式必须闭合验证
~~~~~~~~~~~~~~~~~~~~~~

* 数值安全不是单个变量类型检查；
* 连续加法、目标差值、绝对值、上下界剪枝和最终窄化都在宽类型域完成；
* 特别检查最小有符号值取绝对值、窄类型先运算后提升以及平台 ``int`` 位宽差异。

输出累加器按真实复制成本计费
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* 组合和枚举题不仅计算叶子数量，还检查结果容器追加语义；
* R 的 ``c`` 追加、不可变字符串反复拼接和数组重新分配可能产生累计复制；
* 可预知输出数量时精确预分配；不可预知时使用具有明确摊还追加语义的结构。

容量乘积先检查再分配
~~~~~~~~~~~~~~~~~~~~

* 分支数乘积、行数乘列数、元素数乘元素大小都使用目标容量类型；
* 每次乘法前检查是否超过 ``SIZE_MAX / factor`` 或语言对应上限；
* 容量计算、结果槽位和元数据数组必须保持同一成功状态。

文档承诺与实现一致
~~~~~~~~~~~~~~~~~~

* 主解法章节中的剪枝、去重和状态优化需要在十语言实现中落实；
* 只在部分语言出现的内容标为可选优化；
* 复杂度和证明只覆盖实际执行的算法，不能以某个语言的优化替代其他语言的事实。

语言特化算法需要单独证明
~~~~~~~~~~~~~~~~~~~~~~~~

* Rust 借用、R 引用语义、JavaScript 数值模型等可能要求不同实现；
* 差异实现单独写状态、正确性、输入修改和复杂度；
* 允许不同算法，不允许用统一伪代码掩盖实质差异。

链表节点所有权明确
~~~~~~~~~~~~~~~~~~

* 说明节点对象由谁创建、由谁释放、断链后是否仍可能被平台访问；
* 手动内存语言明确 ``free`` / ``delete`` 责任；
* 托管语言说明断链即可交给垃圾回收；
* 所有语言保持同一逻辑结果，资源契约按语言和平台分别写清。

0026. Remove Duplicates from Sorted Array
-----------------------------------------

正向样本
~~~~~~~~

有效前缀接口、尾部不属于结果以及 ``slow <= fast`` 保证覆盖安全的证明清楚。它适合作为原地稳定
压缩题的基础样本。

前向风险
~~~~~~~~

Julia 只对空数组提前返回，随后使用 ``2:length(nums)``。当数组只有一个元素时，``2:1`` 会生成
递减范围并访问无效下标。短数组守卫必须根据循环起点决定，不能只判断是否为空。

R 版本返回 ``k`` 与修改后的向量副本，实际接口、空间和调用后语义与平台原地数组接口不同。正文只
强调算法状态为常数规模，仍不足以描述 R 适配器可能发生的 ``O(n)`` 复制。

提升规则
~~~~~~~~

* 有效前缀题同时定义返回长度、前缀范围、尾部未定义语义和底层容器是否缩短；
* 无法表达原地接口的语言适配器单独标记，并重新计算复制和返回成本；
* ``2:n``、``3:n`` 等循环按最小合法长度守卫，空输入检查不能代替短输入检查。

0027. Remove Element
--------------------

正向样本
~~~~~~~~

稳定压缩与末尾交换方案清楚区分了保持顺序、减少写入和证明难度。正确性证明也分别覆盖“不保留
目标值”和“不遗漏其他值”。

前向风险
~~~~~~~~

本题再次出现抽象算法 ``O(1)`` 状态与 R 复制型适配器之间的差异。原地接口的结果由返回 ``k``
和原数组前缀共同构成，不能把尾部当作返回内容，也不能为了整理尾部增加额外工作。

提升规则
~~~~~~~~

* 原地算法的抽象空间与某语言适配器空间分开报告；
* 返回长度、有效前缀和调用者检查范围必须组成完整接口契约；
* 解法选择除渐进复杂度外，还说明稳定性、写入次数和输入修改方式。

0028. Find the Index of the First Occurrence in a String
--------------------------------------------------------

正向样本
~~~~~~~~

候选起点 ``0..n-m``、逐字符验证和第一次成功即最小答案的证明完整。正文也知道 ASCII、UTF-8
字节和 UTF-16 代码单元只在当前字符域中等价。

前向风险
~~~~~~~~

正文用“当前 LeetCode 约束通常保证 ``needle`` 非空”描述官方契约，同时又增加空模式的通用接口
行为。官方约束和主动扩展需要明确分开，不能以“通常”替代精确事实。

R 的 ``utf8ToInt`` 会分配 ``O(n+m)`` 码点向量，统一的 ``O(1)`` 额外空间不适用于该实现。
标准库 ``find``、``IndexOf`` 等接口在不同语言可能返回字节、UTF-16 代码单元或其他坐标，不能只
验证匹配内容而忽略返回下标单位。

提升规则
~~~~~~~~

* 官方题目契约使用精确约束，通用扩展放入独立小节；
* 字符串算法分别定义比较单位和返回坐标；
* 转码向量、子串和返回下标转换计入目标语言真实成本。

0029. Divide Two Integers
-------------------------

正向样本
~~~~~~~~

先扩宽再取绝对值、``INT_MIN / -1`` 唯一溢出、倍增边界和向零截断的证明完整。安全倍增条件
``value <= remaining - value`` 也是良好的先判断后运算样本。

前向风险
~~~~~~~~

复杂度写成 ``O(log |q|)``，但被除数绝对值小于除数时 ``q = 0``，表达式落入 ``log 0``。应使用
``O(log(|q|+1))``、有效位数或实际倍增表长度。

Julia 的公开接口使用宿主 ``Int``，32 位边界常量和最终转换依赖运行平台的 ``Int`` 位宽。固定宽度
题目若采用平台相关整数，需要明确平台前提或在边界计算中统一使用固定宽类型。

C++ 代码使用 ``INT_MIN``、``std::llabs`` 和 ``std::vector``，代码块没有直接展示必要头文件。R 的
反复 ``c`` 追加在固定 32 位输入下最多 32 次，但推广模型下与普通摊还数组不是同一成本。

提升规则
~~~~~~~~

* 对数复杂度参数可能为零时使用 ``log(x+1)`` 或定义明确的位数；
* 平台相关整数宽度必须声明，边界语义优先使用固定宽类型；
* 固定输入域的常数上界和推广模型的渐进成本分开说明；
* 标准库符号直接导入。

0030. Substring with Concatenation of All Words
-----------------------------------------------

正向样本
~~~~~~~~

按词长余数拆分扫描线、非法单词重置、超量单词收缩和重叠答案继续搜索的证明完整。``count == k``
加逐项不超限推出频次完全相等，也是一段清晰的计数证明。

前向风险
~~~~~~~~

多数语言直接访问 ``words[0]``，依赖 ``words`` 非空、所有单词等长且长度大于零。正文只写等长，
没有把所有会影响循环终止和索引安全的前提列全。C 单独处理 ``wordsSize == 0``，其余语言依赖官方
前提，十语言的防御策略不一致。

``word_length * word_count``、开放寻址容量翻倍以及 C 的所有分配尺寸都依赖精确约束。C 版本的
``table``、``representative``、``need``、``answer``、``seen`` 和 ``stamp`` 没有统一失败契约。

复杂度把哈希表空间写成 ``O(u)``。对复制字符串键的实现，键载荷本身需要 ``O(u*w)`` 字符空间；
返回答案还需要单列 ``O(A)``。逻辑窗口操作为线性并不等于字符工作为线性：切片、哈希和比较每次
可能读取 ``w`` 个字符，总字符工作可达 ``O(nw)``，哈希操作本身还是期望复杂度。

R 使用 ``answer <- c(answer, value)`` 反复扩展答案向量，输出较多时会累计复制。Go 的
``clear(seen)`` 和 C# 的 ``GetValueOrDefault`` 也具有最低语言或运行时版本前提。

提升规则
~~~~~~~~

* 十语言统一列出非空、正长度、等长和合法字符等官方前提；
* 哈希空间同时计算桶、键数量和被拥有的键载荷；
* 区分窗口操作次数、字符串切片次数、哈希字符工作、哈希期望/最坏界和输出空间；
* C 的复合状态分配采用整体成功或整体清理的事务式契约；
* 输出追加按语言真实语义计费；
* 版本相关容器和内建函数声明最低版本。

本批提升的统一规则
------------------

有效前缀接口必须完整
~~~~~~~~~~~~~~~~~~~~

* 返回长度和原数组共同定义答案；
* 明确只检查前 ``k`` 个位置，尾部内容未定义；
* 说明底层容器是否缩短、是否保序、是否修改调用者对象；
* 语言适配器返回副本时单独描述接口与复杂度。

字符串比较单位与返回坐标分离
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* 比较可使用字节、代码单元或码点；
* 返回值必须映射到平台规定的坐标；
* 标准库查找 API 也需要确认返回单位；
* ASCII 等价性只能由精确字符约束支撑。

逻辑操作与真实字符工作分离
~~~~~~~~~~~~~~~~~~~~~~~~~~

* 滑动窗口每个块进入、离开一次只证明逻辑操作线性；
* 字符串切片、哈希和比较可能每次读取 ``w`` 个字符；
* 哈希时间区分期望与最坏，空间计入字符串键载荷；
* 返回索引数组或组合结果单列输出空间和追加成本。

官方契约与通用扩展分离
~~~~~~~~~~~~~~~~~~~~~~

* 官方约束必须精确，不使用“通常”“常见”或“似乎保证”；
* 主动支持空模式、空词表或非法输入时，明确标记为扩展；
* 十语言对同一前提保持一致，不能只有个别语言添加半套防御。

短范围与零值定义域
~~~~~~~~~~~~~~~~~~

* Julia/R 的递减范围按真实循环起点守卫；
* ``log q``、反向循环和容量公式覆盖 ``q=0``、空表和单元素输入；
* 平台相关整数宽度与固定宽题目边界保持一致。

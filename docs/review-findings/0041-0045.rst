0041. First Missing Positive
----------------------------

正向样本
~~~~~~~~

答案范围首先由鸽巢原理限制为 ``1..n+1``，随后证明值 ``v`` 出现当且仅当目标槽位保存 ``v``，
最后用第一处不匹配证明答案最小。每次交换永久填好一个目标槽位，重复值守卫阻止交换环，正确性与
终止性形成闭环。

前向风险
~~~~~~~~

目标下标由当前数组值计算。代码必须先验证 ``1 <= value <= n``，再依赖语言明确的短路求值访问
``nums[value-1]`` 或一基 ``nums[value]``。条件重排可能把正确代码变成越界访问。

C++ 将 ``size_t`` 长度转换为 ``int``，Rust 将 ``usize`` 下标及 ``n+1`` 转为 ``i32``，安全性依赖
精确长度上界。R 在函数内重排局部向量，写时复制可能产生 ``O(n)`` 适配器成本，不具备字面意义的
原地 ``O(1)`` 空间接口。

提升规则
~~~~~~~~

* 值派生下标先完成值域检查，再执行目标槽位访问；
* 原地槽位映射证明永久放置、正确槽位不被破坏和重复值停机；
* 长度与 ``n+1`` 的窄化由精确上界证明；
* 输入重排、所有权消费和复制型适配器按语言说明。

0042. Trapping Rain Water
-------------------------

正向样本
~~~~~~~~

当 ``left_max <= right_max`` 时，右侧已经存在不低于 ``right_max`` 的实际边界，因此当前位置的
限制侧已经确定为 ``left_max``。未来内部柱高只能维持或提高非限制侧，无法改变本次结算。对称情况
同理。该证明准确解释了双指针为什么可以在线提交答案。

前向风险
~~~~~~~~

正文只写“题目约束下总水量可以用 ``int`` 表示”，没有列出柱子数量与高度上界，也没有推导累计
水量上限。聚合结果的宽度不能只由单柱差值决定。C++ 的长度窄化也需要同一组精确约束。

R 使用双精度数值累加，避免 R 整数溢出产生 ``NA``，这属于语言适配器的数值表示差异。

提升规则
~~~~~~~~

* 累计量由 ``数量 × 单项最大贡献`` 推导宽度；
* 在线提交前证明未来信息不能改变已经确定的值；
* 指针和长度窄化由精确约束支撑。

0043. Multiply Strings
----------------------

正向样本
~~~~~~~~

结果最多 ``m+n`` 位、数字对落入相邻槽位以及从右向左传播进位的证明完整。算法枚举所有数字对，
每项部分乘积恰好加入一次，也明确区分了结果数组和输出字符串空间。

前向风险
~~~~~~~~

题目重述只写输入由十进制数字组成，没有列出输入非空及“除 0 外没有前导零”的规范表示。Julia
``findfirst`` 与 R ``which(...)[[1]]`` 在零值早退后假设结果数组一定存在非零槽位；该见证依赖零只写作
``"0"``。若允许 ``"00"``，两个实现会在后处理阶段失败。

C 的零字符串、结果槽数组和返回字符串分配均未形成失败契约。``strlen`` 到 ``int`` 的转换、
``m+n``、分配尺寸与返回长度也需要精确输入上界。

不同语言的序列化路径差异明显：TypeScript ``slice`` 创建数组副本；Julia 生成逐位字符串数组后
``join``；R 使用 ``utf8ToInt`` 与 ``paste0``。复杂度应计入中间集合和最终输出的并存峰值。

提升规则
~~~~~~~~

* 数字字符串契约写明非空、字符域、零表示和前导零；
* 后处理解包前证明非零见证存在；
* C 所有分配与长度表达式形成完整资源契约；
* 数字数组到字符串的序列化管线按语言真实成本计算。

0044. Wildcard Matching
-----------------------

正向样本
~~~~~~~~

最近星号先匹配空串，失配后只把覆盖长度增加一，依次枚举 ``0,1,2,...``，不会跳过可行长度。
正文还区分了常见接近线性的表现和严格 ``O(mn)`` 最坏上界，是受控回退复杂度的良好样本。

前向风险
~~~~~~~~

算法核心只保存四个索引，并不代表所有实现都是 ``O(1)`` 空间。Julia 把两组 ``codeunits`` 复制为
``Vector{UInt8}``，R 用 ``strsplit`` 构造两个字符向量，真实额外空间为 ``O(m+n)``。ASCII 字符域也应
在统一题目契约中写明，以支撑字节和代码单元等价。

终止性可以更明确地使用 ``match_start`` 单调增加且最多到达字符串长度这一进度量。模式片段重扫
决定 ``O(mn)`` 上界，与终止性证明是两个不同问题。

提升规则
~~~~~~~~

* 核心状态空间与输入规范化副本分开报告；
* 受控回退给出单调进度量、回退次数和重扫成本；
* 字节匹配由精确 ASCII 契约支撑。

0045. Jump Game II
------------------

正向样本
~~~~~~~~

把隐式图中连续邻接区间的并集压缩为最右边界，完整扫描当前层后才把 ``current_end`` 推进到
``farthest``，等价于 BFS 进入下一层。最少跳数由目标首次进入层覆盖范围得到，而不是由局部最大值
决定。

前向风险
~~~~~~~~

``farthest`` 与 ``current_end`` 是覆盖坐标，可能大于最后一个合法下标。它们可以参加边界比较，
不能未经裁剪直接访问数组。``index + nums[index]`` 的整数宽度也需要数组长度和最大跳数共同推导。

算法依赖题目保证终点可达。若用于通用输入，层结束时 ``farthest == current_end`` 表示边界无法继续
推进，应返回独立失败语义。Rust 的 ``usize`` 转换还依赖跳数非负和加法安全。

提升规则
~~~~~~~~

* 区间 BFS 压缩证明层出边并集连续；
* 覆盖边界与合法数组下标分开；
* 可达性前提与停滞检测形成完整进度契约；
* 端点加法和累计状态由精确约束推导宽度。

本批提升的统一规则
------------------

值派生下标按守卫顺序访问
~~~~~~~~~~~~~~~~~~~~~~~~

* 先证明值位于合法槽位范围；
* 再通过明确的短路求值执行数组访问；
* 条件顺序属于内存安全契约，不能只在正文中说明。

永久槽位与聚合宽度分别证明
~~~~~~~~~~~~~~~~~~~~~~~~~~

* 原地哈希证明每次交换完成永久进展并处理重复值；
* 聚合结果由数量和单项最大贡献推导宽度；
* 长度、边界和 ``n+1`` 的窄化覆盖所有合法返回值。

规范表示支撑后处理见证
~~~~~~~~~~~~~~~~~~~~~~

* 数字字符串声明零的唯一表示和前导零规则；
* ``findfirst``、``which``、``unwrap`` 前由早退或不变量证明结果存在；
* 序列化过程计入切片、逐项字符串化、中间集合和最终输出。

受控回退使用单调进度量
~~~~~~~~~~~~~~~~~~~~~~

* 回退检查点只沿一个方向推进；
* 单调量给出终止性和最大回退次数；
* 被重复扫描的固定片段决定严格最坏复杂度；
* 输入规范化副本与常数核心状态分别计费。

覆盖边界不是数组下标
~~~~~~~~~~~~~~~~~~~~

* 隐式区间图先证明当前层出边并集连续；
* 汇总边界可以超过数组末尾；
* 只有裁剪或范围检查后的坐标才能用于数组访问；
* 可达性保证或停滞检测支撑每次层转换。

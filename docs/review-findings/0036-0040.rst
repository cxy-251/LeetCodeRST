0036. Valid Sudoku
------------------

正向样本
~~~~~~~~

行、列、宫三类状态与扫描前缀不变量对应清楚。返回 ``false`` 的安全性和扫描结束返回 ``true`` 的
反证都覆盖了验证算法的真实决策。正文同时写出扫描 81 个格子和固定域 ``O(1)``，适合作为固定规模
问题的复杂度表达样本。

前向风险
~~~~~~~~

十语言代码都依赖棋盘严格为 ``9 × 9``，且每个非空字符都属于 ``'1'`` 至 ``'9'``。这些约束直接
支撑数组下标 ``0..8``，应在所有语言共享的接口契约中集中写明。

C++ 代码使用 ``vector``，需要直接导入或明确由平台模板提供。

提升规则
~~~~~~~~

* 固定域题同时说明精确工作量、约束内常数界和推广模型；
* 所有产生数组索引的字符和值域前提集中写入题目契约；
* 标准库依赖在代码块附近完整呈现。

0037. Sudoku Solver
-------------------

正向样本
~~~~~~~~

MRV 选择候选最少的空格，正文清楚区分了搜索顺序与候选集合。安全性证明约束状态不会产生重复，
完备性证明每个合法候选仍被枚举，撤销证明父层状态能够恢复。找到解后立即沿递归链返回，也正确保留
已确认的棋盘修改。

R 将棋盘和三组掩码放进 ``environment``，把 ``best_row`` 等选择变量保留在每次递归调用的局部环境，
是共享可变状态与调用局部状态分离的正向样本。

前向风险
~~~~~~~~

C++、Java 和 C# 把掩码数组保存为对象字段，公共入口没有显式清零。LeetCode 常见的一次调用生命周期
可以让它工作；作为可复用函数时，第二次调用会继承旧状态。公共入口应初始化调用级状态，或者明确对象
只使用一次的前提。

C++ 的 ``__builtin_popcount`` 属于编译器扩展，Python ``int.bit_count`` 和 Rust ``let-else`` 具有
最低版本要求。跨语言题解应区分语言标准、运行时版本和编译器扩展。

每层 MRV 重新扫描剩余空格。9×9 数独中最多扫描 81 格，是固定常数；推广到一般约束满足问题时，
启发式选择成本需要计入每个搜索节点。

R 返回新的棋盘对象，与平台原地修改接口不同，应标记为语言适配器并说明调用后语义。

提升规则
~~~~~~~~

* 调用级可变字段在公共入口初始化或清空；
* 启发式证明“只重排、不删候选”，同时计算启发式选择成本；
* 编译器内建和版本相关语法明确环境前提；
* 原地接口的复制型语言适配器单独说明。

0038. Count and Say
-------------------

正向样本
~~~~~~~~

正确性先证明单次游程编码，再对序列编号归纳。复杂度用各轮长度之和表达，避免把迭代次数误当作总工作量。

前向风险
~~~~~~~~

C 的 ``current`` 和 ``next`` 在分配后直接写入，``append_text`` 又把 ``realloc`` 结果直接覆盖旧指针。
扩容失败会丢失原缓冲区并在后续 ``memcpy`` 中产生未定义行为；容量翻倍和长度加法也需要先检查溢出。

Julia 使用 ``for _ in 2:n``。当 ``n = 1`` 时，``2:1`` 会生成递减范围并执行两轮，主代码返回错误项。
这说明语言语义说明本身也需要验证，不能凭其他语言的空范围直觉推断 Julia。

R 在每个分组后执行 ``parts <- c(parts, ...)``，会重复复制已经生成的片段。正文的线性扫描总和没有
覆盖该实现的累计追加成本。

空间写成 ``O(L_n)`` 过于简化。每轮同时持有 ``current``、``next``、片段列表、计数字符串和转换
临时对象，峰值应按并存对象计算，例如 ``O(L_k + L_{k+1})`` 加片段元数据。

提升规则
~~~~~~~~

* C 字符串构造采用事务式分配和扩容；
* 循环范围语义通过实际语言行为确认；
* 空间复杂度统计同一时刻并存的旧值、新值和临时对象；
* 输出片段追加按目标语言的复制或摊还语义计算。

0039. Combination Sum
---------------------

正向样本
~~~~~~~~

非递减路径为每个组合提供唯一表示。递归传入当前 ``index`` 准确表达候选可重复使用，正数约束让
``remaining`` 严格下降，也支撑排序后的提前停止。合法性、无重复和完整性证明结构完整。

前向风险
~~~~~~~~

C 的结果指针数组、列长度数组、路径和每个答案行都缺少统一失败契约。两个 ``realloc`` 直接覆盖
旧指针，还可能让 ``rows`` 与 ``sizes`` 容量不同步。路径容量依赖 ``candidates[0]``，因此非空、正数
和目标上界都属于内存安全前提。

复杂度只写“输出敏感的指数级”。更可执行的表达是：排序成本，加访问搜索节点的成本，再加所有答案
路径快照的总元素数量。空间同样区分递归栈、当前路径和结果集合。

R 的路径选择和撤销都创建新向量，实际成本与原地 ``push/pop`` 语言不同。多数语言原地排序输入，
Rust 拥有传入副本，R 在局部副本上排序；调用后输入语义应按语言说明。

提升规则
~~~~~~~~

* 回溯复杂度使用“预处理 + 搜索节点 + 输出载荷”；
* 路径快照、追加和撤销按语言真实复制语义计费；
* C 的多缓冲区分配与扩容保持整体一致；
* 排序是否修改调用者输入写入语言接口说明。

0040. Combination Sum II
------------------------

正向样本
~~~~~~~~

正文没有把同层去重简化为记忆条件，而是解释了根层保留 ``1a``、深层仍可使用 ``1b`` 的层级差异。
完整性进一步使用“最早可用等值下标”替换后续下标，证明保留分支拥有不小于被跳过分支的可用后缀。

前向风险
~~~~~~~~

C 复用了 0039 的分配与扩容模式，整体失败路径仍未闭合。

Julia 正文声称 ``start:length(candidates)`` 在 ``start`` 越过末尾时是空范围。Julia 的 ``a:b`` 在
``a > b`` 时会生成递减范围；选择最后一个候选后若剩余值仍大于零，下一层可能访问 ``n + 1`` 并越界。
R 版本正确地在进入循环前检查了后缀是否耗尽。

同层去重条件 ``index > start`` 只是实现形式。后续题解需要证明被跳过的分支与保留分支拥有相同值
选择，并且保留分支的可用后缀覆盖被跳过分支。

R 的路径追加和撤销继续产生写时复制；排序修改输入与搜索节点、输出快照复杂度也应按语言说明。

提升规则
~~~~~~~~

* 语言行为说明与实际范围、索引和复制语义一致；
* 同层去重证明等价分支和后缀覆盖关系；
* C 多缓冲区扩容采用事务式更新；
* 回溯路径与输出成本按语言分别计算。

本批提升的统一规则
------------------

固定域与推广模型同时表达
~~~~~~~~~~~~~~~~~~~~~~~~

* 固定棋盘、固定字符集和固定位掩码给出精确上界；
* 说明哪些工作因题目固定而成为常数；
* 保留推广模型时定义变量并计入启发式扫描。

搜索顺序与候选集合分离
~~~~~~~~~~~~~~~~~~~~~~

* MRV、排序和候选优先级说明它们改变搜索顺序的方式；
* 正确性证明合法候选全集保持不变；
* 复杂度包含选择启发式的成本。

调用级状态有明确生命周期
~~~~~~~~~~~~~~~~~~~~~~~~

* 对象字段、闭包环境和辅助缓存在公共入口建立本次调用状态；
* 多次调用共享对象时，入口负责清空上一轮数据；
* 单次调用平台生命周期作为明确前提记录。

构造过程计算并存空间峰值
~~~~~~~~~~~~~~~~~~~~~~~~

* 字符串和数组迭代构造统计旧值、新值、片段容器和转换临时对象；
* 动态追加成本按摊还、复制或写时复制语义计算；
* C 扩容先验证容量表达式和新指针，再提交状态。

回溯成本拆成节点与输出
~~~~~~~~~~~~~~~~~~~~~~

* 排序或其他预处理单列；
* 搜索阶段使用访问节点数量描述；
* 答案保存使用总输出元素数量描述；
* 递归栈、当前路径和结果集合分别计费。

去重证明覆盖等价分支
~~~~~~~~~~~~~~~~~~~~

* 同层重复值属于等价首选；
* 保留最早可用下标拥有不小于后续等值下标的可用后缀；
* 深层重复值代表不同数组位置，仍可形成合法组合。

语言语义说明需要验证
~~~~~~~~~~~~~~~~~~~~

* 范围、切片、下标、字符串和复制行为以目标语言实际语义为准；
* 编译器内建和版本相关 API 记录运行环境；
* 关键语义通过编译、运行或官方文档确认后进入主讲解。

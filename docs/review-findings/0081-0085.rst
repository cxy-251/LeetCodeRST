0081. Search in Rotated Sorted Array II
---------------------------------------

正向样本
~~~~~~~~

闭区间二分先检查中点，再处理 ``nums[left] == nums[mid] == nums[right]`` 的信息歧义。三端相等且
中点未命中时，左右端点也不可能是目标，可以同时收缩。消歧后再根据至少一侧非递减的事实排除半区。

正文正确说明重复值会破坏严格对数保证。全部相同或大段相同的输入中，每轮可能只删除常数个位置，最坏
时间为 ``O(n)``；常见输入仍能按二分方式快速缩小区间。

信息退化与复杂度保证
~~~~~~~~~~~~~~~~~~~~

算法的复杂度保证取决于比较结果提供多少区分信息。重复值使中点、左端和右端的比较无法确定旋转断点
位置，只能删除已经证明不是目标的边界。这里的边界收缩是正确的消歧动作，却不再保证每轮删除固定比例。

Rust 使用 ``usize`` 下标，并在 ``mid - 1`` 前验证 ``mid > 0``。这种防下溢分支必须与闭区间更新规则
一起审查，不能只验证数学下标而忽略目标类型。

前向规则
~~~~~~~~

* 当重复值、碰撞或等价类降低比较信息量时，分别给出通常和最坏复杂度；
* 消歧删除必须证明被删除对象不可能是答案，不能只因为它“不提供信息”就丢弃；
* 闭区间、半开区间和无符号下标的终止与下溢证明必须成套出现；
* 对拍应包含全部相同、三端相同但目标位于内部和不存在目标等退化输入。

0082. Remove Duplicates from Sorted List II
-------------------------------------------

正向样本
~~~~~~~~

哨兵节点统一处理头部重复段。``previous`` 始终停在结果有效前缀末尾，``current`` 指向尚未分类的第一
个节点。检测到重复值后越过完整值段，再让 ``previous.next`` 指向第一个不同值节点，确保重复值一个
副本也不保留。

Rust 的 ``link`` 表示当前节点所在的所有权槽位。重复时用后继替换槽位，唯一时把槽位推进到
``node.next``，不使用 ``unsafe``，被移出的 ``Box`` 自动析构。

断链与资源责任
~~~~~~~~~~~~~~

“结果链表不再可达”与“节点内存已经释放”是两个不同结论。C 和 C++ 实现只重连指针，题目适配器不负责
释放被移出结果链表的数据节点；Rust 的所有权替换则会自动释放离开槽位的 ``Box``。托管语言由垃圾回收
器最终回收不可达节点。

因此链表教程需要同时说明：哪些节点保留、哪些节点断开、节点身份是否复用，以及断开节点由谁负责回收。

前向规则
~~~~~~~~

* 删除完整值段时，前驱必须停在值段之前，直到整个区间被绕过；
* “断链”“立即释放”和“最终由运行时回收”分别说明；
* 原地链表测试检查值序列、保留节点身份、节点数量和无环性；
* 所有权语言优先使用可变链接槽位表达删除，而不是复制节点值模拟结果。

0083. Remove Duplicates from Sorted List
----------------------------------------

正向样本
~~~~~~~~

本题保留每个连续值段的第一个节点。内层循环持续绕过与 ``current.val`` 相同的后继，直到新后继为空或
值更大，随后才能推进 ``current``。有序性保证只做相邻比较即可完整处理每个值段。

实现复用原节点并保持稳定顺序。Rust 通过 ``take`` 转移后继所有权；C 和 C++ 同样只断链，不负责释放
被绕过的数据节点。

值段契约不能混用
~~~~~~~~~~~~~~~~

0082 和 0083 的扫描骨架相近，结果语义完全不同：

* 0082 删除所有长度大于一的值段；
* 0083 为每个值段保留第一个节点。

复制相邻题代码时必须先固定“保留零个、一个还是最多若干个”的契约。只看到“有序链表去重”不足以确定
前驱推进、值段提交和节点释放规则。

前向规则
~~~~~~~~

* 连续值段算法先定义每段保留数量，再设计前驱与扫描状态；
* 绕过一个重复节点后重新检查新后继，不能立即推进到下一值段；
* 保留节点身份属于接口结果，不能只比较最终值数组；
* 相邻比较的充分性必须由输入有序性证明。

0084. Largest Rectangle in Histogram
------------------------------------

正向样本
~~~~~~~~

非递减下标栈保存尚未遇到右侧严格更矮柱子的候选。当前高度更小时，弹出柱子的右侧首个更矮位置就是
当前下标；弹栈后的新栈顶给出左侧首个严格更矮位置，宽度为 ``right - left``。

局部虚拟零高度统一结算非递减后缀，不修改输入数组。相同高度允许同时留栈，最左同高柱最终获得最大
宽度，因此使用严格 ``>`` 弹栈不会漏掉最大面积。

单调栈边界证书
~~~~~~~~~~~~~~

只写“每个元素入栈出栈一次”只能证明摊还时间，不能证明面积正确。每次弹栈还必须给出完整边界证书：

#. 当前扫描位置为何是右侧第一个严格更矮位置；
#. 弹栈后的新栈顶为何是左侧最近的严格更矮位置；
#. 两个边界之间为何全部不低于弹出高度；
#. 弹出的候选为何以后不再需要保留。

虚拟下标只用于触发结算。若把它压栈，必须证明循环结束前不会再通过它访问真实高度数组。

前向规则
~~~~~~~~

* 单调栈证明同时覆盖维护顺序、弹栈触发条件、左右边界和摊还次数；
* ``>`` 与 ``>=`` 的等高策略必须与边界证明和结果去重策略一致；
* 虚拟哨兵不得越界访问底层数组，也不得修改只读输入；
* 面积乘法先按约束推导上界，再选择中间类型。

0085. Maximal Rectangle
-----------------------

正向样本
~~~~~~~~

每行处理后，``heights[column]`` 精确表示以当前行为底向上连续 ``'1'`` 的数量。任意全一矩形有唯一
底边行，并在该行映射为柱状图中的连续区间；柱状图候选也能反向映射为合法矩形。

每行调用 0084 的单调栈，单元格更新和下标入栈、出栈都只发生常数次，总时间为
``O(rows × columns)``，柱高和栈的峰值工作空间为 ``O(columns)``。

降维映射与状态复用
~~~~~~~~~~~~~~~~~~

二维问题降为逐行一维问题，需要证明三件事：

* 编码不变量：柱高等于当前底边向上的连续一数量；
* 完整性：每个二维矩形在唯一底边行进入某个一维候选；
* 反向合法性：一维候选覆盖的全部单元格确实都是一。

C、Java、Go、TypeScript 和 C# 复用固定栈缓冲；Python、C++、Rust 和 Julia 在每行建立新栈。二者渐进
峰值空间相同，但重复分配和容量复用应按语言实现分别说明。所有实现还依赖矩阵各行列数一致。

前向规则
~~~~~~~~

* 维度压缩必须证明编码不变量、对象归属维度和双向合法映射；
* 复用子算法时重新检查哨兵、下标体系、数值上界和输入修改契约；
* 区分每行重新分配、复用容量与峰值工作空间；
* 使用首行列数遍历全部行时，明确规则矩阵前提或增加形状验证。

跨题统一归纳
------------

本批规则可以归并为六个检查动作：

#. **信息保证。** 比较信息退化时，重新评估最坏复杂度和安全消歧动作。
#. **值段契约。** 先确定连续段保留数量，再决定前驱推进与断链方式。
#. **资源责任。** 区分不可达、释放、自动析构和垃圾回收。
#. **边界证书。** 单调栈弹栈同时证明左右首个阻断位置和最大扩展区间。
#. **虚拟哨兵。** 哨兵只触发结算，不越界读取，也不污染输入。
#. **降维双射。** 高维对象与逐层低维状态之间建立完整且合法的双向映射。

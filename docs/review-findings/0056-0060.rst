0056. Merge Intervals
---------------------

正向样本
~~~~~~~~

排序后维护唯一尚未提交的覆盖段，正文把“新区间仍重叠”和“首次严格分离后永久提交”分别证明。
闭区间使用 ``next_start <= current_end``，端点相接不会被错误拆开。

C 比较器使用关系比较而非端点相减；二维结果中的每个区间独立分配，任一失败时释放全部已完成行。
Python、Go、Julia 等实现也建立独立二元快照，没有把输入行直接作为可变结果保存。

前向风险：标准排序空间不能统一写死
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

解法表把额外空间统一写成 ``O(log n)``，这只能描述某些原地比较排序模型，不能直接代表十语言实际
标准库：

* Python ``list.sort`` 与 Java 对象数组排序可能使用线性临时缓冲；
* C ``qsort`` 的内部算法和辅助存储不是由题解代码决定；
* JavaScript ``Array.sort`` 的具体算法由运行时实现；
* R 版本明确建立排序后的矩阵副本，额外适配器空间为 ``O(n)``。

“API 会原地重排输入”与“排序只使用对数辅助空间”是两个不同命题。输入调用后状态、排序运行时资源和
输出快照需要分开记录。

参考：

* `CPython listsort.txt
  <https://github.com/python/cpython/blob/main/Objects/listsort.txt>`_：Timsort 最多可能需要约 ``N/2``
  个指针的临时数组；
* `Java Arrays.sort
  <https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Arrays.html>`_：对象数组排序的
  临时存储可从小常数增长到 ``n/2`` 个对象引用。

提升规则
~~~~~~~~

* 标准排序的时间、稳定性和辅助空间按目标语言与运行库说明；
* 原地 API 只说明输入会被重排，不自动推出常数或对数空间；
* 闭区间端点接触语义必须贯穿排序、扫描和验证；
* 输出区间与输入内层容器解除别名。

0057. Insert Interval
---------------------

正向样本
~~~~~~~~

本题没有重新排序，而是使用“原区间已按起点排序且两两不重叠”的强前提，把扫描严格分成：

#. 位于新区间左侧的完整区间；
#. 与动态合并段相交的连续区间；
#. 位于合并段右侧的完整区间。

三个阶段互斥且覆盖全部原区间。空输入、插入首尾、端点接触和跨越多个区间都由相同控制流处理。
C 由 ``n+1`` 推导精确外层容量，所有语言都建立独立输出行。

前向风险
~~~~~~~~

``O(n)`` 时间依赖已排序且不重叠前提。若输入只是任意区间集合，第一阶段提交的区间可能被后续区间
连接，第二阶段也不再是连续块；此时必须回到 0056 的排序合并。

``O(1)`` 算法额外空间排除了返回的最多 ``n+1`` 个二元快照。``copy``、``clone``、新建切片和矩阵行
属于输出载荷；Rust 按值取得输入后仍按下标克隆行，所有权消费、输出复制和峰值并存应分别说明。

提升规则
~~~~~~~~

* 强前提用于删除排序或搜索步骤时，证明前提与降阶之间的因果关系；
* 三阶段扫描证明阶段互斥、完整以及进入下一阶段后不会返回；
* 工作状态与返回快照分别计费；
* 输入不修改、输入所有权消费和输出独立性分别描述。

0058. Length of Last Word
-------------------------

正向样本
~~~~~~~~

题目把字符域限制为 ASCII 英文字母与普通空格，字节、UTF-16 代码单元和码点在该输入域上一一对应。
跳过尾部空格后计数最大非空后缀的两阶段不变量完整，非空单词前提直接支撑边界访问。

正文没有把 R 的 ``charToRaw`` 当成常数空间操作，而是明确计入 ``O(n)`` 字节副本；Rust
``as_bytes`` 与 Julia ``codeunits`` 则使用借用或视图语义。

前向风险：逻辑后缀扫描不等于实际只读后缀
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

C 版本先调用 ``strlen`` 获取末尾位置。``strlen`` 本身会完整扫描字符串，随后算法才反向读取尾部。
因此“只关心必要后缀”是状态设计优势，不代表所有语言实现的实际访问量只与后缀长度有关。

ASCII 特化也不能外推到 Unicode 单词：一旦允许其他空白、组合字符或多字节字母，分隔符判定、长度单位、
随机访问与反向扫描 API 都需要重新定义。

提升规则
~~~~~~~~

* 前置标准库调用的完整遍历和分配计入成本；
* 字符串题先固定比较和长度单位；
* ASCII 字节特化由精确字符域证明；
* 无符号反向索引在计算 ``index-1`` 前先证明 ``index>0``。

0059. Spiral Matrix II
----------------------

正向样本
~~~~~~~~

剩余区域、边界收缩、位置和值一一对应的证明完整。每个位置恰好写入一次，``value`` 同步从 ``1`` 增长
到 ``n²``。输出矩阵与四个边界工作状态也被正确分开计费。

R 和 Julia 已吸收上一批对 0054 的发现：反向范围显式写负步长，并同时检查剩余行与剩余列。
C 的外层行指针先初始化为空，失败时只释放已成功建立的行。

前向风险：单维守卫依赖方阵耦合
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

部分零基实现写完上边和右边后，第三条边只检查 ``top <= bottom``，第四条边只检查
``left <= right``。本题仍然正确，因为初始区域是方阵，每轮同步删除一行和一列，剩余高宽始终相等；
一个维度存在时另一个维度也存在。

该证明只属于方阵构造。复制到 0054 的矩形读取时，单行与单列会独立退化，必须同时检查相关边界。
Rust 的正向闭区间在起点越过终点时依赖空范围语义；它不是所有语言范围对象的共同性质。

提升规则
~~~~~~~~

* 弱化边界守卫前证明形状不变量使两个条件等价；
* 方阵耦合不能迁移到矩形；
* 空范围、报错范围和显式负步长按目标语言分别验证；
* 二维输出的每行必须拥有独立可变存储。

0060. Permutation Sequence
--------------------------

正向样本
~~~~~~~~

正文先把题目的一基 ``k`` 转为零基 ``rank``。剩余 ``remaining`` 个候选时，每个下一位块包含
``(remaining-1)!`` 个排列：

.. code-block:: text

   choice = rank / block
   rank   = rank % block

由 ``rank < remaining!`` 可得 ``choice < remaining``，所以下标始终合法。选定数字后将它从有序候选
表删除，新的 ``rank`` 恰好表示目标在选中块内的位置。

各实现也正确计算了顺序容器中间删除的真实成本：``erase``、``remove``、``splice``、``deleteat!``、
Go ``copy`` 和 R 负下标删除都可能移动或复制线性后缀，因此总时间为 ``O(n²)``。

前向风险
~~~~~~~~

单字符输出严格依赖 ``n <= 9``。当元素可能为 ``10`` 或更大时，直接执行 ``'0'+value`` 不再是一个
数字 token；即使改为十进制文本，字符串字典序也不一定等于数值序列字典序。

扩大 ``n`` 时还需要同时升级阶乘表、``rank``、``block`` 和下标计算，不能只把最终阶乘换成更宽类型。

提升规则
~~~~~~~~

* 组合秩选择证明一基到零基转换、块大小、商的下标上界和余数新秩；
* 阶乘与全部中间状态使用统一且足够宽的类型；
* 顺序容器中间删除按移动或复制成本计费；
* 单字符编码由元素值域证明，扩展多位 token 时重新定义输出字典序。

本批提升的统一规则
------------------

标准库与语言运行时
~~~~~~~~~~~~~~~~~~

* 原地排序与辅助空间是两个独立属性；
* 标准库隐藏的完整扫描、转换和缓冲仍计入复杂度；
* 范围对象的空区间和方向错误按目标语言验证。

前提、形状与状态压缩
~~~~~~~~~~~~~~~~~~~~

* 强输入前提降低复杂度时写出完整因果证明；
* 单维边界守卫若依赖方阵或同步收缩，需要登记形状不变量；
* 输出载荷、调用后输入状态和算法工作状态分别描述。

数值秩与序列容器
~~~~~~~~~~~~~~~~

* 一基排名先转零基秩；
* 阶乘块选择证明商和余数保持合法状态；
* 中间删除按后缀移动或复制成本计算；
* 单字符 token 编码由精确值域支撑。

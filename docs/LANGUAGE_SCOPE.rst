编程语言范围
============

本项目不再设置第二层和第三层语言。语言集合保持固定，保证读者能够长期连续学习，也避免后续助手随意扩大范围。

核心语言
--------

普通算法题默认提供以下 10 种语言的实现：

#. C
#. C++
#. Python
#. Java
#. Rust
#. Go
#. TypeScript
#. C#
#. Julia
#. R

每种语言承担不同的教学目标：

* C：数组、指针、结构体、手工内存和底层数据结构；
* C++：STL、引用、迭代器、泛型、值语义和资源管理；
* Python：动态类型、容器、迭代协议和简洁表达；
* Java：类、泛型、集合、装箱和引用语义；
* Rust：所有权、借用、模式匹配、``Option`` 和迭代器；
* Go：切片、map、结构体、零值和多返回值；
* TypeScript：JavaScript 运行时、静态类型、``Map``、数组和类型收窄；
* C#：泛型集合、值类型、引用类型、属性和 LINQ；
* Julia：多重派发、参数化类型、数组、数值计算和一基索引；
* R：向量、列表、矩阵、数据框、索引语义和函数式数据处理。

Julia 与 R 的处理原则
---------------------

Julia 和 R 是正式核心语言，不作为附录或偶尔补充。

算法题中的 Julia 和 R 代码应保持语言自身的写法：

* Julia 优先展示类型推断、参数化方法、多重派发和数组语义；
* R 优先展示向量、列表、环境、索引和数据结构表达；
* 不能把 Python 代码机械改写成 Julia 或 R；
* 当 LeetCode 风格接口不适合该语言时，可以提供等价的独立函数，并明确说明接口差异；
* 对链表、树、图等结构，必须先定义清楚节点表示和可变状态。

基础能力补充
------------

下面三项属于基础必学能力，但不需要在每道普通算法题中重复提供一份近似代码：

JavaScript
~~~~~~~~~~

TypeScript 建立在 JavaScript 运行时之上。项目保留 TypeScript 作为正式实现语言，同时在 TypeScript 章节中解释必要的 JavaScript 运行时知识，例如：

* ``number`` 的数值边界；
* ``Map`` 与普通对象的差异；
* 引用、数组和对象的可变性；
* 闭包、原型和事件循环在相关题目中的影响。

只有 JavaScript 与 TypeScript 的实现存在实质差异时，才额外提供独立 JavaScript 代码。

SQL
~~~

SQL 是基础必学语言，只用于数据库类题目。数据库题应根据题意提供合适的 SQL 方言，并解释连接、聚合、窗口函数、子查询和空值语义。

Shell
~~~~~

Bash 或 POSIX Shell 是 Linux 与工程实践中的基础能力，只用于 Shell 类题目或必要的命令行说明，不在普通算法题中强行加入。

不纳入当前范围
--------------

当前不加入 Kotlin、Swift、Ruby、PHP、Dart、Scala、Racket、Erlang、Elixir 等语言。除非用户以后明确调整范围，任何助手都不得自行扩充核心语言集合。

汇编语言用于理解机器执行、调用约定和性能边界，可以在相关讲解中阅读少量汇编，不要求为每道题编写汇编解法。

覆盖规则
--------

* 普通算法题默认覆盖 10 种核心语言；
* 数据库题增加 SQL，不强行提供不适用的普通语言版本；
* Shell 题增加 Bash 或 POSIX Shell；
* 某种核心语言暂时无法可靠完成时，必须登记原因，不能用未经检查的代码填充；
* 语言实现顺序保持稳定，方便读者对照阅读；
* 注释密度由 ``state/CONCEPT_LEDGER.toml`` 决定，不得每题重复解释基础语法。

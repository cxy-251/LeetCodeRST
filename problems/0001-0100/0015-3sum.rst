0015. 3Sum
==========

题目信息
--------

:题号: 0015
:难度: Medium
:主题: 数组、排序、双指针、去重
:原题: `LeetCode 0015 <https://leetcode.com/problems/3sum/>`_
:访问状态: Available
:教学重点: 固定锚点、单调双指针、结果去重、排序后的整批排除

题目重述
--------

给定一个整数数组 ``nums``，找出所有由三个不同下标组成、元素之和等于 ``0`` 的三元组。

返回结果按数值去重：同一组数值只能出现一次，原数组中相同数值来自哪些具体下标并不重要。
三元组内部和结果列表的顺序都不作为答案正确性的条件。

自建示例
--------

包含重复值
~~~~~~~~~~

.. code-block:: text

   输入：[-1, 0, 1, 2, -1, -4]
   排序：[-4, -1, -1, 0, 1, 2]
   输出：[[-1, -1, 2], [-1, 0, 1]]

大量零
~~~~~~

.. code-block:: text

   输入：[0, 0, 0, 0]
   输出：[[0, 0, 0]]
   说明：虽然有多种下标选择，数值三元组只能保留一次。

不存在答案
~~~~~~~~~~

.. code-block:: text

   输入：[2, 3, 5, 8]
   输出：[]

正负值不对称
~~~~~~~~~~~~

.. code-block:: text

   输入：[-5, -2, -1, 3, 4, 6]
   可行组合：-5 + -1 + 6 = 0，-2 + -1 + 3 = 0
   输出：[[-5, -1, 6], [-2, -1, 3]]

问题抽象
--------

暴力方法枚举三个下标，时间复杂度为 ``O(n^3)``。排序后可以固定第一个数 ``nums[i]``，
把剩余问题改写为在右侧有序区间中寻找：

.. math::

   nums[left] + nums[right] = -nums[i]

这就是一个有序两数和问题。对于固定锚点：

* 当前和小于 ``0`` 时，需要增大总和，只能向右移动 ``left``；
* 当前和大于 ``0`` 时，需要减小总和，只能向左移动 ``right``；
* 当前和等于 ``0`` 时记录答案，再跳过两侧重复值。

排序还让重复值相邻，因此可以在锚点层和双指针层分别去重。

解法选择
--------

.. list-table::
   :header-rows: 1

   * - 方法
     - 时间复杂度
     - 空间复杂度
     - 取舍
   * - 排序、固定锚点、双指针
     - ``O(n^2)``
     - 取决于排序实现
     - 主解法；移动依据和去重边界都清晰
   * - 枚举两数并用哈希集合找第三数
     - ``O(n^2)``

     - ``O(1)``

主解法：排序后固定锚点
--------------------

状态含义
~~~~~~~~

排序后，算法维护：

* ``i``：当前固定的第一个元素下标；
* ``left``：待搜索区间的左端；
* ``right``：待搜索区间的右端；
* ``result``：已经确认的唯一数值三元组。

每轮计算：

.. math::

   sum = nums[i] + nums[left] + nums[right]

只允许 ``left`` 增大或 ``right`` 减小，因此每个锚点下的扫描是线性的。

锚点去重
~~~~~~~~

若 ``nums[i] == nums[i - 1]``，当前锚点值已经在上一轮完整搜索过。再次以相同数值为锚点，
只会得到相同的数值三元组，因此直接跳过。

排序后若 ``nums[i] > 0``，右侧元素都不小于它，三个数之和必然大于 ``0``，可以结束整个外层
循环。

双指针为什么能排除一整批候选
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

固定 ``i`` 后：

* 若 ``sum < 0``，当前 ``right`` 已是可选范围中的最大值。对同一个 ``left``，
  换成任何更小的右端只会让总和更小，所以当前 ``left`` 不可能参与解，可以令
  ``left += 1``；
* 若 ``sum > 0``，当前 ``left`` 已是可选范围中的最小值。对同一个 ``right``，
  换成任何更大的左端只会让总和更大，所以当前 ``right`` 不可能参与解，可以令
  ``right -= 1``。

这两个排除都依赖排序后的单调性。

命中后的去重
~~~~~~~~~~~~

发现一个三元组后，同时移动两端，并跳过与刚才相同的数值：

.. code-block:: text

   left_value = nums[left]
   right_value = nums[right]
   while left < right and nums[left] == left_value:
       left += 1
   while left < right and nums[right] == right_value:
       right -= 1

这样每个锚点下，每一对数值只会记录一次。

核心不变量
~~~~~~~~~~

对固定锚点 ``i``，每轮循环开始时：

* ``left`` 与 ``right`` 之间是尚未排除的候选区间；
* 位于 ``left`` 左侧的候选已经因总和过小、已命中或重复而处理完；
* 位于 ``right`` 右侧的候选已经因总和过大、已命中或重复而处理完；
* ``result`` 中没有重复三元组；
* 尚未记录的合法答案若以 ``nums[i]`` 为首值，其另外两个值仍位于当前闭区间中。

正确性依据
~~~~~~~~~~

排序不改变元素数值和可选下标数量，只改变遍历顺序，因此不会创造或删除合法三元组。

固定一个未被跳过的锚点 ``nums[i]``。若当前总和小于 ``0``，由于 ``nums[right]`` 已是最大
右值，当前 ``left`` 与任何可选右值组合都不可能达到 ``0``，删除当前 ``left`` 不会漏解。
总和大于 ``0`` 时同理，当前 ``right`` 与任何可选左值组合都不可能达到 ``0``，删除当前
``right`` 不会漏解。总和等于 ``0`` 时，当前三元组合法；跳过相同左右值只删除数值完全相同
的重复表示。

双指针最终交叉时，固定锚点下所有数值对都已命中或被单调性证明不可能。外层又枚举了每个不同
锚点值，因此所有唯一合法三元组都会被记录一次，且不会重复。

复杂度
~~~~~~

设数组长度为 ``n``：

* 排序时间复杂度为 ``O(n log n)``；
* 外层最多执行 ``n`` 次，每个锚点的双指针总共移动 ``O(n)`` 次；
* 总时间复杂度为 ``O(n^2)``；
* 除返回结果外，额外空间取决于排序实现；原地排序时通常为 ``O(log n)`` 调用栈或
  ``O(1)`` 到 ``O(n)`` 的实现相关空间。

.. code-block:: c

   #include <stdlib.h>

   static int compare_ints(const void* left, const void* right) {
       int a = *(const int*)left;
       int b = *(const int*)right;
       return (a > b) - (a < b);
   }

   int** threeSum(
       int* nums,
       int numsSize,
       int* returnSize,
       int** returnColumnSizes
   ) {
       *returnSize = 0;
       *returnColumnSizes = NULL;

       if (numsSize < 3) {
           return NULL;
       }

       qsort(nums, numsSize, sizeof(int), compare_ints);

       int capacity = 16;
       int** result = malloc(capacity * sizeof(int*));
       int* columns = malloc(capacity * sizeof(int));

       for (int i = 0; i < numsSize - 2; ++i) {
           if (nums[i] > 0) {
               break;
           }
           if (i > 0 && nums[i] == nums[i - 1]) {
               continue;
           }

           int left = i + 1;
           int right = numsSize - 1;

           while (left < right) {
               long long sum =
                   (long long)nums[i] + nums[left] + nums[right];

               if (sum < 0) {
                   ++left;
               } else if (sum > 0) {
                   --right;
               } else {
                   if (*returnSize == capacity) {
                       capacity *= 2;
                       result = realloc(
                           result,
                           capacity * sizeof(int*)
                       );
                       columns = realloc(
                           columns,
                           capacity * sizeof(int)
                       );
                   }

                   int* row = malloc(3 * sizeof(int));
                   row[0] = nums[i];
                   row[1] = nums[left];
                   row[2] = nums[right];
                   result[*returnSize] = row;
                   columns[*returnSize] = 3;
                   ++(*returnSize);

                   int left_value = nums[left];
                   int right_value = nums[right];
                   while (left < right &&
                          nums[left] == left_value) {
                       ++left;
                   }
                   while (left < right &&
                          nums[right] == right_value) {
                       --right;
                   }
               }
           }
       }

       *returnColumnSizes = columns;
       return result;
   }

   threeSum <- function(nums) {
       nums <- sort(as.integer(nums))
       result <- list()
       n <- length(nums)

       if (n < 3) {
           return(result)
       }

       for (i in seq_len(n - 2)) {
           if (nums[i] > 0) {
               break
           }
           if (i > 1 && nums[i] == nums[i - 1]) {
               next
           }

           left <- i + 1
           right <- n

           while (left < right) {
               total <- nums[i] + nums[left] + nums[right]

               if (total < 0) {
                   left <- left + 1
               } else if (total > 0) {
                   right <- right - 1
               } else {
                   result[[length(result) + 1]] <- c(
                       nums[i], nums[left], nums[right]

                   }

                       right <- right - 1
                   }
               }
           }

关键边界与易错点
----------------

* 锚点、左端和右端都需要去重；只做其中一层会留下重复三元组；
* 命中后不能只移动一端，否则可能再次记录同一数值组合；
* ``nums[i] > 0`` 才能提前结束，``nums[i] == 0`` 仍可能与两个零组成答案；
* C、C++、Java、Rust 和 C# 中可先提升到更宽整数再求和，避免约束变化后窄类型溢出；
* 排序会修改输入数组；需要保留原顺序时应先复制；
* Julia 与 R 使用一基下标，循环和左右指针边界不能照抄零基实现。

新增与强化知识
--------------

新增
~~~~

* **排序后三数和**：固定一个锚点，把三数问题降为有序区间两数和；
* **双层去重**：锚点去重负责跨轮次唯一性，命中后的左右去重负责轮内唯一性；
* **单调整批排除**：一次指针移动证明一组候选全部不可能，而不是只跳过一个组合。

强化
~~~~

* 0011 已使用双指针收缩区间；本题的移动依据从“较短边上界”变为“有序和的单调性”；
* 0001 的两数和思想再次出现，但排序后的双指针同时解决了搜索和结果去重；
* 宽类型中间值继续用于防止多个整数相加时的潜在溢出。

最小自检
--------

#. 为什么 ``sum < 0`` 时可以直接排除当前 ``left``，而不是尝试更小的 ``right``？
#. 为什么锚点重复时可以跳过整个双指针搜索？
#. 命中一个答案后，为什么必须跳过两侧所有相同值？
#. ``nums[i] > 0`` 的提前结束依据是什么？
#. 排序带来的主要收益有哪些？

答案要点
~~~~~~~~

#. 当前 ``right`` 已是最大可选值；连它都使总和小于零，更小右值只会更小；
#. 相同锚点值的所有右侧数值对已经在上一轮完整枚举，重做只产生重复三元组；
#. 相同左右值与同一锚点形成的数值三元组完全相同；
#. 右侧元素都不小于正锚点，三数之和不可能回到零；
#. 排序提供和的单调性、让重复值相邻，并允许提前结束。
